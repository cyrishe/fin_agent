2026-10-02。本轮按用户授权，在 MySQL `kingdomai` 新建四张独立的 `notice_*` 表，并写入真实公告的抽取样本。批次为 `notice_pilot_20261002_v1`。

这是**本会话逐篇研读、选择核心信息并录入的试验**，不是已完成的自动抽取程序，也不是经过独立金融业务人员确认的金标。临时工具只负责获取原文、组装已阅读结果、导入和回读核对。本轮没有修改聊天、MCP 或部署配置。

## 2. 实际表结构

可执行建表定义见 [pilot_schema.sql](pilot_schema.sql)，与早先逻辑方案的 `announcement_*` 名称对应，本轮按用户用语统一命名为 `notice_*`。

| 表 | 粒度 | 本批行数 | 主要用途 |
| --- | --- | ---: | --- |
| `notice_documents` | 一份文档的一次内容/抽取版本 | 65 | 来源、原类型、公司原称、日期、正文快照、摘要、哈希、处理说明 |
| `notice_events` | 文档中的具体事项 | 83 | 本次发生什么、条件和进展、命名日期、前次公告引用 |
| `notice_metric_facts` | 带主体、单位和期间的数值事实 | 231 | 检索数值及区间，区分实际、预测、方案和余额口径 |
| `notice_participants` | 某事项中的某个参与方角色 | 111 | 区分买卖方、借贷方、保证人、标的、诉讼当事人等 |

原文、数值事实、角色和关键日期均可回到本次证据正文。证据保存正文哈希及 Unicode 字符半开区间；只有本轮实际下载并建立页映射的 PDF 才填写物理页号。其余正文不伪造 PDF 页码。

`metric_code`、规范证券代码和参与方标准名称暂未强行映射。原始证券代码、公司/主体原称、指标原名可以查询。`unit_code` 当前沿用明示单位字符串，尚未接入统一单位字典；这不代表跨公司指标已经全部可直接聚合。

版本标识绑定来源 URL、源元信息、证据正文、抽取结果与抽取版本。重读相同样本可以核对同一版本，但本轮尚未实现自动选择“当前有效事实”的视图。

## 4. 样本已经体现的价值

以下结论是基于本批源公告的结构化表达和查询结果，不是对公司经营事实额外进行独立调查后的判断。

| 实际问题 | 样本能提供什么 | 必须保留的区别 |
| --- | --- | --- |
| 比亚迪 8 月卖了多少，出口多少？ | 销量 440,293 辆、出口 189,466 辆；另有累计和车型分项 | 月度与累计、总量与分项分开；出口不改名为海外零售 |
| 中芯的晶圆量价如何？ | 上半年销量 5,379 千片、ASP 966 美元/片 | 折合 8 吋标准逻辑口径；未将总收入直接除以销量推造 ASP |
| 振华重工 A/B 股何时分红？ | A 股登记 10/13、派发 10/14；B 股登记 10/16、派发 10/23；均 10/14 除息 | 多股份类别、多币种、多日期必须带适用范围 |
| 凯盛新能实际担保有多少？ | 实际余额 85,310 万元；含未用额度总额 183,000 万元 | 合同金额、实际余额、批准额度不能混成一笔 |
| 天顺上半年扣非利润是否为正？ | 更正前 107,715,751.04 元，更正后 -28,654,605.38 元 | 同期版本变化不能求和；需要更正关系和有效值选取 |
| 奥尼 GPU 大单是否是新增收入？ | 交易方向为子公司采购，供货方为未具名的 C 公司 | 采购合同金额不是销售收入，也不是已经支付现金 |
| 收到补助能增厚多少利润？ | 百大收到 211 万元，预计增加归母净利润 158.25 万元 | 到账、税前收益、税后归母影响不是同一口径 |
| 曲江文旅诉讼进展怎么样？ | 同文拆出 8 个案件，分别保留角色、诉请/判付/执行和进展 | 原告请求、被告责任、实际执行不能合并成“损失总额” |
| 交流材料能补经营指标吗？ | 高能环境答复江西鑫科 2026 年预计利用率约 60%–70% | 区间、预测、公司陈述均保留，不取中点当实际 |

业绩说明会还能纠正提问中的前提。例如华达投资者问第二季度亏损，公司答复给出的是**半年度**扣非利润；宁波精达明确目前不生产液冷板；中国船舶解释收入确认同时存在满足时段条件与时点条件的情形。只提取问句或用标题分类会丢掉这些价值。

## 5. 验证结果及其边界

- 四张表所有已写字段逐项回读，与准备入库的结果比较一致。
- 425 条事项/指标/参与方的原文引用，均可从数据库正文及定位重建；另在入库前核对 25 个命名日期引用，共 450 个证据项。
- 原文缺失、数值缺失与真实 0 分开。7 份有价值公告没有单独数值事实，仍正常保存事项。
- 新表的可选字段为空、指标不绑定事项等兼容输入可用；跨公告错误绑定、孤立事项、重复文档版本均被数据库约束拒绝。临时测试行全部回滚，正式行数不变。
- [pilot_queries.sql](pilot_queries.sql) 的 10 条只读 SQL 均实际执行，包括分类计数及上表 9 类业务问题。其中按源 ID 定位是为了确定性检查样本，不是未来在线检索规则。

这些检查验证的是**保存、关联、数值保真、证据定位和基本查询可用性**。未验证全量自动抽取效果、并发和性能，也未验证聊天或 MCP 能力；本轮未把新表接入这些入口。语义抽取还需要使用者复核，不能把“数据库校验通过”称为“金融结论全部正确”。

## 6. 对设计的判断和下一轮重点

**四张共用表可以保留，暂不需要按业务类别增加专表。**多案件、多担保、A/B 股日期及子公司经营指标都已能表达。下一轮优先复核以下真实出现的问题：

1. **指标定义和可比口径。**先确认常用指标与既有 `metric_def` 的准确对应关系，包括归母/非归母、单季/累计、集团/子公司、单位量级。没有确定映射就保留原称。不要为了查询方便把“收益”统一成“归母净利润”。
2. **更正与重复披露。**天顺更正公告与更正后摘要披露同一个新值。保留各自证据，同时在查询层确定最新适用值和来源关系；不覆盖旧值、不将多份公告视为多笔业务。先对这些真实样本明确规则，再决定是否需要极少量的标准关系字段。
3. **数值含义与口径说明。**已签合同金额可以是已披露事实，但不是已发生现金或收入。`actual/forecast` 不能独自决定可加总性，消费端必须一起读取指标名、范围和 basis。先看用户是否能准确理解现有结果，不立刻增加大批状态码。
4. **抽取完整度。**首批长财报聚焦主要财务指标，尚未覆盖全部附注；同一投关活动也只选取核心经营信息。后续针对实际问答需求确定必取内容和可留在摘要中的内容，不追求将全文拆成字段。
5. **原件与表格证据。**空正文和错列表格都值得触发补解析。保留 PDF、表头、页映射和版本；扫描件、下载失败与跨页复杂表尚需另加样本验证。
6. **ignore 边界。**本批按用户要求只选择有价值公告，65 份均保留，不能声称已验证忽略规则。召开通知等纯程序材料可以进入低价值候选，但实际问答记录、重大议案内容、风险事项和更正不能仅凭类型忽略。下一轮需补少量低价值及容易误判的对照样本。

本批覆盖的是上述 13 个大类，不代表补助/税务/准则、融资/债务/担保等每一个子型都已覆盖。例如本批会计类别没有专门的税收优惠样本，分红类别未覆盖转增；OCR、英文原文和所有证券市场也未验证。是否扩大覆盖，应由用户审阅后的重点问题决定。
