# 公告原生流程：设计复核与实测

2026-10-02。基于工作区 ref `d4b354bbe8f7f623f4c67e086f64b18cb04554a1`，本轮代码是尚未提交的新增脚本，不是该 commit 已包含的能力。使用现有环境的 `BL/deepseek-v4.1-flash`。PG 只读，MySQL 仅追加授权的 notice 测试数据；未部署或改生产聊天。

## 判断

四张表适合作为当前公告的共同基础，暂不拆 13 套专表，也不向研报表建立业务依赖。结构相似部分来自共同的数据溯源需要，公告核心是**事项及其本次变化**，不是研究观点、估值、评级或预测模型。

设计有用的证据是：同一模型/提示词能处理月度经营、更正、多币种分红、多主体担保、采购合同、多案件诉讼和不含数字的人事事项；无需按公司或案例分支。日期、范围、参与方角色需要结构化，生效条件和过程说明保留自然语言。没有因为这轮测试增加业务状态枚举、类别专属 validator 或额外业务表。

但“能统一保存”不等于“所有数字可以统一运算”：指标原称、单位、区间边界、更正版本与子公司归属仍须一起解释。跨公告自动归并、最新有效事实选取及金融聊天检索入口，本轮没有实现。四表也不是全量自动入库的无条件质量保证。

## 多轮验证做了什么

| 轮次 | 范围 | 结果与真实发现 |
| --- | --- | --- |
| 初始小样本 | 5 份 | 均可解析；发现公司答复与投资者提问数值混淆、主体字段混入口径。数值匹配通过不能证明业务正确 |
| 网关诊断 | 首批长文 | 旧 thinking 参数未生效，消耗预算后截断；中止该轮，不计为成功样本。实际接口验证后改用 enable_thinking=false |
| 全量基线 r3 | 65 份、13 类 | 65 成功；严格同单位数值匹配 206/231。发现约数优先、更正前值遗漏及 PDF 合并单元格丢失 |
| r4 | 同 65 份 | 65 成功；调整核心抽取口径并加入 PDF 单元格几何解析；分红共用日期得到恢复 |
| 最终主样本 | 同 65 份 | 65 成功，66 次模型调用，421,851 tokens；151 事项、1,049 数值、301 参与方关系 |
| 扩展样本 | 另外 13 份 | 13 成功；包含子公司审计、经营快报、担保、控制权风险、会议资料等；不称为独立专家盲测 |
| 易误忽略材料 | 另外 3 份法律意见书 | 均保留其中的实质议案/任免结果，证明不能按文档标题忽略；数值提取偏多仍需观察 |

| PDF/图像补充 | 扩展样本中 1 份 57 页审计报告 | 自动转录 17 个图像页，恢复原先缺失的主财务表；共 18 次模型调用、69,610 tokens。没有换用其他模型 |

共涉及 **81 份不同的真实公告**；重复抽取轮次不计作新样本。65 份主样本仍为之前有意挑选的 13 个大类、每类 5 份，不代表所有子类型、市场、语言及 PDF 形态均已覆盖。

最终提示词正文和字段说明合计 1,575 字符；一个通用抽取提示，没有为各公司、各类别复制长提示。图像转录另用一句短指令，职责仅是保留原页文字与表格。Python 负责身份、证据定位、类型/精度、事务和幂等；LLM 负责业务信息选择与表达。

## 核心信息是否接近前次研读结果

231 条前次研读数值中，216 条严格匹配相同单位和 scalar/lower/upper 组合，**93.5% 只是诊断覆盖率，绝非准确率**。15 条未匹配项逐项复核，主要包括：

- 原单位与换算单位、单位分母表达不同，如 ASP 的美元与美元/片。
- 最低承诺/减持上限保存为带“最低/不超过”说明的 scalar，而参考记录使用上下界。
- 44 名解锁对象、51% 收购比例、3 年服务期、30 日整改要求等保留在摘要/事项，未全部进入 metric 行。
- 同时填 value 和 lower 的等价表达造成严格匹配失败。

因此当前适合“检索结构化证据后由模型解释”的问答，不能把 metric 表当成已经完成全部单位归一和边界归一的计算宽表。原生抽取产生的指标比人工筛选多，不能把行数更多当作效果更好；尤其法律意见书的表决票数仍偏多。

## 原件处理的实际边界

振华分红表的 B 股除息日期是合并单元格，不是缺值。此次按 PDF 边框恢复单元格覆盖行列，交给模型理解，未写“B 股沿用 A 股日期”之类业务补丁。

新疆天业集团矿业审计报告的 source content 有正文，但主表是图像。强制 PDF 补解析后，由同一模型转录文字极少的图像页，再统一抽取。解析表示保留原件、页号和转录标记。第 9、10 页旋转表仍出现日期/局部数字识别疑点，抽取结果保留了说明；**不能声称 OCR 全文无误**。已有正文局部缺失不会只因 content 非空而自动触发 PDF，遇到疑点需 `--pdf` 复核。

另一次曲江文旅 PDF 重抽试验中，模型在摘要自行给出未经原文直接披露的合计金额；该试验版本没有入库，保留为失败证据。最终主样本版本没有这一合计。这个现象说明证据地址正确仍不能消除模型语义/汇总错误，批量发布前必须抽检，不应用一组成功问题外推全部输出可靠。

## 数据库与协议检查

主批次 `notice_native_20261002_final`：65 documents、151 events、1,049 metric_facts、301 participants；另一个 OCR 试验批次 `notice_native_20261002_ocr` 只追加上述 1 份审计报告，便于单独查看。

- 主批次四表每个已写字段逐项回读一致。
- 1,725 个原文证据项（含命名日期）都能按 hash 和 Unicode 区间重建。
- 再次执行同一主批次：65 份复用缓存，新增 0 条。
- 65 份 PG source content 哈希均保持不变，原来 4 个 NULL 仍为 NULL。
- 先前人工批次保持 65/83/231/111 行；未覆盖或修改研究报告相关表。
- 17 个针对性测试通过：正常、兼容可选输入、真实错误拒绝、证据定位、数字精度、原子事务、幂等、有限修复、合并单元格、扫描页、模型请求开关和 Python 3.9 语法。
- 复制脚本和提示词后，在仓库外的 `/tmp` 工作目录实际跑通 1 个真实样本，没有导入应用代码。

不声称仓库全量回归、长稳/压测、生产发布或聊天/MCP 接入通过；这些维度本轮没有运行证据。
