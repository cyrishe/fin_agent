## 1. 执行需要的是方法契约，而不是一次必填参数

`subject → dataview → 方法执行包 → finance_query`

浏览可以逐层进行，也可直接读取明确的 subject/dataview/operation。省略 operation 时，返回该 dataview 的完整方法包，包内各方法可以执行；只读某个 OP 时，只取得该 OP 的执行契约。概览中的其他方法名称仅用于导航。

DSH 使用现有 Harness 工具限制与 guard，不新增业务审查层：

- 在本次模型生成前，从真实工具历史提取版本匹配的执行包；不用用户文本或进程全局“曾经读过”的标记授权。
- 对一个 flow 的所有调用目标检查契约。临时增加一个方法，也需要先读取它的执行包。
- 同一轮模型并行生成的“读包”和“执行”不能互相授权：模型生成执行请求时尚未看到那个包。
- 缺包时在进入 Python 查询与数据源之前返回所缺方法，引导补读；不消耗数据查询修复次数。
- 字段、参数、filter 和计算表达式仍交给原有 Python 解析与静态检查；不检查用户语义是否正确，不增加业务 OP 支持矩阵。
- 保留已定义的两段式明细查询兼容输入。历史包被压缩掉或目录版本变化后，需要重新加载。

实现：[dsh_loop_policy.mjs](../../src/scenarios/financial_qa/dsh_loop_policy.mjs)。此硬顺序约束属于 DSH 主线；CC 共用工具与契约，但不宣称 CC 具有相同的 Harness 生命周期约束。封存 CC 基准未修改。

## 2. Skill 前置，但充分性由 Agent 判断

`选择／读取适用 Skill → 按方法判断现有证据 → 按需取数、组合分析 → 交付`

`read_finance_skill` 新增可选的批量 `skill_ids`，保留旧 `skill_id`。空列表表示本题采用通用方法，不创建虚构 Skill，也不强迫命中。批量选择先完成全部授权检查，再记录加载，避免一半成功一半失败。

系统只保证“方法选择先完成，再调用数据工具”。是否覆盖充分、还缺哪些证据，由 Agent 结合方法正文和当前问题判断，不要求输出覆盖率、业务状态枚举或额外规划 JSON。已经有足够证据时，可以直接按方法回答；没有足够证据时，在同一上下文中读取数据执行包、取数并补充分析。用户显式选择且正文已加载的 Skill 直接复用。

这里没有另建一个 `execute_skill` 黑盒或嵌套 Agent。业务 Skill 是指导同一个 Agent 工作的方法；执行其中的取数步骤，仍使用上述统一数据协议。原有数据查询、修复及总轮数预算继续生效。

**候选范围需要与顺序分开看。** 仓库历史内置目录有 12 项，不只是个股分析和研报分析。上一轮四题使用了这个目录，因此不能当作“仅两项候选”的效果评测。本次补测通过既有应用 Skill 授权列表仅开放 `stock-research`、`equity-report-analysis`；不修改生产注册目录，不删除历史文件，也不破坏个人／公开 Skill 的动态发现。其他任务正在修改的业务 Skill 正文未混入本次隔离运行。

实现：[tools.py](../../src/scenarios/financial_qa/tools.py)、[dsh_system.md](../../src/scenarios/financial_qa/dsh_system.md)。测试脚本增加 `--allowed-skills`，在 manifest 中记录候选范围与 Skill 版本。

## 3. 字段到底有没有给模型

`stock.basic_info.query` 的实际执行包包含：

```text
fields: code, name, industry, listed_date（上市日期）
args: filter, order, limit, realtime
output_rule: 输出当前方法定义的字段。
filter_syntax: 比较、and/or、括号、contains、in/not in、is None/is not None。
```

公共协议字段是 `listed_date`，底层数据库列是 `b.list_date`，映射由 Provider 完成。模型不需要知道数据库列名。[目录定义](../../src/tools/finance_data/catalog/api_view_catalog.json)、[Provider 映射](../../src/experiments/staged_data_protocol/phase2/base_info_provider.py)。

之前阳光电源的现场：先读取 financial_3_table 与 business_segment，没有读取 basic_info，随后输出 basic_info 的 `list_date`。因此这一例属于**缺执行包后猜字段**，执行前契约约束能处理它。[原始过程结论](server_query_v5_regression_20260908.md)

但另一类错误仍然存在：本次较早四题中的科大讯飞已读取财务字段，仍写出 `rnd_expense`，正确字段是 `rd_expense`；原有静态检查指出后修复。这是**已读包仍写错**，不应通过自动别名或单题提示掩盖。

字段定义集中在 dataview；OP 给出调用参数、输出规则，以及相应的聚合字段／窗口指标等元数据。明细输出字段与聚合后结果列不能混为一谈。本次覆盖全部 31 个 dataview、47 个方法包，核对选择 OP 后仍保留字段与 filter 语法。没有复制一套字段名单到常驻提示词。

## 4. 名称／代码工具的边界

```json
{"identifiers": ["阳光电源", "300274"]}
```

- 当前实现针对股票身份，读取新 kingdomai 库的 `kcrp_stock_baseinfo`。不声称覆盖所有市场或基金、债券、板块身份。
- 先按名称／代码精确匹配；名称没有精确结果时，再做包含匹配。批量最多 20 项，逐项最多返回 20 个候选并注明是否截断。
- 同名、多候选交给 Agent 结合问题确认；零候选只说明身份表没有匹配，不推断其他数据源也没有这个公司。
- SQL 结构固定、值参数化，模糊匹配转义通配符；不经过 LLM 编写 filter，不附带行业 JOIN 或上市日期。
- 已有代码，或数据接口能够直接按名称查询时，可以直接取数，不强制增加身份步骤。
- detail 保留身份工具输入、耗时，以及 Skill 选择信息；连接错误不暴露凭据。

实现：[security_identity_service.py](../../src/services/security_identity_service.py)。服务器真实只读探测：阳光电源、短代码、完整代码均得到 `300274.SZ`；“银行”返回多候选；表中没有的港股标识返回空。五个输入合计约 39 毫秒，仅是单次观察。

## 验证与尚未解决项

- 本地扩大范围：**593 passed、2 skipped**（跳过项为本地缺凭据的外部测试），不是全仓库回归。
- DSH 生命周期：**48 passed**，包括每个方法的契约、空包、同批并行、版本与上下文、Skill 优先、无匹配、证据已足够、身份工具、修复预算和结束边界。
- 共享适配器验证包括 CC 与 DSH；数据 Provider 的离线测试使用替身，不将它们当作模型效果分数。

两项候选补测（同一基线 Skill 正文、真实 MCP、原题不变）：

| 原题 | 实际 Skill | 轮数 | 服务耗时 | Token | 数据行数 | 查询判断 |
|---|---|---:|---:|---:|---:|---|
| 科大讯飞：AI 大模型对业务增长的催化 | 个股分析＋研报分析 | 9 | 56.91 秒 | 139,134 | 87 | 四个取数子步骤均首次静态通过；追加财务与机构预测、结果翻页扩大了工作量。 |
| 阳光电源：光伏行业竞争地位 | 个股分析 | 5 | 24.35 秒 | 43,553 | 28 | 业务分部＋研报观点两个查询均首次通过；新增研报方法先读包，再执行。 |

两题均 HTTP 200，数据、summary、detail 完整；原生请求头确认第一步只开放两个 Skill 读取工具，既有应用授权列表在模型可见目录与读取权限两处均生效。它们仍不能当作业务回答完全正确：

- **科大讯飞的实际步骤**：①读取两项 Skill；②身份转换＋研报／分部执行包；③查询两类数据；④输出一段分析；⑤读取财务／研报指标包；⑥查询财务与预测；⑦尝试读 60 行，超过已声明的单次 50 行上限；⑧改为 50 行，另一个翻页调用触及原有读取次数预算；⑨输出最终摘要。模型响应累计 52.82 秒，数据 Provider 累计 3.73 秒。没有重现缺包、`list_date` 或 `rnd_expense`，但有结果读取参数错误及预算拒绝，不称为全程无协议错误。
- **阳光电源的实际步骤**：①读取个股分析；②身份转换＋分部包；③查分部，同时读取研报包；④查研报；⑤摘要。并行的是已加载方法的执行与新方法的读包，新方法直到下一步才执行，符合契约约束。模型响应累计 23.01 秒，Provider 累计 1.11 秒。
- **摘要仍有独立质量问题**：阳光电源将储能收入写成 51.6 亿元，而本次返回的该期对应数据约为 154.56 亿元；科大讯飞把收入、利润变化直接作为大模型贡献的验证，因果表述偏强。这些不是取数入口或字段协议失败，不通过增加字段别名、业务硬校验或单题提示来修补。

结论：四项主框架机制已经落地并验证；只保留两项候选能排除历史方法竞争，但不能保证取证范围、读取参数、摘要准确性和时延自动变好。后续效果工作应针对方法的任务收敛、充分性判断和证据到结论的表达，不能把“接口返回成功”当作整体效果通过。这里记录问题，不因此撤回或搁置本轮其他已完成改动。

耗时采用服务端 execution duration；Token 为输入（含缓存读取）加输出。模型响应时间包含请求准备、推理及生成，不是单独思考时间；Provider 累计不是纯 SQL 时间，与并行耗时不能直接相加。行数包含不同数据集，不等于研报篇数。
