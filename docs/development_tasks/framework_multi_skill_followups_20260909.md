# 主框架：多方法选择、预算感知与回答后续交互

日期：2026-09-09。开发起点 `a42ab5f`；期间另一个任务提交了仅含说明文档的 `5f75bc2`，业务代码基线相同。本轮改动尚未提交、推送或部署。

## 实现范围与职责

本轮由用户授权优化四项主框架能力：多 Skill 与基础数据协作、预算感知收尾、折叠参考数据、LLM 推荐后续问题。涉及 SOFT 编排/表达与少量 HARD 身份传递；没有新增业务状态、金融 validator 或独立的多 Agent 调度器，没有修改具体业务 Skill。

### 多 Skill

运行时原本支持 `read_finance_skill.skill_ids`、`explicit_skill_ids` 和共享数据工具；缺口在 Composer 单选和 Web 只传一个显式方法。

- 输入框可连续使用 `$` 选择多个**金融方法型 Skill**，显示顺序，可单独移除，重复选择去重。
- 同步和 SSE 增加可选 `selected_assets` 数组；旧 `selected_asset`、单元素列表和旧文字调用继续使用原路径。非空列表优先于旧单选字段。
- 逐个复用现有资产解析、归属与可用性检查，所有方法有效后才进入金融 Agent。系统保持用户选择顺序，完整方法正文按序注入。
- Skill 是同一 Agent 内的方法资产，按用户顺序分析，后续方法复用证据、按需补充基础数据，综合成一个答案。顺序属于 SOFT 工作方法，不新增每 Skill 独立任务和状态机；独立数据目录仍可并行加载。
- 普通可执行工具和旧 SkillRunner 资产保留单独调用。此次没有实现“任意工具/异步 Skill 混选”的任务队列。金融方法 + 基础数据不需要额外选择数据工具。

主要入口：`frontend/src/components/Composer.tsx`、`composerSuggestions.ts`、`App.tsx`、`api.ts`，以及 `AssetInvocationService.plan` 和 Flask 同步/SSE 入口。能力标识沿用目录现有 `skill_type`。

### 预算与收尾

此前提高的是目录/查询/结果读取**工具调用额度**，不是固定 LLM 轮数，也不是必须完成的次数。标准普通路径为 6/3/2，实际加载方法后为 16/12/8；一次查询可含多个执行步骤。

- 利用现有 DSH `agent/pre-step`/提示接口，将当前有效额度的“剩余/上限”提供给模型；调用计数变化后刷新，即使业务阶段未变。
- 明确证据足够即可作答，按剩余额度安排必要取证、修复和证据复用；查询只余一次时提前引导聚焦，额度耗尽后给出有边界的结论。
- fast 沿用一次目录定位阶段、一次查询阶段的合同，同阶段独立调用可并行；不会把“阶段一次”误写成“工具只能调用一次”。data-only 保留原始数据交付协议。
- `reasoningEffort`、输出 token 仍由现有阶段/Skill 配置决定；本轮没有增加让模型修改运行时参数的工具，也没有增加总 LLM turn 上限。
- 正常完成不因余量更大被强制续跑；失败/明确未完成执行仍沿用最多一次结束补充引导。网络错误、取消、硬超时及输出截断不因预算提示而获得绝对保障。

真实双方法测试曾出现模型用空查询声明完成，随后补充引导让最后回复变成协议记录说明。此次精简修正共享查询字段说明（普通问答证据足够直接回答），并将结束补充指引明确为面向原问题的完整业务答案，过程细节留在独立通道。没有放宽空执行流校验，也没有新增特殊错误分支。

### 参考数据

已有参考区原本只折叠表格；现在在存在分析正文时，将金融证据块（包括图表、指标等）放到文末“参考数据”，默认收起。展开单项后才挂载具体 Renderer，原分页与数据读取入口继续使用。正文内用于分析的小表格保留；纯数据交付没有分析正文时仍直接显示。历史与流式使用同一分组规则。

### 后续问题

金融聊天成功返回正文后，使用当前用户问题与最终回答调用基础轻量模型，生成 2—3 个后续问题。独立金融领域提示文件为 `src/scenarios/financial_qa/follow_up_questions.md`；它只指导后续研究、对比、风险与待核验证据，不改变主答案。

- 单次请求，512 输出 token，8 秒超时，不重试；解析/网络失败返回空推荐，保留已完成的答案。
- 结果使用可选展示字段 `follow_up_questions`，加入历史展示白名单。点击后填入输入框，由用户编辑并发送，不自动发起后续查询。
- 推荐调用用量保存在 `follow_up_usage`，合并到整轮 `llm_usage` 一次；DSH 的核心逐步计数保持原口径。
- 仅聊天展示层生成；data-only、失败回答和独立 MCP/数据 API 不增加推荐调用。

表中次数/耗时仅为 DSH 核心；推荐问题另一次 LLM，约 2—3 秒。单次样本不能证明整体性能或准确率。
