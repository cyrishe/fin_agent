## 优先优化方向与边界

1. **复用结果资产完成列表展示，避免模型逐行搬运。** 当前已经有 result_ref、Surface Block、DataTable 和分页接口。让 SOFT 环节选择需要展示的结果及必要说明，HARD 绑定权威结果与列，Renderer 展示完整列表。优先复用现有协议，不新增 CPO 专用路径、关键词规则或一套交付状态。纯文本出口如需全量文字列表，可从同一结果确定性格式化；需要语义分析时仍提供必要明细。这样同时避免反复读取、推理下一页和长文本抄表。43 秒是本例后半程的观测值，不是承诺可全部节省。

2. **目录调用契约减少歧义。** 第一步错误目录读取与第二步未读契约即查询是实际空转。重点检查通用 subject/dataview/operation 的描述、Schema 与目录返回的一致性，使模型按已有层级发现方法；不要为 CPO/hot_event 写参数猜测或自动替换。契约守卫本次阻止了无依据查询，不能直接取消。修复回合的 2.753+1.769 秒不能全部视为净可节省，因为正确路径仍需要加载契约。

3. **推理预算应由当前工作需要决定。** skillGuidedAnswer 当前仅依据 skillCatalogAvailable 且非 data-only；即使没有加载 Skill，普通列表读取在 requiredAction 解除后也从 off 升为 low。本例第六步为读下一页消耗了 1,757 reasoning token。不能用“查成分股”等关键词直接关闭推理；先减少机械搬运，再评估是否可沿用已有 SOFT 决策表达是否需要综合分析。直接全局禁用推理属于尚未验证的效果变化，本轮不建议做。

4. **分页预算与结果交付解耦。** 当前普通请求最多两次 load、每次最多50行，本例已用完额度。这与任意大小全量列表交付不兼容。优先让 Renderer 从资产分页，避免盲目加大模型读数预算；确实要分析全部行的任务需另行验证取证策略。完整性错误记录为效果问题，不通过截断结果换效率。

5. **统一终点用量汇总。** 流式与非流式路径在同一个权威完成入口按组成部分各加一次，保留 DSH 缓存口径，覆盖外层路由及追问用量。协议回归须验证负向路由仍计费、缓存不漏算、嵌套规划不重复、既有入口兼容。这是本例新确认的计量缺口。
