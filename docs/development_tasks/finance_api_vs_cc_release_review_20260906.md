# 金融数据 API 与 CC：版本对比结论

2026-09-06。只评估取得所需数据的能力，不要求生成分析答案，不把正常空数据判错，也不要求 API 名称完全相同。

## 结论

DSH 主框架没有表现出整体落后于 CC，已有同题实验的入口覆盖和耗时反而更好，可以保留当前技术路线。但当前公网 API 尚有三项相对历史 CC 的具体差距：名称包含条件的失败恢复、分钟数据口径、指数区间数据覆盖。建议把这三项作为本版本的定向收口，而不是继续追求所有题目全对或重做框架。

可以作为内部试用版本；暂不宣布“全场景数据能力已经与 CC 持平”。普通明细、合理聚合替代、正常空结果和减少辅助查询，不应阻塞定版。

## 1. 真正的 CC / DSH 同题实验

9月2日，同一批20道题、同一 deepseek-v4-flash、相同并发和超时。以下使用双方首跑，不把 DSH 的重测成功覆盖首跑失败。

| 指标 | CC | DSH Opt 首跑 |
|---|---:|---:|
| 请求完成 | 20/20 | 19/20 |
| 首入口符合当时评测标注 | 14/20 | 19/20 |
| 最终涉及可接受入口 | 18/20 | 19/20 |
| 覆盖全部要求的数据入口 | 17/20 | 18/20 |
| 平均完整对话耗时 | 50.06秒 | 40.80秒 |

DSH 首跑平均耗时低18.5%，入口覆盖没有下降，但多一次请求失败。后续整组验证为20/20完成、平均38.73秒；它是独立重测，不代表首跑也是100%。这些是历史对话实验，不是今天公网 API 的全量验收，入口指标也不等于答案正确率。

## 2. 当前 API 与历史 CC 的逐题核对

本次已有21道题，其中6道使用上一轮修复后的复跑记录，其余15道保留原始记录。这是“最新证据盘点”，不是同一版本一次跑完的成功率，也没有在本轮新增模型调用。

以原通用228题 CC 记录和9月1日研报 CC 记录为基线；BUS006 原记录没有取数，补查8月4日 CC 记录。BUS119 没有可比较的成功 CC 取数记录，单列，不将它算作当前新增退步。

20道可比较题首次数据目录均一致。进一步检查查询条件、字段、窗口及执行结果：17道未发现相对 CC 的实质取数退步，3道仍有差距。**17/20 是此次人工相对复核结果，不是全量准确率或稳定成功率。**

| 范围 / 题号 | 与 CC 对比判断 |
|---|---|
| BUS001–004、BUS006 | 基础资料入口与主要条件一致。BUS003/004 多了一次纠错，但最终恢复，不按效果退步处理。 |
| BUS007–009、BUS192 | 行情入口与取数目标基本一致；部分历史 CC 还需多次补查。未对不同日期的数据值做绝对正确性认证。 |
| BUS010：宁德时代近10日行情 | 复跑与 CC 一样返回10日日线明细。首跑错误保留，单次恢复不能证明稳定率。 |
| BUS011：20日振幅排名 | CC 用固定均值方法，当前用 dynamic_cal 表达相同日振幅均值和排名，均取得20行。不因方法名不同判错。 |
| BUS028、BUS151、BUS176 | 三张表、板块成分、基金近20日入口一致；基金日历错误已修复。数据不足与模型入口能力分开看。 |
| BUS214：机器人热点 | state 已提供用户所需字段，少查辅助信息不是退步。 |
| RTE007、RTE016 | 预测指标和研报理由的入口一致；指定机构预测正常返回0行不判错，也不强制去掉机构条件找数据。 |
| BUS005：名称包含新能源 | **差距。** CC 生成 like 并成功取数；当前生成 contains，静态失败后重复原串，没有恢复。问题是协议生成/失败反馈的有效利用，不是数据缺失。 |
| BUS012：当前分钟成交量前20 | **差距。** 旧 CC 的 mode=2 在当时 Provider 中返回最新分钟增量；当前同样的 mode=2 已返回1d快照累计量。API 串相似不代表数据口径等价；不能算两边共有的问题，也不能仅归因于 Harness。 |
| BUS085：指数近20日跌幅前10 | **差距。** CC 用窗口方法取10名；当前9轮、64秒，期初/期末各仅取默认100条，无法覆盖全指数排名，并调用了不存在的 compute。问题不是用了明细，而是必需数据不完整。 |
| BUS119：行业平均涨跌幅和上涨家数 | 历史首次跑进入 free_chat、没有实际取数；8月4日 CC 完整记录也失败。当前仍失败，但没有证据将它认定为本次相对 CC 的新增退步。 |

## 3. 发布优先级

1. 保留 DSH 和已验证的数据库/SQL修复，不回退整体路线。
2. 优先收口以上三个真实差距，针对失败恢复、现行行情口径、窗口查询的数据完整性还原主线。先确认根因，不加公司/关键词补丁，不强制明细改聚合。
3. 定向修复后，用同题重复验证，加少量邻近真实题检查稳定性；通过后冻结本版。历史共有缺陷和非实质调用差异进入后续清单，不作为追求100%的理由。

不将旧完整对话耗时与当前纯数据 API 耗时直接相除，宣称 Harness 加速倍数：两者输出范围、数据库和部署环境不同。分钟题当前7.2秒返回了不同口径的数据，也不作为性能达标证据。
