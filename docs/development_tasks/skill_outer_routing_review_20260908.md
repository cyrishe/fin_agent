# 外层方法选择与执行契约评审

日期：2026-09-08。范围：主框架、方法选择规则、渐进工具加载；合并另一任务已完成的 Skill 描述整理。

**评审结论：外层已经有正常的“不选 Skill、直接查数据”路径，执行包门槛也工作正常；但还不能声称误入 Skill 已解决。最终 17/17 分析题选中核心方法，纯取数 5/9 不选 Skill。8 个真实 MCP 请求全部完成，仍有 1 题数据口径偏离及 summary 边界问题。**

## 结论与职责

Skill 优先意味着“适用的方法优先指导执行”，不意味着“每题必须选一个 Skill”。本轮采用一个共享的正向选择规则，以用户要求的产出与方法贡献选择；查询、筛选、排序、聚合可以走通用取数路径。方法提供专业处理、判断依据或交付规范时再加载；后续按真实缺口补充。没有增加模型自报置信度、业务关键词分流、公司／题目特例或新的一套状态机。

| 层级 | 负责什么 | 实现位置 |
| --- | --- | --- |
| 语义选择 SOFT | 本轮产出、方法贡献、正常空集、渐进补充 | `src/scenarios/financial_qa/skill_selection.md`，由 `service.py` 组装供 DSH／当前 CC 共用 |
| 选择衔接 HARD | 首步提供方法加载与数据目录两个正常入口；后续执行等待真实契约 | `tools.py`、`dsh_loop_policy.mjs`；保留单个 ID、批量及空集兼容输入 |
| 数据发现 | subject → dataview → operation，可按目标直接定位执行包 | `read_finance_catalog`；operation 浏览参数不强制必填 |
| 执行衔接 HARD | 每个调用目标已取得模型可见的执行契约 | `dsh_loop_policy.mjs`；原 Python 协议解析器负责语法、参数、字段 |
| 结果 SOFT | 基于证据解释、补充或交付 | 已选方法与通用能力；trace 与正式输出分离 |

最终版本首步开放 `read_finance_skill` 与 `read_finance_catalog`：先评估适用方法，需要时加载；通用取数直接读取数据目录，省去强制提交空集的往返。两者都只是发现／读取，金融数据执行工具仍未开放。同批读取独立方法与目录可以并行，但执行必须依据实际返回的叶子契约；没有因并行读取就放开同批生成的查询。显式指定且已经加载的方法直接复用；没有任何可用方法时直接进入工具路径。没有新增嵌套的“执行 Skill”Agent：加载正文后，仍由当前 Agent 按方法使用工具。

当前 CC 共享方法规则、目录和工具实现；DSH 的逐阶段工具限制与执行包门槛由其原生工具限制／guard 实现。本轮不把 DSH 机制伪装成 CC 同等硬约束，独立封存的 CC 基准完全不动。

## 有证据的原因与修正

1. 另一任务 18 题初选有 3 题同批请求未开放的数据工具；首轮常驻上下文却提前列出这些工具。现在工具按真实可用阶段披露，执行包返回后才开放执行。直接取数也有同等正常的目录入口，不再把调用 Skill 工具当成必经仪式。
2. 原空集只是“没有匹配”的兜底，系统首句、研究模式又重复强调 Skill 优先。实际捕获的纯收盘价问题初始上下文包含这两层偏置；第一版新规则的小样本仍选了个股分析。已统一各层表述，以本轮产出和具体方法贡献为依据；保留失败证据，不声称已证明单句因果。
3. 只加载上层目录即可进入执行，曾导致猜调用结构及字段。现在每个目标必须有本次生成前可见且版本有效的实际方法包；同批才返回的目录不授权已经生成的兄弟调用。缺包返回目录阶段，不计为数据执行失败或消耗修复预算。
4. 股票身份由 `resolve_security` 批量取得标准代码、名称和市场；固定参数化 SQL 查询身份表，歧义保留候选。不强制已有代码／支持名称的接口再做查找。
5. 双入口样本又暴露 `subject`／`dataview` 仅是无描述字符串，出现公司名填入主体类型、把路径填入视图的问题。最终 Schema 从实际目录生成两个标识的可选值并解释含义，保留可选及空字符串浏览；没有增加 subject×dataview×operation 支持矩阵或业务限制。

## 验证设计

- 选择阶段：原 18 题保持题目与预期核心方法，再追加历史工具评测中的 8 道数据获取题，共 26 道；所有 12 个系统业务 Skill 开放，没有按题过滤。原预期集合评分保留，但不把辅助方法多选一律等同业务错误。最终版允许实际已经开放的数据目录调用，并据捕获的原生 Schema 检查参数；这是接口随版本演进的评分适配，历史原始评分不重写。
- 选择测试捕获真实框架首请求，再向模型回放；不派发模型生成的工具调用。它只能验证首选，不能证明 Skill 的最终分析效果。
- 服务端全链路：8 题真实 HTTP MCP，`response_mode=both`、`detail=true`、`research_mode=fast`、`execution_mode=standard`，全部系统 Skill 开放。4 道原研报协议题与 4 道历史纯取数／市场数据题；输出原始记录前两条、summary、真实工具和步骤用量。
- 服务器使用独立 checkout 与隔离监听、worker／结果目录、临时内存 API Key，生产统计记录关闭；读取正式数据和模型配置。不修改数据库、个人 Key、nginx 或线上业务会话。
- 本地历史18题的端点是`dashscope.aliyuncs.com`；服务端使用阿里云北京MAAS端点上的`deepseek-v4-flash-0731`。两者端点不同，历史只作同题参照，不声称严格同端点A/B或稳定性提升。
- 特别校正：MCP原manifest中的`provider=deepseek-official`是Harness适配器名称，**不代表实际访问DeepSeek官网**。服务读取规范`LLM_BASE_URL`；只读复核确认服务器实际域名为`ws-vcy055rt5dmrgd7b.cn-beijing.maas.aliyuncs.com`，选择回放manifest也记录同一域名。已让后续MCP评测manifest单独记录实际配置域名（不含Key），旧原始记录保持不改。

本地其他任务在测试期间新增了基金、债券、资金类 Skill 并更新相关描述，本轮不合并其未完成改动；服务器测试固定在上述 12-Skill 代码版本，避免边测试边变更资产。

### 3. 已确定的机制与保留的问题

- **正常通用路径已落实**：不选方法也可直接找数据目录；有适用方法则加载方法，后续能按缺口补充。没有额外置信度字段或打分调用。
- **执行包门槛实际生效**：蔚来初次混入未读包的基本信息查询，在数据源执行前被挡住；随后读取再执行，不靠长提示要求模型“记得先读”。
- **字段和身份有确定入口**：公开的 `listed_date` 可在基本信息执行包找到，专用股票身份工具确实被调用；模型仍可能做冗余查找，不把新增工具等同于自然语言规划完全正确。
- **方法误入尚未稳定解决**：后续应在固定端点／固定资产下重复测量正向的产出与方法贡献规则；不引入公司、行情问题关键词或大量排除项。
- **数据口径和summary归属SOFT**：市场总额与代表指数、零行边界、额外行业判断需后续优化相应数据说明／通用交付规则；本轮记录证据，没有新增业务拒绝器。
- **真实的目录参数错误仍会由loop纠正**：operation可省略，但提供时必须为操作类别且有subject/dataview。最终一题省略dataview、另一题把operation填成空字符串，均如实保留，不把所有可重试错误当作框架失效。

未来新增 Skill 只需进入授权目录并说明用途，新增工具注册其目录和执行契约；外层继续按同一规则发现、加载和执行，无需为每个 Skill／工具添加路由分支。当前没有证明此机制已在大规模目录下稳定，扩容时仍需固定样本与成本测量。
