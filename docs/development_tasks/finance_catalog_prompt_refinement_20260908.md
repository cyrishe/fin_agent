# 金融 API 目录与提示词：分层优化续篇

日期：2026-09-08。范围：当前 DSH 主线的目录和提示词；封存 CC、生产服务器与数据库保持不变。

## 结论

本轮修复了目录组装中的确定性矛盾，保留五类操作与已有金融计算实现。**目录更一致了，但 12 道历史原题的前后实测尚不能证明整体效果或速度稳定提升。** 缺值后的重复查询、跨方法时间口径混用仍需继续处理；本轮未用针对题目的提示词补丁掩盖这些问题。

## 1. 现在各层各管什么

| 层级 | 内容 | 权威位置 |
|---|---|---|
| 常驻说明 | 角色、数据与分析的职责、证据和交付原则 | `src/scenarios/financial_qa/dsh_system.md` |
| 数据导航 | subject → dataview 的范围、当前可选 op | catalog 的 `desc`；`tools.py::_catalog_routing_index` |
| 方法类别 | query、window、constitution、aggregate、compute 的统一用途 | `catalog.py::OPERATION_DESCRIPTIONS` |
| 当前执行包 | 精确 API、参数、字段、调用格式、特殊口径、示例 | `finance_data_tool_catalog_service.py::get_model_dataview` |
| 当前阶段 | 当前可执行动作及剩余流程；结果证据另行返回 | `dsh_loop_policy.mjs`、`tools.py` |
| 业务分析方法 | 如何解释与分析取得的数据 | 授权业务 Skill；本轮未改 Skill 正文 |

导航示意（由真实 catalog 生成，非另写路由规则）：

```text
stock（股票）
  quote [query/window/aggregate/compute]：历史日 K、分钟 K 与实时快照
  report [query/aggregate]：逐篇研报评级、目标价、观点、风险与来源
  report_metric [query/aggregate]：八类标准年度指标事实
plate（板块）
  constitution [constitution/aggregate]：板块与成分股关系及成分指标统计
hot_event（市场热点）
  member [constitution]：热点与关联股票关系
```

总计仍为 **7 个 subject、31 个 dataview、47 个方法入口、5 类 op**。上层只给导航，选定方法后加载其执行包；省略 op 仍可查看该视图全部方法。

## 2. 本轮具体修正

| 已核实的问题 | 修正方式 |
|---|---|
| 一个 subject 的全部视图挤成一行，上层也未列出可选 op | 改为逐层缩进；op 从已有方法定义生成；移除 subject 对下级范围的重复枚举 |
| `stock.pricevalue` 窗口仅支持 percentile，通用模板却又展示 sum/avg 等方法 | 模型窗口包只通过 `kd` 展示 field → method 组合；删除第二套模板方法清单。模板与执行逻辑原样保留 |
| `hot_event.member` 被归为 query，且普通成分模板展开出不存在的 hot_event_code/name | 导航归入 constitution，API 仍为 `hot_event.member`；使用现有逐行查询模板与真实字段，旧 query 目录选择兼容 |
| 热点关联接口最多返回 500 行，成分模板却宣称 limit=-1 全量 | 移除误套规则，按该 Provider 实际行为说明默认 100、最多 500；本轮不改变其分页能力 |
| 两融明细示例用了 start/end，窗口示例用了 as_of，但参数表未列出 | 补齐已经支持的规范参数。两融明细使用一个内部模板承载其特有日期选择方式，公共 op 仍是 query |
| 研报明细的“limit=-1 返回全部研报/指标事实”处在视图层，聚合也收到 | 该说明移入各自明细方法；聚合保留其分组结果说明 |
| 常驻说明、阶段提示和工具参数多次重复 flow 引用和完成标记定义 | 定义集中在 finance_query，常驻与阶段说明引用它；保留权限、证据和执行约束 |
| 日期、Skill 阶段里仍有反向提醒及固定回答段数 | 改为正向日期基准、适用方法导航和按问题规模表达；用户显式 Skill 的优先级仍保留在常驻说明 |

这些是模板适用范围、说明归属和上下文组装问题。没有增加关键词路由、逐题规避规则、验证器、状态机或新的业务 op；没有更改 median/sum、涨跌停公式等金融实现。

字符量（字符数，不是 token）：常驻说明 **1199 → 921**；导航 **1555 → 1814**（新增全部视图的 op 可用性）；47 个独立执行包合计 **95027 → 95265**（各次独立加载的合计，并非常驻上下文）。本轮目标是消除矛盾与放对层级，不是单纯压缩所有文字。

## 3. 验证

- 47 个方法的**实际可接受参数、必填参数、运行类型、字段及 kd/computed/aggregate_fields/value_domains**前后一致。补齐文档参数未扩张执行能力。
- 除 catalog 映射外，phase2 执行、Provider、解析和校验文件哈希全部一致。
- 测试遍历全部目录与操作，覆盖热点成分的旧 query 选择兼容、错误 `.query` API 不存在、窗口组合单一来源、示例参数完整性及正常查询协议。
- 相关 Python 测试 **428 通过、2 跳过**（未启用的直接数据库测试）；DSH 阶段测试 **39 通过**。不是全仓库测试结论。
- 封存 CC 的 SHA256 清单 **26 项全部通过**。

两侧分别捕获源码快照，串行执行同一批原题，使用本机配置的 Bailian `deepseek-v4-flash-0731`、相同 DSH 阶段策略和应用授权范围。运行模式为完整问答（含 summary）、standard、research_mode=auto；不是预先锁定金融子目录的单步生成测试，也不是重新运行封存 CC。

基金题修改后 API 约0.4秒，最后一轮模型生成约99.5秒。模型耗时口径含请求准备、网络、推理及输出，**不是纯思考时间**。该单题异常延迟贡献了绝大部分总耗时增量，但不能因此删除此题或宣称整体提速。单次小样本与实时服务波动也不足以归因每一个差异。

## 5. 留下的明确断点

1. **成分关系与不同行情口径的组合。** 直接成分聚合现有能力是日行情；今天的统计需要关联实时行情结果。目录虽已写明，模型仍会把行情 mode 混入成分 filter。下一步应还原跨执行包的组合过程，检查阶段上下文与参数作用域，而非追加涨停题专用指令。
2. **完整问答在缺值后反复补查。** 沪深300权重和天齐目标价已有明确缺口，仍触发核验、扩窗或额外聚合；上游 Skill 与阶段策略共同影响此行为。此次只清理说明，未改预算/状态转换，也未将此问题宣布解决。
3. **热点实测环境。** 本次复用的隔离评测启动器只注入 kingdomai 与模型配置；热点 Provider 使用 stock_agent，所需凭据未带入 MCP 子进程。它是本次评测环境限制，不能外推生产也缺配置。本轮未改生产环境，后续热点全链路复测需先补全隔离配置。

这些断点与当前目录修正可分开推进。本轮改动保留在工作区，**未提交、推送或部署，未将实测结果当作生产放行证明**。
