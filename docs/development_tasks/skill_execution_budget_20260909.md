# Skill 分析执行预算调整

## 范围与原因

DSH 标准问答中，实际加载 Skill 后使用独立的分析预算。之前分析请求复用了取数输出上限，可能在工具执行成功后截断最终分析；增加取数次数本身不能解决该问题。

| 项目 | 普通路径（不变） | Skill 标准分析 |
|---|---:|---:|
| 目录调用上限 | 6 | 12 |
| 查询调用上限 | 3 | 8 |
| 明细读取上限 | 2 | 6 |
| 非强制取数阶段的单次模型输出上限 | 原阶段预算 | 8192 token |

输出额度包含推理与正文，不保证正文有 8192 token。以上是工具调用次数上限，不是模型轮数，也不要求执行满额；一次查询调用可以包含组合 flow。推理强度沿用既有配置，默认分析为 low。

## 生效条件和边界

- 当前轮存在成功加载的非空 Skill 正文，或系统已注入显式 Skill 正文。
- 仅适用于 standard 分析，fast 和 data-only 保持原预算。
- 空选、加载失败、仅有 Skill 目录均不扩容；轮次开始时清空既有调用记录。
- 使用已有调用结果判断，不增加业务状态或按 Skill 名称分支。
- 修复、重复调用、必要步骤引导和服务超时限制保持不变。
- `FINANCE_DSH_LOOP_POLICY_CONFIG` 新增可选 `skillMaxCatalogAttempts`、`skillMaxQueryAttempts`、`skillMaxLoadAttempts`、`skillAnalysisMaxTokens`。Skill 路径使用独立额度，原有通用字段仍控制普通路径。

## 验证

本地 Node 协议测试 52 项通过：覆盖非空/空/错误加载、扩容后的查询及明细上限、跨轮重置、配置、fast/data-only 兼容，以及既有目录契约、修复和重复调用回归。

这是本地协议验证，不是生产效果评测；未部署或重启服务器，未重新执行生产用户问题。增加预算降低预算不足的限制，但不保证消除模型输出错误或所有截断。
