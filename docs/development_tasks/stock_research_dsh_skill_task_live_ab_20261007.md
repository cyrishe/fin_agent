# 个股研究：DSH Skill 子任务真实链路对照（2026-10-07）

## 要回答的问题

先前的「受控单会话」把预先取得的数据摘要和两份 Skill 正文一起放进一次模型输入；它既没有走正常 Skill 读取工具，也没有重新取数。先前的 DSH 对照是手工分段的离线模拟，不等于产品中的 Skill 调度。本文用本地 Chat API 入口重新比较。

## 测试边界

- 同一问题：截至 2026-09-30，比较紫金矿业 2026H1 与 2025H1 的归母净利润、经营现金流，判断投资活动净现金流能否代表资本开支，并指出缺口及下一验证点；只用入库财务数据。
- 相同代码 commit `4b4d7a13d16144a43f3e5a5fb991060bccaa1682`、模型 `BL/deepseek-v4.1-flash`、Skill 目录修订 `7dc545259e4098dc4d3960fa23391904c0b38b833d5d03d7b78478482b0951cb`、财务目录修订 `5905f3dbd13c38490a5dd19668d4c79412bf72984be529e74b549a8f0b93e5f1`。
- `scripts/eval_skill_chat_live.py` 通过 Flask test client 调用 `/api/chat/dispatch`，使用真实路由、模型、Skill 读取工具、`finance_query` 和回答生成。身份与会话持久化为本地测试适配；没有浏览器、真实网络 HTTP 传输和生产会话写入。
- 基线是当前单主会话。实验组仅在本地评测进程挂载 DSH 的 `finance_skill_task`，允许一个子会话读取 Skill 和主会话已有的 `result_ref`，不改变生产配置。两组均为单次顺序运行，不能视为统计显著的性能基准。

可复跑用例：`tests/evals/stock_research_dsh_skill_task_live_20261007.json`。基线及实验组证据分别在 `outputs/stock_research_dsh_skill_live_struct_base_20261007/zijin_cashflow/` 和 `outputs/stock_research_dsh_skill_live_struct_managed_r2_20261007/zijin_cashflow/`。较早的 `stock_research_dsh_skill_live_struct_managed_20261007` 子任务因工具名过滤配置错误没有启动，不计入本对照。

## 实际执行链路

| | 当前单会话 | DSH 子任务实验 |
|---|---|---|
| 主会话 | 证券解析 → 读取两份 Skill → 财务目录 → 两次成功取数 → 最终回答 | 证券解析 → 财务目录 → 读取财务质量 Skill → 两次成功取数（另有一次字段校验失败）→ 调用 `finance_skill_task` → 最终回答 |
| 子会话 | 无 | 独立模型会话，调用 `read_finance_skill` 读取业绩分析和财务质量 Skill；调用 `load_finance_result` 读取主会话的 `result_ref`；返回局部分析 |
| 是否网页取数 | 否 | 否 |

这里的「调用 Skill」是读取 Skill 文档后按其方法完成局部任务，Skill 本身不是一个可执行 Agent。子会话确实独立运行，但仍需主会话明确提供证券、期间、局部问题与结果引用。实验组父子均读取了财务质量 Skill，说明现有子任务配置尚有重复上下文。

## 结果

| 指标 | 当前单会话 | DSH 子任务实验 | 解释 |
|---|---:|---:|---|
| Chat API 端到端耗时 | 111.3 秒 | 144.6 秒 | 实验组多 33.3 秒（约 30%） |
| 模型调用 | 4 | 7（主 5、子 2） | 子任务确实产生独立调用 |
| 输入 + 输出 token，不含缓存读取 | 26,798 | 55,351（主 46,428、子 8,923） | 实验组约 2.07 倍；只看主会话会漏掉子会话消耗 |
| 缓存读取 token | 36,864 | 34,560（主 32,512、子 2,048） | 单独列出，不能直接等同付费 token |
| 含缓存读取的输入 + 输出总量 | 63,662 | 89,911 | 实验组约 1.41 倍 |
| 最终回答字符数 | 3,281 | 2,720 | 实验组短约 17%，但仍偏长 |
| 核心数值 | 两组均正确给出归母净利润 232.92→391.70 亿、经营现金流 288.30→554.72 亿，以及同比 +68.2%/+92.4% | 同左 | 子任务未带来可见的核心数值改进 |

两个回答都正确指出投资活动净现金流不是资本开支，也都明确缺少购建长期资产支付现金等明细。但两组都有一个共同的**分析口径错误**：把 `2025-06-30 → 2026-06-30` 的固定资产余额同比增加 **192.62 亿**，与 **2026H1 六个月累计**投资活动净流出 **182.36 亿**直接比较。这是十二个月的存量变化与六个月的流量混比。基线其实取到了 `2025-12-31` 固定资产 **1,170.42 亿**；若只算 2026H1 的余额变化，应为 `1,232.57 - 1,170.42 = 62.15 亿`。即便使用同期间差额，固定资产余额变化也不能推定购建现金支出，因为折旧、在建转固、并购并表、处置与汇率均会影响余额。实验组还称余额变化是资本开支「粗上界」，这个上下界判断也不成立。

实验组第一次 `finance_query` 请求不存在的 `cashflow_operating_yoy` 字段，被现有目录校验挡住；随后重试成功。这是一次真实的工具修复开销，而不是返回数据错误。两个回答也都从应收和存货的同比增速低于收入增速，推到「未对现金形成拖累」；现有两期余额并不足以支持这个确定性结论。

## 判断

这次更真实的对照证明 DSH 可以把局部 Skill 分析放在独立会话中，并让子任务沿引用读取已经取得的数据；它并没有证明这种分段能自动减少 token、缩短耗时或消除财务口径错误。当前实验反而更慢、总消耗更大，业务答案没有明显提升。因此不应据此将 `finance_skill_task` 直接上线为个股研究默认路径。

下一轮应针对真实失误改造任务边界：主会话提供小而清楚的证据包（证券、报表口径、期间、单位、数据引用）；子任务只负责一个明确的财务判断，并返回简短结论、关键数字、不能推断之处；主会话负责综合且避免重复取数和重复读 Skill。这些可以先在 SOFT 层和测试用例中验证，暂时不新增核心协议状态或大规模校验器。必须以多题、多个行业和一致的事实评分复测，才能判断是否值得产品化。
