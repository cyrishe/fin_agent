# 金融目录分层优化：10 道历史题对照

## 结论

最终版本的取数完成度有所改善、模型输入减少，但不能说“所有问题都更快、更准”。10 题人工复核中，基线 8 题、最终版 9 题的数据方案基本合理；剩余一题是“今天的板块统计”仍取上一交易日日行情。这个数字只描述本次小样本，不是全量准确率。

所有问题原文来自历史评测集，使用本地 DSH、Bailian `deepseek-v4-flash-0731`、standard、data-only、全目录；没有指定必须走研报，也没有编造新题。每组只运行一次，前5/后5分别启动，最终表不拼取不同版本的最佳结果。

## 消耗与可靠性

| 指标 | 基线 | 最终 |
|---|---:|---:|
| 请求正常结束 | 9/10 | 10/10 |
| 数据方案基本合理（人工复核） | 8/10 | 9/10 |
| 发生静态失败的题数 | 2 | 2 |
| 静态失败总次数 | 3 | 2 |
| 模型调用总轮次 | 22 | 23 |
| 目录读取次数 | 13 | 16 |
| 累计输入上下文 tokens（含缓存） | 111,785 | 92,716 |
| 其中非缓存输入 / 缓存输入 | 47,273 / 64,512 | 38,444 / 54,272 |
| 输出 tokens | 6,666 | 5,030 |
| 总 tokens（输入含缓存 + 输出） | 118,451 | 97,746 |
| 模型调用阶段合计 | 83.774秒 | 65.033秒 |
| 底层数据 API 合计 | 10.204秒 | 7.175秒 |
| 总请求时间合计 | 109.647秒 | 90.617秒 |

输入上下文减少17.1%；本次观测总耗时减少17.4%，但轮次并未减少。多数总耗时差来自板块题的失败/恢复路径变化；缓存、冷启动、数据库响应和模型随机性也不同，不能据此承诺稳定17.4%提速。模型阶段计时含请求准备和生成，不能冒充精确的纯思考时间。

静态通过不等于语义正确：基线宁德时代行情的 `code == '300750.SZ'` 被解析成 `code: "= '300750.SZ'"`，虽然校验通过，却没有保真。该既有解析缺陷另列保留，本轮没有通过扩大校验器修复它。

## 剩余问题：板块统计的日期

最终第一次使用了不存在的 `stock.quote.change_percent`，被静态检查拦下；读取行情字段后改为 `pct`，计数用 `is_limit_price`，两项聚合均成功：

```text
plate.constitution.agg(
  filter="plate_name == '人工智能' and tradedate == -1",
  agg=avg(stock.quote.pct), ...)

plate.constitution.agg(
  filter="plate_name == '人工智能' and tradedate == -1 and is_limit_price == 1",
  agg=count(stock.quote.pct), ...)
```

这些是上一交易日的日行情数据，不是今日实时行情。目录已如实公开直接 `stock.quote` 聚合的数据源为日行情；模型仍选择了这一口径。应继续保留真实样本观察，不能因为API成功就记作完全正确，也不为了这道题在提示词中堆补丁。

## 中间试验与最终版本绑定

本轮共35次真实请求：基线10题、第一修改版10题、中间诊断版5题、最终固定版10题。全部保留，最终对照只使用最初基线10题和最后固定版10题。

- 第一修改版暴露：SDK的 `$stock_codes` 占位符示例混入没有bindings参数的Agent工具；公开schema允许省略operation，而DSH guard却拒绝，导致额外重试甚至blocked。两项均按接口契约修正，而非按题目写提示。
- 第一修改版还发生过“平安转债”被扩大为“平安”的语义错误；中间诊断版发生过ROE字段拼写错误及漏年报日期。不能因最终一遍没有再次出现，就认定这些波动已经被根治。
- 中间诊断版只跑5题后发现需要准确公开“日行情”边界，因此封存为诊断结果，重新固定最终快照后完整跑同10题，没有拼表。
