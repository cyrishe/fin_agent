## 仍未解决的问题

### 1. 人工智能板块平均涨幅、涨停家数：未完成且更慢

该题由63.28秒增至89.18秒，共7个模型轮次：

| 轮次 | 实际动作 | 模型耗时 |
| --- | --- | ---: |
| 1 | 读取板块成分明细与聚合目录 | 4.76秒 |
| 2 | 查板块及成分股 | 2.31秒 |
| 3 | 查平均涨幅；涨停计数使用非法跨视图条件，被静态检查拒绝 | 2.98秒 |
| 4 | 修正阶段用满3072输出Token，全部用于推理，未产生工具调用 | 40.93秒 |
| 5 | 再读个股行情目录 | 4.78秒 |
| 6 | 继续修正，但仍生成不存在的 `is_limit_price` 字段和不支持的 `true` 字面量 | 29.97秒 |
| 7 | 返回不完整summary | 3.04秒 |

全部数据调用累计约 **0.13秒**，模型请求累计 **88.76秒**。这次不是索引或数据库慢。首次还使用统一 `pct >= 9.9` 判涨停，不能满足不同证券的涨停规则；被拦截的直接原因则是结构上的跨视图字段，不是静态检查理解了这条业务错误。

平均值查询使用 `tradedate == -1`，summary又混用“今日”和“上一交易日”。返回1481条包括1480条中间成分记录和1条平均值，并不表示整个问题完成。

### 2. 新宙邦机构增长预期：仍生成不存在的API

模型读取了 `stock.report_metric` 的 aggregate 操作目录，却生成 `stock.report_metric.query(...)`，且首次遗漏 `->` 输出字段。修正只补了输出字段，API路径仍错误，最终失败。

这是目录操作选择与后续请求生成没有一致衔接，不是数据不存在。系统实际有 `stock.report_metric(...)` 明细接口和 `.agg(...)` 聚合接口。summary声称该视图只有聚合、没有明细，是对当前所加载目录切片的错误概括。

### 3. 行业成分股：新增一次结构修正

先生成 `industry_name == r1.industry`，结果列按协议是集合，被静态检查拒绝；改为 `industry_name in r1.industry` 后取数成功。该题说明当前组合引用仍有生成波动，不能宣称一次生成已全面稳定。

本轮共3题出现结构问题，其中1题修正后完成，2题未完成。5个错误子请求中，1个是外层解析错误、4个被静态检查拦截。没有在评测途中修改代码或追加自动重跑来替换失败记录。
