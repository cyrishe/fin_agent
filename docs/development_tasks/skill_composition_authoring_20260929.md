# Skill 协作与用户编写：对接现有体系

日期：2026-09-29。基于当前工作区实现；未部署、未修改生产数据库或启用真实用户资产。

## 目标与职责

延续现有 `SkillHubCatalogService → FinanceBusinessSkillCatalog → Finance Agent` 主线。用户 Skill 与系统 Skill 使用同一方法运行机制。用户描述研究目标和偏好，Agent 按需读取专业方法，使用共享数据工具并给出一个综合结果。

- SOFT：用户目标、专业方法、方法选择、组合顺序、解释与交付偏好。
- HARD：已有身份、owner、可见性、不可变revision、active指针、授权快照和结果引用。
- 运行主体仍是当前 Agent。关联 Skill 是方法上下文，不是自动递归调用、独立子Agent或新的工作流状态机。

本次不增加数据库表、必填输出字段、运行状态、业务验证器或逐指标路由。当前系统目录18个方法；沿用现有简述发现、正文加载、按需参考三层结构。

## 推荐的使用流程

1. **用户说目标**：例如“结合技术面与行业表现复盘持仓，指标由你选择”。不要求填因子清单、工具名或子方法ID。
2. **生成候选**：编写Agent读取当前可用能力，把用户目标、专业方法的贡献、按需条件和输出偏好写入方法。专业细节复用系统方法，避免把目录中每种能力都变成必做步骤。
3. **阅读与反馈**：先看方法和工作步骤，直接说“保留范围，回答缩成三段”。系统携带完整上一版、已有引用和有效能力；无须用户重新输入。
4. **显式启用**：沿用现有candidate/active与CAS机制。修改创建新候选，不覆盖已启用版；公开分享是独立动作。
5. **执行与协作**：主Agent读取用户方法，按任务读取专业方法和必要参考，发现数据口径，执行查询；后续方法复用同对象、同周期、同口径和实际截止时点的结果。已有数据足够时直接分析。
6. **统一交付与迭代**：给一份符合用户偏好的结论，保留实际证据和缺口。方法文本不替代数据，多个同源判断不算独立证明。进一步优化继续走候选反馈。

系统方法的协作遵循同一原则：围绕本题选主要方法，实际缺口决定是否补充。技术结构、K线、相对表现可以组合，但不固定串行全部运行；复杂度来自业务需求，不来自Skill数量。

## 实现边界

`related_skills`仍是现有的composition_context。运行包中的附录为其派生视图，不复制关联方法正文。正文读取、应用限定和工具权限仍由原运行体系执行。未知、不可访问、自身和重复关联不进入附录；关联不会将目标方法加入调用者授权范围。

旧候选没有关联字段时沿用原行为。关联用途变化随启用版本改变运行哈希；旧快照保持原内容。不会自动启用关联草稿，也不会自动授予该方法声明的附加工具。

格式错误仍使用既有的一次修复机会。本次真实模型曾漏写frontmatter description，两次泛化错误提示未修复；现将错误指向具体缺项及位置，未增加重试次数或新状态。
