# 列表展示与模型读取解耦（2026-09-10）

## 澄清原始请求

CPO 样本 turn 2260 的完整取数结果为190行，全部保存于 result_ref 指向的结果存储。第一次查询给模型 schema、row_count 和3行样本；模型随后两次调用 load_finance_result，各读取50行，因此100行进入该轮模型上下文，并被正文表格重复输出。独立数据卡片仍绑定完整结果，不受这100行限制。

原报告所说43.043秒是第六、七次模型步骤之和，包括决定读取第二页的处理和最终正文生成，不是数据库取数耗时，也不代表完整190行都经过了LLM。用户接受正文截断、少量示例和分页展示，因此本轮不改造现有展示样式，也不把正文少于190行视为整体交付失败。

## 实施

本次属于 SOFT 框架适配与既有工具契约说明，无新增业务状态、关键词路由、输出字段或模型调用。

- Presentation 提供当前聊天入口的真实展示能力说明：明细表可从已存结果分页读取，界面翻页不经模型。Service 将说明提供给 CC/DSH 的本轮输入。沿用现有数字 thread_id 的聊天分页边界；独立 API 标识和仅数据模式不注入网页分页承诺。
- 查询工具说明完整结果、模型预览和展示范围的区别；data_request_complete 依据已保存结果覆盖判断，sample_complete=false 不要求为了界面展示继续取数。
- load_finance_result 明确是向模型提供具体内容的读取入口。分析、比较、核验或用户明确要求全文正文时仍可读取，不拒绝调用、不缩减工具预算。
- DSH 系统提示说明模型读取范围和用户展示范围分别管理；列表优先按入口能力交付，真正依赖具体内容的工作继续按需读取。

没有改变缓存内容、结果权限、金融查询范围、业务 Skill、分页接口或前端布局。现有表格在参考数据区展开后按页加载；它已经是所需的分页实现，无需另造缓存或第二套分页协议。
