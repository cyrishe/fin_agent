# 从公司资讯目录逐步读取新闻

## 主线

用户问题 → Agent/DSH 选择来源 → general_search 返回日期、标题、URL → Agent 判断相关性并选择链接 → general_search 返回所选正文 Markdown → Agent 综合回答并引用来源。

相关性、事件推理与不同市场证券的归属由模型解释。工具承担股票代码到固定资讯目录的定位、HTML 提取、时间排序、限量与链接读取。没有新增业务阶段或自动相关性分数，也没有额外嵌套一个搜索模型。选中的 URL 是两次调用之间的稳定执行参数。

当前首个目录来源为新浪个股资讯，支持显式市场代码（300408.SZ 或 sz300408）。股票目录不依赖 Brave 或 ES 的 provider 配置，也不产生 Brave API 请求。无 stock_code 或 urls 的原有调用继续使用配置的搜索 provider。

```python
general_search(query="三环集团近期上涨原因", stock_code="300408.SZ", limit=15)
# 模型结合标题、日期选择链接；下一次调用中的 urls 必须来自已取得的候选。
general_search(query="三环集团近期上涨原因", urls=["实际选择的文章链接"])
```

首轮仅取当前目录页，按目录日期降序，total 为该页提取并经过时间过滤的候选数，不是全网或历史新闻总量。正文一次最多5条，3路并行，每篇 HTML 最多1 MB、Markdown 最多5000字符；支持已验证的新浪移动到桌面站跳转，最多3次跳转且逐跳校验支持域名。单篇失败明确返回未取得正文；全部失败返回 ok=false。站点目录可混入行业、基金和另一上市市场的信息，需要读正文核对证券市场和事件日期。

DSH 复用现有 general_search 工具资产、结果变量和 load_finance_result；补齐会话上下文中的 allowed_agent_tools/skill_tool_access 传递，以及 MCP 与标准模式执行策略中的可见性。授权变化时重建工具列表；普通用户未授权时不可见。fast 模式保留既有执行边界。工具调用和结果引用进入既有 trace，无额外状态机。

## 三环集团案例的用量统计与筛选预算

统计对象为上述首次真实三环集团实验，不重跑模型或抓取。模型为 deepseek-v4-flash-0731，5轮模型请求，目录返回15条候选，选择5个不同URL读取正文，Brave请求0次。5个不同URL不代表5个独立新闻事件：本次含多篇MLCC/村田主题报道，主题层面仍存在信息重叠。

| 模型轮次 | 下一步动作 | 非缓存输入 | 缓存读取 | 输出（含推理） | 模型步骤区间 |
|---|---|---:|---:|---:|---:|
| 1 | 读取目录、解析证券 | 4,227 | 0 | 211 | 3.079秒 |
| 2 | 展开15条标题 | 928 | 4,096 | 232 | 3.309秒 |
| 3 | 选择5篇正文 | 2,450 | 4,096 | 537 | 5.249秒 |
| 4 | 展开部分已保存正文 | 5,337 | 6,144 | 321 | 3.992秒 |
| 5 | 综合回答 | 2,888 | 11,264 | 1,457 | 15.256秒 |
| 合计 | | 15,830 | 25,600 | 2,758 | 30.885秒 |

累计输入上下文为41,430 token，含输出的处理量为44,188 token。输出中602为推理token，已包含在2,758中，不能再次相加。最后一次请求上下文为14,152 token。日志 llm_usage.total_tokens=18,588 是非缓存输入加输出，未包含25,600缓存读取；这不是完整token处理量，也不能据此直接推算账户金额。实际金额取决于当前提供商缓存与输出计价。

总耗时41.513秒。按session事件时间戳计算：目录工具往返1.439秒，5篇正文工具往返1.555秒（内部并行，含提取与结果保存），证券解析0.333秒，两次已保存结果读取合计0.029秒；工具区间共3.356秒，模型步骤区间共30.885秒，初始化、调度及其它区间合计7.272秒。模型步骤包含请求往返和本地处理，不能解释为纯服务端推理时间；这一次也未记录逐篇HTTP请求数及逐篇网络耗时。

当前选择策略：每个问题先看最新10–20条候选，结合时间窗口、相关性和新增信息合并后最多读5篇；同事件转载/近似标题优先保留原始或证据完整的来源，有新增事实或不同观点的报道可保留，已有正文复用，不足5篇不凑数。该累计5篇是DSH工具使用指引；工具已有单次maxItems=5及完全相同URL去重，没有新增跨调用计数器或语义去重validator，因此不是跨调用的硬配额。此指引更新后尚未重新跑业务效果评测。
