# 金融数据目录：五类方法与分层说明优化

日期：2026-09-08。范围：本地工作区的数据取数链路；未提交、部署或修改生产库。

## 1. 现在的体系

成分关系已独立为 `constitution`，不再以 `query` 作为规范分类。调用仍是 `index/industry/plate.constitution(...)`；旧客户端用 `operation=query` 读取成分目录仍兼容。

```text
金融数据
  └─ subject：对象（股票、指数、行业、板块、基金、债券、热点事件）
       └─ dataview：数据范围、记录粒度、字段与口径
            └─ operation：本次方法
                 └─ 完整契约：用途 → 精确调用 → 参数 → 输出 → 特殊口径 → 示例
```

| 方法类别 | 用途 | 实际调用形态 |
|---|---|---|
| query | 明细筛选、排序、限量 | `subject.dataview(...)` |
| window | 已定义的 K 期指标 | `subject.dataview.kd_<field>_<method>(...)` |
| constitution | 主体与成分证券的关系 | `subject.constitution(...)` |
| aggregate | 当前记录或成分证券的分组统计 | `subject.dataview.agg(...)` |
| compute | 自定义行情计算 | `stock.quote.dynamic_cal(...)` |

五类是公共的选择逻辑，15 个内部模板继续复用实现差异；不是让模型学习 15 套操作分类。现有 7 个 subject、31 个 dataview、47 个 API 名称保持。

## 2. 各层只负责自己的内容

| 层级 | 提供给模型什么 | 权威位置 |
|---|---|---|
| 常驻角色 | 理解目标、交付方式、证据责任 | `financial_qa/system.md`、`dsh_system.md` |
| 路由目录 | 哪类对象有哪些数据；五类方法用途 | `catalog.py::OPERATION_DESCRIPTIONS` + catalog 的 subject/dataview 描述 |
| 当前执行包 | 本方法完整定义及数据字段 | `finance_data_tool_catalog_service.py::get_model_dataview` |
| 当前阶段 | 此刻读目录、查询、修复还是收尾 | `dsh_loop_policy.mjs` |
| 执行返回 | 结果引用、样例、实际口径、失败及恢复事实 | `result_registry.py`、现有结果协议 |
| 专业分析 | 根据问题选择金融分析方法 | finance-business Skill；本轮只精简入口描述 |

模型执行包不再要求从 `function.api_class` 跳到另一块 `api_classes` 拼定义。每个 function 直接包含 `api_name`、`operation`、`request_pattern`、`args`、`output_rule`、局部规则与示例。调用签名展开真实 API 和成分字段，并呈现关键字参数形式。

CC、DSH 与旧分阶段查询共用这一组装结果。Coding 资料保留其文件接口，同时对齐五类 operation、调用签名，并补齐共享筛选语法、值域和聚合字段。编辑器仍保留内部模板结构，兼容原有维护方式。

## 3. 清理与保留

已完成：

- 全量归纳 31 个视图、15 个模板的说明；删除示例 note 中重复的规约和内部源表/SQL实现介绍。
- 视图说明数据范围，具体方法说明自身参数、结果与特殊口径；明细用途留在明细方法，聚合说明自己的输入与分组。
- 移除 DSH 阶段中的业务关键词路由表，具体入口由 catalog 决定；删除“单点查询必须补数据”的强制引导。
- 11 个业务 Skill 的目录与 frontmatter 描述同步为正向用途；未重写研究方法正文。
- 股票行情字段的适用 mode 从执行端现有字段集合生成，与静态检查同源。

保留：字段和参数合法性、安全边界、结果引用、明确的完成标志、金融特殊公式和默认口径。没有增加业务语义 validator，也没有改变 median、融资变化、窗口算法、实时涨跌停或数据源执行实现。

## 4. 回归揭示并修正的结构问题

| 问题 | 根因 | 本次修正 |
|---|---|---|
| 成分聚合的 filter 写成完整指标路径 | agg 与 filter 的字段命名空间未集中定义 | 共享模板明确：agg 使用指标路径，filter 使用关系字段及所选指标视图/结果的短字段名 |
| 行情示例出现无法绑定的 `$stock_codes` | SDK 专属 bindings 示例进入了不提供 bindings 的 Agent 工具 | 共享示例改为各端均可执行的字面列表；SDK 绑定仍由 SDK 文档说明 |
| 合法目录读取被拒、额外消耗预算 | 工具允许省略 operation，DSH guard 却要求必填 | guard 对齐公开工具契约，允许完整视图读取；非法参数依赖仍拒绝 |
| 成分聚合被理解为继承实时行情 | 直接引用 stock.quote 实际走日行情库 | 准确声明直接聚合的日行情范围；其他已查询数据仍通过逐股票结果列组合 |

这些修正都回到实际调用契约，没有加入涨停题、公司名或某个问题专属的提示。

## 6. 历史样本回归

本节实测运行器是 **DSH**，不是 CC / DSH 双运行器对照。使用原有 10 道题，覆盖股票行情、资金、三张表、指数成分、板块聚合与窗口、基金、债券、研报正文和指标；全部目录可选，非固定研报入口。基线和各迭代均用不可变源码快照，最终版整组重跑，不从不同版本挑选最好结果。

| 小样本结果 | 改前 | 最终版 |
|---|---:|---:|
| 数据方案基本合理（人工复核） | 8/10 | 9/10 |
| 请求正常结束 | 9/10 | 10/10 |
| 静态失败次数 | 3 | 2 |
| 模型轮次 | 22 | 23 |
| 输入上下文 token（含缓存） | 111,785 | 92,716 |
| 输入＋输出总 token | 118,451 | 97,746 |
| 模型阶段合计秒数 | 83.77 | 65.03 |
| 总请求合计秒数 | 109.65 | 90.62 |

输入上下文减少约17%，本次总耗时减少约17%，但轮次没有下降；大部分时间差来自板块题的失败/恢复路径，不能外推为稳定提速或全量准确率。两版各有2题发生静态失败；最终额外预测查询也增加了部分题目的耗时。

剩余未完全对齐的题是“今天板块平均涨跌幅和涨停家数”：最终两项聚合完成，但使用上一交易日，时间口径仍不正确。日期、实体条件、字段与数据范围均纳入复核，不以 API 成功代替正确性。

[10题简洁对照](finance_catalog_layering_sample_review_20260908.md)列出每道原题、最终入口、前后轮次/时间与判断；[机器汇总](../../outputs/catalog_layering_sample_20260908/summary.json)保留 token、时间和源码绑定。本轮合计35次真实请求：基线10、第一版10、中间诊断5、最终固定版10；中间失败保留，未拼取最佳结果。最终快照的全部 src/config 与当前源码哈希一致，目录 revision 为 `6decc5e9e21b03865248706f63344cfc75e13591ba40f5e9aefb9fefd045369d`。

### 已确认的剩余边界

- 旧解析器会把 `code == '...'` 这种错误位置表达式误当作 `code` 参数值；基线已确定性复现。新的关键字签名改善说明，但不等于解析器缺陷已修。本轮未扩大到解析器改造。
- 成分聚合直接行情仍是日行情能力；是否按用户要求选择实时数据并正确组合，属于需要继续评测的生成效果。
- 数据中的重复成分、权重缺值、空记录及窗口缺数据独立于目录结构；本次不以缺数据本身判入口错误。
