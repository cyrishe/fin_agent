# DSH 明细读取保真与按需选列实施记录

日期：2026-09-10。基线 Fin `a4fd7d2`，DSH `0433ae61319e1cdbe8adc8f1ca7192306bd2a6e4`。本轮按用户要求实施效率优化，并提交、推送；不执行生产部署。前置分析见 [按任务读取调研](dsh_adaptive_reading_review_20260910.md)，展示优化见 [结果展示记录](dsh_result_display_efficiency_20260910.md)。

## 决策和实施

本次属于 SOFT 工具契约说明和 DSH 原生执行协议适配，不修改业务 Skill、金融数据口径、统计方法和前端布局。

1. **主动读取的明细完整进入模型。** 继续使用 DSH 原生 `tools/post-execute`，初次查询仍提供受限样本和完整引用；`load_finance_result` 的响应只做 JSON 格式空白压缩，不再裁行或裁单元格。原来模型请求 offset=0/50/100/150，却各只收到4—10行，会漏掉中间数据；长字段反复读取仍只能看前缀。现在返回页与实际模型可见页相同，长字段尾部可以读到。
2. **成功分页不再消耗失败预算。** `maxLoadAttempts` / `skillMaxLoadAttempts` 保留旧配置键，改为约束实际失败的明细读取，默认分别为2/8。从原生调用和结果事件推导失败数，不增加状态。并行发出的有效页不因预先累计调用数而被拒绝。完全相同的重复调用、失败修复额度、原有查询额度和整个任务的超时边界继续生效。合法空结果不是读取失败。
3. **查询额度与已存结果读取分开。** 普通模式用尽查询额度后仍能读取已保存证据；不会因此重新开放查询。原有 fast 和 data-only 终止语义保留。
4. **Agent 自行选列、选范围。** 在现有 `columns` 参数集中说明：根据完整 schema 和样本选择参与分析的列，遍历所有行仍可只读必要列，之后可增列补读。`limit` 明确单次最多50行和实际续页位置。不新增读取规划模型、业务关键词、读取模式枚举或强制少读规则。

这里选择先保证完整取证，而不是新建长字段切片协议：原先24,000多字符的单元格现在可以一次完整读取。模型可通过现有 columns/filter/order/offset/limit 控制输入范围，省略 columns 或传空列表仍为本页全列。极大单元格/全文任务可能消耗更多上下文；本轮没有承诺任意数据规模都能在既有模型窗口或超时内完成。后续若真实 workload 需要，再接可定位的分段读取。

## 原生能力使用边界

- 沿用 DSH 的工具守卫、原生事件和 post-execute 内容投影；工具 canonical value、存储、权限和 UI 分页没有修改。
- 保留原生 `request/history`：独立请求从当前 turn 组装模型历史，旧内容仍存于 session；后续相关请求恢复完整历史。没有追加上下文分类模型。
- 没有启用 PTC、宿主代码执行、自动摘要、head/tail pruner 或不可回读的 spill。此前调研已经说明它们的隔离、权限与语义取证边界；仅为节省 token 开启它们不满足本轮效果优先要求。
- `detailCellMaxChars` / `detailTotalMaxChars` 作为历史配置兼容解析，不再对明确请求的明细执行裁剪；`detailMaxRows` 在 Python 适配器中原有的默认页大小作用保留。查询预览配置含义不变。
