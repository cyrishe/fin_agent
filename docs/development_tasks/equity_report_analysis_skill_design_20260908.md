## 能力定位

“个股研报解读”把机构研究转化为当前个股问题可用的证据：机构说了什么、根据什么、相互分歧在哪里、观点如何变化、对用户的命题有什么贡献。

直接入口包括报告事实、机构看法、目标价、评级、预测、管理层、业务与事件解释。间接入口是个股深度分析中需要研报提供的观点、预期、反证或产业链线索。目标公司是分析中心，确有必要时可用相关公司或行业研报补证，不自动扩展成全行业研究。

研报对自身观点和预测的记载可以核验，但其预测不等于实际业绩，其投资逻辑也不等于已证实因果。方法需将报告陈述、机构判断、机构预测、公司事实与本轮推断清楚表达；这些是业务写作与评测要求，不增加系统事实类别枚举或业务 validator。

## 总分关系

```text
Finance Agent：理解用户问题并统一综合
  ├─ 直接研报任务：使用个股研报解读
  └─ 个股深度研究：按证据需要采用研报解读及其他方法
        ↓
个股研报解读总 Skill
  ├─ 默认：定位、取证、字段查询、基础总结与分布说明
  ├─ 专题证据综合
  ├─ 共识与分歧
  ├─ 预测与估值假设
  ├─ 观点与预期修订
  ├─ 事件与情景传导
  ├─ 产业链线索
  └─ 兑现与论点复核
        ↓
选择零个或若干专业子方法，共用本轮证据，形成一次回答
```

产品上可以展示为“总 Skill / 子方法”。首轮实现采用一个顶层 `SKILL.md` 和按需 References：同一 Finance Agent 读取相应指导，Reference Loader 负责资源与权限。默认方法直接放在总正文，避免为简单事实增加文件读取。只有某个方法以后有独立触发、跨任务复用和评测价值时，再考虑独立注册为 Skill。

这保留用户期望的总分关系和灵活组合，不增加父子Agent、隐藏执行依赖或路由状态机。`stock-research` 由 Finance Agent 选择并列研究方法，不直接递归调用本 Skill。专业方法选择不强制等到取完全部数据后发生；初步证据可改变后续取证和方法选择。

## 场景划分

| 方法 | 典型问法 | 专业贡献 |
| --- | --- | --- |
| 默认检索解读 | 最新目标价、评级、作者、机构覆盖；总结一篇报告 | 精确来源、时点、统计对象和主要观点 |
| 专题证据综合 | 管理层如何、护城河是什么、新业务空间多大 | 区分评价与行为证据、行业空间与公司兑现 |
| 共识与分歧 | 机构怎么看、分歧在哪、看多与谨慎各依据什么 | 对齐样本和命题，分清观点差异与口径差异 |
| 预测与估值假设 | 为何给这个目标价、估值靠PE还是DCF | 连接预测、模型条件和目标期限 |
| 观点与预期修订 | 最近谁上调、与之前相比有什么变化 | 同机构同年度配对，分清时间变化与样本变化 |
| 事件与情景传导 | 原料上涨10%、政策或订单变化有何影响 | 暴露、传导、缓冲、时间和条件测算 |
| 产业链线索 | 大客户扩产会否带来订单、供应链关系是什么 | 连接实体证据，区分认证、订单与收入 |
| 兑现与论点复核 | 过去预测准不准、原来逻辑还成立吗 | 早期预测和后来实际对照，检验关键假设 |

截图中四类均被覆盖。风险分析贯穿专题、分歧、传导和复核，不为每个业务名词再建一个方法。研报质量与分析师长期准确率排名暂不承诺；后者需要足够历史样本、实际值与可比较评价方法。

## 组合示例

- “A证券最新目标价是多少”：默认精确查询并给机构、日期、期限；不要求加载估值方法。
- “机构对公司怎么看”：默认样本定位；必要时组合专题综合与共识分歧，解释共同逻辑与争议前提。
- “M材料涨价对公司有何影响”：定位相关业务证据，选择事件传导；存在上下游关系问题时读产业链方法；机构假设矛盾时再读分歧方法。
- “管理层怎么样”：专题综合，将机构评语与实际行动证据分别表达；无相应内容时说明可读材料缺口。
- “深度研究公司，预期是否过高”：主研究统筹财务、价格与事件；本 Skill 提供预测假设、机构分歧和观点变化，最终融入主研究结论。

源码：[report_provider.py](../../src/experiments/staged_data_protocol/phase2/report_provider.py)、[当前目录](../../src/tools/finance_data/catalog/api_view_catalog.json)、[旧工具定义](../../src/tools/definitions/equity_research_search.tool.json)。聚合不是预定义的一致预期产品；直接对报告行做均值会让频繁发报告的机构获得额外权重。每机构最新可比样本是本实验可选的分析口径，实际计算必须按该口径执行并说明覆盖。

## 产品交互

### 统一发现、显式使用和三类归属

根据2026-09-08用户补充，本实验的正式接入要求包括：与其他业务Skill共用Agent可发现的目录，支持用户通过`$`明确选择，同时支持system、public、private三类归属/可见性。研报Skill不设专用发现或执行旁路。

| 产品分类 | 创建与维护 | 正常目录和`$`的可用范围 |
| --- | --- | --- |
| system | 平台维护的业务方法 | 已启用且应用授权范围内的用户 |
| public | 个人创建并选择公开分享 | 平台内符合应用与运行权限的用户；原作者持有维护权 |
| private | 个人创建、仅本人使用 | 所有者本人；其他用户的召回、补全和内容读取均不可见 |

这三类描述归属和分享范围，与现有`business_method / system_skill / legacy_compiled`执行类型不同。例如平台维护的研报Skill属于system归属、business_method执行类型；内部开发用的system_skill不会因为同含“system”就进入用户目录。

底层优先利用可信的系统归属信息、owner和visibility生成三类展示，不另存一份重复授权语义的三值状态，也不复用现有业务主题category。身份与可见性由系统管理，不由Skill正文或模型声明决定。公开分享与版本启用分别处理：private的已启用版本也应能被本人自动选中或`$`使用；尚未启用的candidate只在创作/隔离试跑中使用。

建议以本研报方法作为system基线，用户复制后形成独立身份的private版本，优化后可将自己的版本设为public。复制不改变原资产owner，不让普通用户修改平台版或他人公开版；名称相同时以稳定身份解析，选择界面展示作者和来源。

Agent发现目录、Skill Hub与`$`补全必须基于同一份按当前身份和应用授权过滤的active Skill集合；自动选择和显式选择加载同一版本包。用户输入`$equity-report-analysis`表达本轮明确采用该方法，不能只是删除标记后再次当成普通语义匹配，也不能把它交给历史compiled SkillRunner。数据与工具权限仍取调用用户实际权限和运行策略的交集，公开分享Skill不分享作者的数据、凭据或历史运行结果。

目录初期只注册研报总Skill。七个子方法作为随父Skill版本发布的References，继承父Skill的可见性与读取授权，不单独占据七个`$`入口。用户可以在同一次调用中用自然语言限定“只比较分歧”或“重点看产业链”，方法仍可灵活组合。

**当前源码尚未完成上述统一链路：**

- [Skill Hub](../../src/services/skill_hub_catalog_service.py)目前能投影系统业务方法，但`invocation_enabled=False`，业务Skill的`$`被明确保留为待接入切片。
- [显式调用服务](../../src/services/asset_invocation_service.py)保留旧compiled Skill扫描与运行语义，不能直接复用为新业务方法的执行路径；[旧能力检索](../../src/services/capability_search_service.py)的Skill集合返回空，不能把Finance CC原生Skill选择与旧检索入口混称为已统一。
- [用户候选存储](../../src/services/skill_candidate_store_service.py)已保存owner和private visibility，但新候选的active pointer为0；公开分享与激活闭环仍待实现。当前Hub没有按用户合并私有active方法的能力。
- [前端调用映射](../../frontend/src/api.ts)仍会排除非public Skill；支持private时需消费后端已授权的可调用目录，同时保留执行端的授权校验，不能只修改界面过滤。
- 本研报包仍在实验目录，不在当前系统业务catalog中。新增本设计要求不等于已经注册、发布或可通过`$`调用。

正式接入最小验收覆盖：系统版自然问题选中与`$`显式使用；private本人可见可用、其他用户不能读取；public可被其他授权用户发现和使用但不能修改原件；三入口解析到相同active版本；References与父Skill版本和权限一致；未启用candidate不进入普通可调用目录。目录命中与方法执行效果分别留证。

### 构造、使用与优化体验

构造：从本草案或实际问答出发，用自然语言提出分析偏好。首屏展示用途、几个典型问题及示例结果，完整方法和Reference按需展开。

使用：用户直接提问；复杂任务可简短显示“正在对齐机构预期”“核对涨价传导依据”等动态进度。方法选择由任务语义驱动，用户无须先勾选子方法。

结果：事实问题优先简短答案；对比问题展示机构差异；变化问题展示时间线；传导问题展示证据支持的链条。首屏关注结论和限制，来源/样本与过程可展开查看。复用 Surface/Renderer，初期允许自然语言和表格表达，不要求新 Renderer 或固定输出 Schema。

优化：用户在结果上指出问题后，关联到当时的报告证据与方法版本，提出局部修订并比较前后结果。数据缺失、确定性Tool错误或权限问题回到相应层处理；方法优化聚焦实际有用的特殊口径、证据判断和表达，并允许删减说明。
