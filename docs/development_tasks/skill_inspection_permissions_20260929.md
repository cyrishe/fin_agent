# Skill 查看、编辑与共享权限（2026-09-29）

本次范围为 Skill Hub 中的 CC-native 金融业务 Skill，含系统内置方法与用户创建的方法。框架内部 authoring/coding 提示包及 legacy compiled bundle 继续由原有入口管理，不由本次编辑 API 改写。

## 权限

| 归属 / 访问者 | 查看用途、选择使用 | 查看完整实现 | 保存与启用版本 |
|---|---|---|---|
| 系统 / 有目录访问权限的用户 | 是 | 是 | 否 |
| 系统 / 管理员 | 是 | 是 | 是 |
| 个人 / 作者 | 是 | 是 | 是 |
| 个人共享 / 其他用户（包括管理员） | 是 | 否 | 否 |
| 个人私有 / 其他用户 | 否 | 否 | 否 |

沿用 `owner` 与 `visibility=private/public`。public 表示开放使用，不再表示公开源码。`viewable`、`editable` 是按当前登录身份推导的响应属性，没有新增权限状态表或角色枚举。角色取服务器会话，不接受请求体提供的角色、owner 或权限。

## 阅读与编辑

- 当前启用版本：完整 SKILL.md、正文中的业务定义/处理方法/数据需求/方法组合、参考文件、随包 interface 配置、版本与内容哈希。
- 注册版本另返回该版本保存的 control_manifest、flowchart、需求及修改证据。正文中的自然语言调用意图保持原样，不把它转换为强制执行 DAG，也不把目录关联当作本轮执行记录。
- 编辑界面提供显示名称、SKILL.md、参考文件新增/删除/修改，以及可折叠的原有结构化关联配置。系统随包工具授权和可执行文件不经此编辑接口变更；这些属于部署及 Agent 授权边界。
- 草稿从原始已保存定义读取，不把运行时追加的关联说明再次写回源正文。
- 保存产生不可变候选版本，显式启用才移动 active 指针。每次保存核对候选修订号及内容哈希；启用继续使用候选/active 双修订比较。冲突返回 409，拒绝静默覆盖。
- 进行中的分析持有原有快照；后续执行构建新快照。界面启用后刷新详情和目录。

接口：

- `GET /api/skill-hub`：目录公开用途 + 当前调用者权限。
- `GET /api/skill-hub/<id>`：可查看者取得完整详情；仅使用者取得目录元信息，不返回正文、references、controls、definition 或 companion_files。
- `GET /api/skill-hub/<id>/references/<path>`：独立校验查看权，不能从详情限制旁路读取。
- `GET /api/skill-hub/<id>/definition`：管理员读取系统编辑版本，作者读取个人编辑版本。
- `PUT /api/skill-hub/<id>/definition`：保存新候选（expected_candidate_revision、expected_content_hash）。
- `POST /api/skill-hub/<id>/definition/activate`：启用候选，沿用双版本校验。

## 存储和系统方法

复用 `aiia_runtime_artifact` / `aiia_runtime_artifact_revision` 的 `skill_v2`，无新表及列。系统源文件仍是内置基线；管理员修改保存为 owner=system 的注册版本。身份在服务端固定，用户正文不能把个人方法升级为系统方法。运行目录允许该归属覆盖相同内置 ID，保留原 category 和工具政策，参考文件则来自已启用修订。审计贡献记录真实编辑者 `authoring_evidence.edited_by`。

多进程从同一注册库读取 active 版本，无需通过写服务器 checkout 同步。未连接注册库的启动时目录仍仅加载内置基线；有身份的请求加载注册版本。数据库不可用时既有回退路径使用内置基线，并在结果中记录版本库不可用，不能当作管理员最新版本执行的证据。

## 实现保密的边界

查看接口、参考接口、编辑接口实施服务端权限；其他用户仍能由受信服务端模型执行共享方法。公开 tracker 不再复制共享正文，原生 SDK 的无归属正文回显也不写入用户结果证据。

**这不构成模型层的强保密边界。** 当前用户对话与方法执行仍使用同一个模型上下文；模型需要看方法，并可能受提示注入诱导复述内部内容。增加执行用途约束有帮助，但不证明绝不会泄露。本次没有把共享方法改造成独立的黑盒执行服务，也没有声称完成提示提取攻击验证。若把“不能看”定义为对恶意提取也有严格保证，需要另做隔离执行及结果出口设计和对抗评测，不能仅隐藏前端或堆叠提示词。
