### 已定位的机制

1. **茅台截断不是 key 问题，也不只是全局8192设置。** `dsh_loop_policy.mjs` 的 Skill 分析请求将实际 maxTokens 设为阶段预算的较大值，本次为3072。最后一轮实际输出3072，其中reasoning2068、正文1004，触发max-tokens。应在阶段预算层分析，不给个股加提示词补丁。
2. **内部错误与外层完成状态脱节。** `FinancialQaCcService.answer` 保留部分文本并把error放在 `financial_qa.error`；Web终态按顶层error收尾，又发“任务已完成”。SSE过程也出现completed重发。因此报告将运行时终态与页面状态分栏，不以done作为成功依据。
3. **第三题不是达到768上限。** native路由记录显示输出111 tokens，供应商finish为stop、Harness为completed，但reason字符串和JSON均未闭合；`_extract_json_object` 确定性拒绝。根因目前定位到上游返回了格式不完整的正常停止文本，无法据此断言供应商为何提前停止。未重跑掩盖此事。
4. **过程显示仍不够明确。** 真正读取Skill及references的记录完整存在，但SSE往往展示为“金融数据处理”；前端不易直接辨认读了哪个方法。Excel运行时步骤保留真实工具名和reference，SSE步骤保留原始展示状态。
