# 金融问答公开溯源与 DSH Opt 增强（2026-09-04）

## 目标

本轮同时解决 Chat 与 Finance REST/MCP 的两个体验问题：

1. 让用户看到实际查询的数据对象、数据类型、业务目标和记录数，但不暴露内部 `subject`、`dataview`、API 名称或调用 DSL。
2. 把“数据口径 / 本步已完成”改为由真实工具调用生成的业务过程，例如“确认股票 · 研报预测指标”“查询股票 · 财务三表与财务指标”。

随后在不改变 CC 执行协议的前提下，继续增强 DSH Opt 的上下文效率和空结果稳定性。

## 架构：SOFT → HARD → SOFT

```text
用户自然语言
  ↓
模型理解并选择内部 catalog 路由（SOFT）
  ↓
内部 subject/dataview/operation、查询 DSL、result_ref（HARD，仅执行与 trace）
  ↓
catalog 同源公开投影：数据对象 + 数据类型 + 查询目标 + 记录数（HARD，公开协议）
  ↓
Chat 过程、数据卡、REST/MCP 返回的场景化表达（SOFT）
```

公开名称保存在唯一 catalog 真源中：subject `_meta.public_name` 与 dataview `public_name`。`FinanceDataToolCatalogService.get_public_data_source()` 是唯一投影入口；Chat、CC/DSH 过程和 REST/MCP 不再各维护一份名称映射。

## 公开返回协议

`FinanceQueryResponse.data_sources[]` 对每个已执行数据目标返回：

- `label`：如“股票 · 研报明细”；
- `data_object`：如“股票”；
- `data_type`：如“研报明细”；
- `description`：来自同一 catalog 的权威数据范围说明；
- `query_goal`：本次执行的业务目标；
- `row_count`：完整结果记录数。

公开 `FinanceResultPage` 不再返回内部 `api`，执行元数据也不再返回内部 `apis`。服务端 trace 和 result registry 仍完整保留内部标识，不影响调试、回放或执行。

Chat 数据卡的 `domain_context.source` 使用相同公开标签；零行结果仍产生证据卡，展示查询目标、公开数据来源和 0 行事实。

## 过程表达

过程事件由真实工具参数和结果生成，不展示模型隐藏思维：

```text
识别查询范围
  已识别查询对象和数据范围，准备处理股票 · 研报预测指标。

确认股票 · 研报预测指标
  已确认可用字段、时间范围和查询口径。

查询股票 · 研报预测指标
  已查询：查询宁德时代 2027 年归母净利润预测，取得 4 条记录。
```

多数据目标使用同阶段编号，例如 `查询股票 · 研报明细 1/2`、`查询股票 · 财务三表与财务指标 2/2`。读取分页明细时显示公开来源与读取字段数，不显示 `result_ref`。

## DSH Opt 增强

本轮使用 DSH 原生 `tools/post-execute` 实现“模型上下文投影”：

- 完整 row-dict、schema、row count 和 `result_ref` 继续由服务端保存并返回给调用方；
- 只对复制到下一次模型请求的长文本样例设置行数、单字段字符数和总字符数预算；
- 一旦发生投影，显式把模型侧 `sample_complete` 标为 false，允许模型仅按所需列调用 `load_finance_result`；
- 数值型、短文本型的小结果保持字节不变，不额外制造明细调用；
- 对不超过 `queryMaxRows` 的小结果，DSH 工具结果直接带齐本轮所需行；长文本仍由同一投影预算约束，因此常见“五日行情”不再为了补两行额外进入分页 loop；
- 明细读取同样有独立且更宽松的模型侧预算，避免研报长文本重新把上下文放大到数万 token。
- 明细工具在 DSH 下会先取得一个仍然有界的较宽窗口，再由模型侧预算保留有序结果的首尾样本；因此升序时间序列不会因为默认分页恰好漏掉最新一期，CC 的默认分页大小不受影响。

模型偶尔会把当前结果名（如 `r1`）传给明细工具，而不是复制完整的内部引用。运行时现会在当前会话 working set 内解析这个稳定结果名，再由原有 result store 执行归属校验；这不放宽跨会话访问，也避免因复制不透明 URI 产生无效调用。

默认参数位于 `resultProjection`：

```json
{
  "enabled": true,
  "queryMaxRows": 5,
  "queryCellMaxChars": 480,
  "queryTotalMaxChars": 6000,
  "detailMaxRows": 10,
  "detailCellMaxChars": 2400,
  "detailTotalMaxChars": 16000
}
```

它只属于 DSH Opt，不改变 CC 看到的工具结果，也不改变 REST/MCP 的完整数据返回。

同时收紧两个通用行为：

- 查询阶段只获取用户明确事实和完成计算不可缺少的依赖，不再自动补一个“解释性比较目标”；
- 零行答案只陈述当前条件没有匹配记录，不允许用模型记忆补写公司背景、披露习惯、可能原因、替代来源或未查询事实。
- 当证据只表明目标字段不存在时，答案只报告数据边界、已查范围和无法给出数值的结论，不搬运同批文本中的无关数字，也不推荐本轮没有执行的数据来源。

由于低推理模型对上述软约束仍可能偶发不服从，所有执行结果均为零行且没有运行错误时，Chat 与 Finance REST/MCP 共用的服务层会采用一个最小、可举证的零行摘要：只返回业务查询目标、0 条记录和无法给出数值的结论。原始零行结果与公开数据来源照常返回，模型生成的背景扩写不会进入正式答案。这是结果事实的严格后置投影，不增加业务分类、关键词分支或新的状态机。

真实多目标回归进一步补齐了两个口径边界：DSH 每轮自然语言输入都会注入 Asia/Shanghai 的系统日期，所有“最近/近 N 月”等相对时间据此计算；财务 catalog 唯一真源明确规定默认 HB 为年初至报告期累计值，多期走势必须保持可比报告频率与 statement_type，禁止把不同季度累计值称为单季值或直接作环比。

## 验证门槛

协议测试覆盖：

- catalog 公开投影及 API pattern 解析；
- REST/MCP output schema 不暴露内部 API；
- summary-only 仍返回数据来源；
- Chat 正常/零行数据卡均显示公开来源；
- DSH 过程标题、业务目标和真实记录数；
- 长研报样例只投影模型副本，原对象与 `result_ref` 不变；
- 紧凑数值结果字节不变；
- 小型完整结果不触发明细 loop，结果名可安全解析为当前会话引用；
- 原有 DSH 阶段、预算、修复、快速模式和并发策略继续通过。

上线后至少回归：单一行情、研报长文本、研报预测指标、财务三表、多数据目标、零行查询六类代表性问题，并同时观察 API 入口、模型请求数、累计上下文、最终回答证据覆盖和公开过程。

本轮服务器实测：RTE005“今世缘估值方法”由旧版约 65.7 秒、累计上下文 110,707、最终上下文 75,990，降至约 16.8 秒、35,906、16,522；模型调用同为 4 次，说明收益来自长文本上下文投影而非减少必要阶段。五日行情由目录、查询、明细三次工具调用降为目录+查询两次；公开 Finance REST/MCP 均返回业务数据来源且不暴露内部 API。

多目标题已能在一次 flow 中规划研报与财务两项查询，并按两个公开数据来源返回。当前剩余效果风险是低推理模型对 catalog 语义规则的服从存在波动：个别运行会为“多期走势”只生成未带时间范围的默认最新一期请求。系统会如实说明证据不足，但本轮没有增加公司名/关键词 validator；后续应通过可配置的阶段业务提示、策略档位和评测反馈继续优化，而不是把单题现象固化到底层协议。
