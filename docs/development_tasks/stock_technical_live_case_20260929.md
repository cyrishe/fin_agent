## 新指标究竟怎样被使用

以下为实际查询的 **2026-09-28 后复权口径**快照。它们用于支持或削弱判断，不单独构成趋势预测。

| 指标或组合 | 实际值 | 此案例中承担的作用 |
|---|---|---|
| MA 与 bias20 | 收盘低于 MA5/10/20；bias20 = −1.68% | 支持当前短期价格位置偏弱 |
| MA60 | 收盘高于 MA60 约 1.87%（复核计算） | 为“中期也已明显转弱”提供反证；仅在均线上方不能证明完整上行结构 |
| MACD、RSI14 | hist = −7.2009，RSI = 46.61 | 补充当前动量状态；单个快照不能证明刚发生交叉或持续恶化 |
| volume_ratio5 | 0.81649 | 当日量约为此前 5 日均量的 82%；需与行情序列结合，不能单独推断资金意图 |
| 布林 %b | 0.06135 | 收盘位于布林区间下部，补充位置判断 |
| atr_ratio14 | 1.53676% | ATR 相对收盘价的尺度，帮助理解价格变化幅度；不是“每日涨跌幅” |
| return20 | −0.87655% | 复权口径的区间收益，避免把除息导致的价格变化全解释为卖压 |

复核了 bias20、MACD hist（本系统 DIF−DEA，不乘 2）、ATR 比例、布林带宽和 %b 的公式一致性；量比还用真实行情的当日量和此前 5 日成交量独立重算，一致。

## 数据覆盖与时效

- 历史行情返回 45 行，2026-07-27 至 2026-09-28；另查询到 2026-09-29 15:30 的最新收盘快照。
- 技术指标只返回 2026-09-28 一行，`formula_revision=technical_daily_v1`、`price_basis=hfq`。这个快照的计算输入有 **2121 根日线**，从 2018-01-02 至 2026-09-28。因此均线等不是用一根行情算出来的；缺的是已保存的逐日指标结果序列。
- 一行快照足以查询最新 MA/RSI/ATR 等状态；不能据此描述过去一个月指标的持续变化、历史分位或交叉时刻。
- 资金流返回 2026-09-29 单日，两融返回 27 日。回答正确说明资金流缺历史，但对指标覆盖范围出现前后不一致。

## 业务复核发现

1. **覆盖范围误报。** 回答开头区分了 9/29 行情和 9/28 指标，结尾却写“行情/技术指标覆盖……45个交易日”。45 行只属于行情；指标只有一行。
2. **ATR 口径错误。** 把 `atr_ratio14=1.54%` 写成“ATR14 1.54%/日”。它是 14 周期平滑真实波幅除以收盘价，不是每日收益率。“波动中性”也缺历史参照。
3. **区间算术不可复现。** 回答列出最高 12.08、最低 11.27，却称未复权振幅约 5.6%，未说明分母。按最高/最低−1计算为 7.19%，无法复现其数字。
4. **部分推断强于证据。** 如“并非抛压”“中期上行结构未破”，不能仅靠除息记录、缩量或位于 MA60 上方确定。应区分观测事实、解释及反证，而不是把可能性写成事实。
5. **调用和输出不够精简。** 一次读取全部 27 个指标；共调用 4 个方法、10 次金融查询，重复确认资金流历史。用户要求不用逐个罗列，回答仍较大篇幅列指标表。
6. **默认执行预算不稳。** 第一轮查询阶段就耗尽 token；第二轮提高测试预算才能完成。不能用重试成功掩盖默认路径失败。第二轮指标查询约 0.31 秒，完整回答约 148 秒，说明此案例首先要检查模型轮次、上下文及取数范围，不能把延迟归因于指标计算。
