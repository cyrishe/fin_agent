# Skill 执行冗余与上下文精简验证（2026-09-29）

本次优先修复确定的数据接口与上下文复用问题，并精简提示词；金融解释质量留待专项迭代。改动在本地完成，未部署或修改生产数据库。

## 修复与职责

1. **数据接口修复**：moneyflow provider 原来收到显式 `tradedate` 过滤后，仍追加“最新交易日”，把日期范围查询错误地收缩到一天。现在日期过滤按其自身范围执行，无日期条件仍默认最新日。stock、plate 共用修复，不新增接口或状态。真实只读查询 `000001.SZ`、`tradedate >= '2026-08-28'` 返回 22 日数据（8/28–9/29），耗时约 0.41 秒。之前观察到的“资金流历史只有一天”应据此修正，不能继续解释成历史数据缺失。
2. **模型上下文复用**：DSH 目录投影仅省略当前模型可见历史中、同 subject/dataview、同目录版本、内容完全一致的字段定义；函数、参数、新字段和变化字段继续完整返回。目录原始值不变，不增加跨会话缓存。历史压缩或版本变化后重新返回完整定义。quote 的 query/window 字段含不同 modes 信息，保留这些差异，未作激进去重。
3. **Skill 正文去重修复**：已有去重逻辑补充 JSON 转义正文的识别，解决多行正文已经在上下文中却未被识别的问题。仅复用完整可见正文。
4. **SOFT 精简**：金融问答 DSH/CC 主提示词、方法选择说明，以及技术结构、相对强弱、资金流三个 Skill 与其 method 参考，共 9 份文本从 9,972 字符降到 4,014 字符（减少 59.7%，不是 token 测量）。共享规约集中说明；保留复权、时间窗口、快照/序列、分单资金与身份区别等特殊口径。角色使用“金融分析师”或“股票分析师”。方法链接作为按需入口，避免被理解成必跑清单。普通数据查询无需空调用 Skill。

已经检查现有独立问题历史隔离逻辑，本次没有证据支持“跨会话污染”结论，也没有再建一套上下文管理系统。K 线相关 Skill 由另一工作会话维护，本次只检查角色与衔接，不覆盖其文件。

## 剩余问题与边界

- 资金面本次一次取得 8/27–9/29 的 23 条资金流，以及 22 条行情和 22 条两融；随后读保存明细，没有再次向 provider 试探同一资金历史范围。
- 技术面仍有一次不必要的重查：首次请求近 30 个已发布指标日期，实际仅一日；模型又更改 as_of/count 查询，仍只有同一日。现有系统没有隐藏结果，属于模型对缺口的处理没有充分收敛。保留 trace，不新增针对个案的硬编码拒绝器；不能宣称反复取数已全部解决。
- 两个用例均只加载一次 Skill；不同窗口的资金合计、首次取数后补公司行为属于新增证据，不按重复调用计算。
- 回答仍有待打磨的金融表述与口径：例如把单点状态描述成“死叉后”、相等低点写为“新低”、不同数据截止日与窗口对齐、比例/单位解释等。两个 completed 仅证明链路完成，**不代表金融结论逐项通过业务审查**。
- 现有证据支持“明确的数据接口缺陷 + 重复上下文 + 部分模型重复取证”这三类原因，不宜统称幻觉，也没有证据把它归因为跨用户上下文混入。
