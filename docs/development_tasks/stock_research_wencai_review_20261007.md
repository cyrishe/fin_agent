## 方法与边界

五题覆盖银行长期逻辑、AI 硬件增长兑现、资源股量价成本、消费龙头渠道变化、日 K 与经营逻辑合并判断。每题在问财的新对话里经已登录的网页 UI 提交一次，查看回答及溯源抽屉；Fin Agent 用真实 `/api/chat/dispatch` 链路各开一段新会话，经过路由、系统 Skill、金融数据查询和模型综合。Fin 侧只替换本地测试身份与会话持久化，不经过浏览器；运行模型为 `BL/deepseek-v4.1-flash`，commit 为 `4b4d7a13d16144a43f3e5a5fb991060bccaa1682`，Skill revision 为 `7dc545259e4098dc4d3960fa23391904c0b38b833d5d03d7b78478482b0951cb`。配置及工作区状态见本地 `outputs/stock_research_wencai_pair_20261007/manifest.json`，期间无源文件改动，五题均完成。完整 Fin 答案、链路、数据快照和统计在同一 `outputs/` 目录，该目录被 Git 忽略，不能当作远端持久证据。

这是非盲评、每题单次运行。问财界面的“思考 6–8 秒”不是同口径端到端耗时；没有独立标准答案的数字只记录为观察，不判定真伪。问财的来源抽屉显示结构化查询表、公告和研报，也混有门户、转载与市场讨论；“溯源数量”不代表来源可信度。Fin 侧每题 172–274 秒，总计约 19.1 分钟串行运行；五题 API `total_tokens` 合计 440,643（内部 `accounting_total_tokens` 是另一统计口径，未用于计费推断）。全部未触及阶段 token 上限，延迟主要在多轮模型推理和扩查，并非预算耗尽。

## 两处数字错误的追因

**Fin 紫金矿业：来源正确，关系在成文时倒置。** 冻结的 `stock.financial_3_table.query` 结果给出 2026H1 经营现金流 55,471,692,934 元，即 554.72 亿元。[检索到的第一财经转载文章](https://finance.sina.com.cn/wm/2026-09-01/doc-iniqipir8085839.shtml)列买矿额约 215.86 亿元，并明确写“经营现金流净额 554.72 亿元，约为其买矿支出的 2.6 倍”。Fin 最终报告却写成“买矿合计约 215.86 亿元，约为同期经营现金流的 2.6 倍”。输入数字没有错，来源关系也清楚；模型把“谁是 2.6 倍”颠倒了。真正的买矿额／OCF = 215.86/554.72 ≈ 0.39。这是一次可定位的生成阶段**关系绑定错误**，不能归因于基础行情或财务表错。另须注意，买矿合计额来自媒体材料，本轮未独立核实公司报告中的全部交易现金流分类；Fin 将其写作“据中报口径”也超过了本轮一手证据的强度。

**问财平安银行：两个返回字段的起点语义没有统一。** 问财的“每日收盘价”表列 2026-08-31 为 11.47、2026-09-30 为 11.57；另一张 `涨跌幅[20260831-20260930]` 表独立返回 1.49%。答复把前者写成 11.47→11.57、紧接着称涨幅 1.49%，没有解释两张表怎样衔接。Fin 侧冻结行情为 8/31 未复权收盘 11.72、9/30 收盘 11.57；公司行为数据为 9/24 除息、每股现金红利 0.249 元。11.72−0.249≈11.47，说明问财的“11.47”高度吻合**前复权**收盘，虽然表头只写“收盘价”。Fin 的复权序列 8/28→9/30 为 1688.1716→1713.3571，恰好上涨约 1.492%；但 8/31→9/30 为 1698.3151→1713.3571，只上涨约 0.886%。因此问财的 1.49% **很可能**是把标记为 8/31 的首个交易日涨跌也计入的区间算法，即实际从前一交易日 8/28 收盘起算；这是数值上的高度吻合，未取得问财该字段的官方公式，不能断言其内部实现。银行板块 1365.13→1391.67 为约 1.94%，所以 `1.49%-1.94%=-0.45pp` 本身没有算错；错误是把不同起点／口径的值当作可直接比较的同一收益率。它更接近**数据目录语义不清 + 模型未核对计算链**，而非凭空编造数字。

## 流程与质量判断

Fin 的总入口确实起作用：五题都加载 `stock-research`；按题目再加载估值、财报、研报、相对强弱和技术结构等子 Skill，平安银行一题的路由尤其符合“技术信号只是经营判断的辅助证据”。中际旭创的现金流反证、平安银行除息调整和茅台的现金流口径提醒，显示现有结构化数据和方法有实质价值。但“最小充分取证、停止扩查”在执行中没有稳定实现：AI 题对并非必要的 K 线工具调用两次且失败，紫金题公开搜索十次；五题模型调用 8–14 次，单题最多 14.4 万 tokens。价格查询有两题出现日期过滤执行错误，虽被补救，仍增加时间。测试未发现预算上限命中。

问财善于把经营变量、相反证据和下次财报验证项放进紧凑表格，来源抽屉还可展开结构化查询表与原始材料标题。这比堆一篇报告更方便快速研究。但本轮答案本身也很长；来源多、精确阈值多，并未防止现金流遗漏、截止日穿越和收益率口径混乱。值得学习的是**证据导航与研究问题组织**，不是直接复制数字、阈值或冗长模板。

## 对现有个股研究线的最小改进次序

1. **先保住关键算术和时点。** 对收益率、相对收益、现金流覆盖倍数等会改变结论的派生数字，优先由现有数据查询／确定性计算产出并连同口径交给表达层；在个股研究 Skill 的最终证据审计中核对分子、分母、窗口、除息与研报发布日期。这里是 SOFT 方法与已有数据工具的配合，不新增全局状态或业务 validator。用本轮紫金、平安银行和中际旭创问题作固定回归样本。
2. **让个股总入口真正收束。** 首轮只取能判断核心命题的经营、反证与必要估值；已有直接证据后停止。若用户未问交易结构且财报已能回答问题，不启用 K 线绘图；外部搜索聚焦缺失的公司经营事实。先复核当前 `stock-research` Skill 的执行轨迹和模型调用内容，再精简提示，不重复写一套硬编排。
3. **补可核实的公司专属事实，不急于加免费接口。** 银行净息差、不良与拨备，矿企产量、单位成本及资本开支，酒企产品／渠道／合同负债，先区分“已有正式报告但未索引或未暴露”和“确实未入库”。优先从已授权的交易所／公司披露材料抽取，保留报告期、公开时间、单位与来源；二手材料只能补背景。
4. **利用已有展示框架。** 前端已有 `AnswerEvidence` 折叠区，可增加正文关键判断到对应表格行／报告段落的轻量定位；首屏保留一句判断、一张少量关键证据表、最强反证与下次验证点，长推导折叠。无需新增协议层、状态机或另一套来源面板。

本轮未改动产品代码或数据库。下一步应先复现并修正上述具体问题，再用相同五题比较准确性、完成时间、token 与读者可定位证据的成本；单次对比不足以支持总体胜率或生产放行。
