# 指标进入现有金融数据工具的方式

日期：2026-09-28。承接[指标体系分类](20_indicator_system.md)。结论：**可查询的数值指标应进入现有`subject → dataview → field → operation`目录**，和指数、行情共用发现、调用校验、Provider执行与结果返回链路。规则事件也是可查询数据，但不应伪装成数值指标；分析方法保留在Skill。无需建立平行的“因子工具系统”。

## 已有链路与当前状态

现有目录由`src/tools/finance_data/catalog/api_view_catalog.json`维护。目录服务按主体与视图展示入口，按选择的方法展开字段说明、参数、调用形式和示例；调用由`call_validator.py`核对API、字段和参数，再由`api_runner.py`分派Provider。结果已有`columns/rows/row_count/evidence`，可由现有结果展示继续使用。`ToolStudioService`也读同一目录。指标无需为每个字段注册一个独立Tool。

| 能力 | 目录视图与查询 | 目前能确认什么 |
|---|---|---|
| 标准日线指标 | `stock.technical.query`、`stock.technical.kd_<field>_<method>`、`stock.technical.agg` | 27项实现字段均在目录；支持明细、多日窗口统计、单日横截面统计 |
| 当前分钟指标 | `stock.technical_minute.query` | 30项字段均在目录；读取已有分钟K按需计算 |
| 分钟逐根指标 | `stock.technical_minute_series.query` | 同一30项及K线时点，适合区间变化/事件解释 |
| 最新报价派生 | `stock.technical_realtime.query` | 8项字段均在目录；依赖当前报价而非分钟历史 |
| 分钟规则事件 | `stock_minute_signals`独立工具 | 6条规则可执行并供任务使用；**尚无金融数据目录的事件视图** |
| 龙虎榜席位 | 候选数据视图 | 表已建；主备采集未完成，不能仅凭表名宣称可查询 |

以上四个指标视图和工具入口指**当前工作区代码**；上一轮隔离测试并未切换生产聊天/API服务。只有源码、目录、Provider和生产加载版本一致，才能对线上可用性作肯定结论。

本轮将日线指标的两种真实运算接入现有统一API，仍只修改`stock.technical`的目录、专属Provider和路由：

| 自然语言需求 | API | 统计范围和结果 |
|---|---|---|
| “茅台最近5个交易日的量比平均值，比今天高还是低？” | `stock.technical.kd_volume_ratio5_avg(codes=["600519.SH"], k=5) -> code, trade_date, value as avg5, current_value, window_count` | 每只股票独立取截至指定`as_of`的最近K个**已发布交易日**；空指标不计入统计，`window_count`说明实际有效值数；`current_value`是末日原值 |
| “今天这批股票量比大于1.5的有多少只？” | `stock.technical.agg(agg=count(stock.technical.code), filter="volume_ratio5 > 1.5") -> stock_count` | 仅截至`as_of`最近一个已发布日的单批次股票；结果证据带实际交易日、批次与样本数 |
| “自选股今天的RSI均值是多少？” | `stock.technical.agg(codes=[...], agg=avg(stock.technical.rsi14)) -> avg_rsi` | 同一日、同公式与后复权口径下的非空值均值；空值不被算成0 |

`query(count=K)`已有历史**明细**，`technical_minute_series.query(since, as_of)`已有盘中**逐根序列**；它们与返回一个统计值的`window`不是一回事。当前分钟指标的`ma20`等本身已在问答时按分钟K窗口算出，直接新增分钟横截面`agg`容易把不同数据截止时刻混成一个“实时”数，所以本轮没有增加。需要跨股票同一时刻的分钟统计时，应先确认共同的已完成bar时点、缺口与时效，再增加独立的分钟方法。指标属于个股`stock`主体，但日线、分钟、快照维持独立dataview；指数和基金仍在自己的subject。撤下技术指标视图及其路由不会改变其他subject/dataview。

目录允许的数学运算不等于每种组合都值得用于研究。`kd_ma20_avg(k=5)`是近5个已发布MA20值的均值，不是重新计算5日收盘价均线；跨股票`avg(ma20)`或`avg(atr14)`也会混合不同绝对价格尺度。通用窗口方法主要用于描述同一股票的指标变化；横截面均值和分布优先用于收益率、量比、偏离率、RSI、相对波动等可比值。业务Skill选择合适的统计目标，目录说明解释其含义；系统不为数学上有效但低风险的业务选择增设拒绝器。

本次核对还发现四个技术指标视图原先把整句“用途/定义”放在`aliases`数组，目录服务会将其当作同义名称。现已改成原生的`desc`字段，真正的同义叫法才进`aliases`。这样模型读到的是明确的字段含义；运行字段与公式无需改变。目录协议测试及27/30/30/8项实现字段的覆盖测试通过。

## 增加一个指标的最小规则

1. **先确定事实身份和计算口径。** 同名指标必须明确证券/主体、日线还是分钟、价格基准、单位、窗口和历史初始化方式。例如后复权日线`ma20`与不复权的当日5分钟`ma20`应属于两个不同视图，不能把数值直接拼在一张图里。
2. **找合适的现有视图。** 同一主体、粒度、来源及调用行为下新增字段；只有这些核心差异使现有操作无法准确表达，或一个视图过大已难以检索时，才按稳定指标族拆分dataview。MA、RSI、ATR等不是各建一个视图或Tool。基金、指数将来有同类因子时，放在相应subject下，不硬塞到`stock`。
3. **目录先写给人和模型看得懂的说明。** 字段键稳定且可寻址；`desc`写定义、用途、单位/比例、特殊边界，`aliases`只写真实同义名称。方法自己的规则写到`query/window/aggregate/compute`方法说明。来源、参数、最小预热及可用时间应足以阻止把供应商值误认为本地重算值。
4. **接通唯一Provider和结果证据。** 正式方法必须有真实可执行的读取或计算；按现有结果形态返回值、数据日期/截止时点、公式或供应商版本、价格口径及必要的不可用原因。NULL保留“未知/预热不足”，不能静默转0；筛选、排序和聚合只对同口径可比值进行。
5. **再发布可发现入口。** 一条自然语言问题可以先在目录选择视图和字段，再按方法生成查询，运行校验后取结果。未接通来源或未验证口径的候选仅留研究清单，不在可调用目录里承诺可用。

公式字段清单以计算模块为准；自然语言用途、别名及调用方式以既有数据目录为准。新增标准字段要用小型契约测试核对两者是否一致，并覆盖正常查询、兼容写法和真正无效的字段/参数。系统只校验可执行的身份、字段、单位/时点等关键条件；低风险业务判断交给Skill和用户反馈。

## 自然语言到返回结果：三种典型路径

| 提问 | 目录选择与执行 | 应展示的关键证据 |
|---|---|---|
| “茅台的20日均线是多少，与今日股价比呢？” | `stock.technical.query`取`ma20`，如需真实价格再取同口径行情 | 交易日、后复权口径和对比价格口径；否则只报告指标值，不做错误价差 |
| “今天5分钟的MACD有没有由负转正？” | `stock.technical_minute_series.query`逐根取`session_macd_hist`，或直接用信号工具检查规则 | 当日递归口径、K线时间、数据截止时间、缺口/预热；不称为跨日MACD |
| “过去一个月ROE改善且估值不高的股票？” | 财务视图与估值视图分别读取，并按已披露时点和同一股票范围组合筛选 | 财报披露日期、估值日期、字段单位及样本覆盖；解释交给研究Skill |

模型选择“哪项指标适合这个问题”属于SOFT；目录提供准确候选及调用说明。视图名、字段名、证券身份、时间口径和返回证据属于稳定衔接。普通使用者只需看到名称、含义、数值、时点、来源和不可用原因，不必看内部API字符串。

## 目前尚有两处缺口

- **规则事件的统一发现。** 现有`stock_minute_signals`可用，但独立于金融数据目录。若希望用户像查行情一样查“曾发生的穿越”，可在`stock`下增加一个事件dataview，使用同一信号服务作为读取端；返回一行一个事件、发生K线时间与实际发现时间。已有定时工具继续负责有归属的持续检查，不复制公式或再建一套规则引擎。
- **自然语言准确率尚未端到端证明。** 目录调用和字段协议测试通过，只证明接口可发现和可执行；还需用固定问题集核查领域选择、口径选择、字段命中、空值解释与结果展示。应包含“量比”歧义、复权价格比较、当日与跨日MACD、停牌/缺口及财报披露时间等真实问题。错误时优先改`desc`、示例或Skill说明，不向系统校验器堆关键词规则。

以后每一批新指标按“来源已可用 → 口径与公式确认 → 合适视图与Provider → 目录描述 → 协议/业务样例 → 自然语言评测”推进。这样指标数量增长时，用户仍通过同一数据工具查找、查询和复核，而不是记住越来越多零散Tool名称。
