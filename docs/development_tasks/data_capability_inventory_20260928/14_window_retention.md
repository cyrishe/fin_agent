# 计算窗口、保留边界与首期实现

2026-09-28。本篇落实用户关于窗口保留和开始开发的确认。新增的是业务公式与无I/O的归档候选选择函数，不新增业务状态、模型Output Schema或通用因子框架。收费竞价仍暂停。后续日线入库和分钟计算的实际进度、输入证据存储容量见[15 实施回执](15_implementation_receipt.md)；自动归档与删除尚未启用。

## 1. 不存在覆盖全部指标的一个“最大N天”

必须区分：一个指标首次有值需要多少bar、准确重算依赖多少历史、要展示多少个结果，以及历史结果/证据要保存多久。这里的“天”均指该证券的有效日线bar，不能按自然日减日期代替。缺失值不填0，也不自行跨缺口拼出完整窗口。

| 范围/类型 | 单个最新值需要的输入 | 多个历史结果/限制 |
|---|---|---|
| MA5/10/20/60 | 5/10/20/60根 | N期均线的D个连续输出要N+D−1根 |
| 1/5/20期收益 | 2/6/21根端点跨度 | 保留缺失，不前向填充 |
| 此前5/20期均量、量比 | 6/21根（含当前） | 基线不含当前，不能误用含当日量均线 |
| 此前20/60期最高收盘 | 21/61根 | 首批有限窗口项的最大值是**61根** |
| BOLL20 | 20根 | 完整窗口，总体标准差；常数价格百分位无有效分母 |
| 20期年化波动 | 21根价格 | 得到20个相邻简单收益，样本标准差×√252 |
| MACD12/26/9 | DIF首次26根，DEA/柱首次34根 | EMA递归，没有保证完全等价的固定截断窗口 |
| RSI14 / ATR14 | 首次15根 | 首值需14次变化/TR；之后Wilder递归，不能每天只取15根重新种子化 |
| 上游CCI84 | 84根 | 原仓库较长的普通指标窗口之一，尚未接入 |
| 上游MA250策略 | 当前均线250根；最近60个MA250完整结果要**309根** | 原仓库不足窗口填0的行为不引入新标准 |
| 上游筹码估计 | 默认210根/时点 | 120个完整时点理论需329根；还要核对上游切片和初始化，未接入 |
| OBV、SAR及其他递归/累积指标 | 依赖历史起点或前一计算状态 | 不能套用最大显式period；未接入 |
| 用户自定义长窗口、历史回测 | 随真实需求增加 | 按需读历史/异步计算，不声称固定320根支持所有需求 |

例如首批有限窗口项显示最近60个结果，需要120根；显示252个结果，需要312根。未来MA250显示252个结果需要501根。**320根可作为常见扩展场景的取数余量，但不是全系统统一保留上限，也不新复制一张320日行情表。**

复核源码：固定版本InStock的`instock/core/indicator/calculate_indicator.py`、`strategy/backtrace_ma250.py`、`kline/cyq.py`；DSA的`src/stock_analyzer.py`。InStock的`threshold`主要控制输出长度，`calc_threshold`才可能截断计算输入，不能把默认threshold=120当成所有指标只依赖120根。

递归函数会随输入起点变化；最小lookback不等于完全消除初始化影响。参见[TA-Lib数值稳定性](https://ta-lib.org/api/#42-numerical-stability)、[pandas递归加权定义](https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.ewm.html)。本地v1锁定下列公式，不声称与所有TA-Lib/行情软件初始化逐值相同。

## 2. 采用的保留设计

| 对象 | 当前决定 | 到期处理/不能做的事 |
|---|---|---|
| 既有原始日线、财务、分钟历史 | 保持既有事实库；读取时按依赖截取 | 不因为MA60只需60根就删除行情历史 |
| 有限窗口计算的内存输入 | N+D−1；一只股票/分块计算后释放 | 不为一次展示复制全市场长期工作表 |
| 递归指标输入 | 首期从固定历史起点读取后计算，显示长度只在算完后裁剪 | 不用滚动300/320根代替固定起点；首期函数没有持久化增量检查点 |
| 标准日线指标热结果 | 建议最近**252个已发布交易日期**，按股票范围/价格口径分别处理 | 更早结果先归档，核验读回和引用，再决定移出热表；不直接丢失历史可查询性 |
| 报告/研究/待完成任务引用的旧日期 | 优先保护 | 首版保守地保护该日期所有修订；不因到期清掉引用结果和证据 |
| 分钟即时指标 | 按输入版本短缓存，更新使旧缓存失效 | 缓存淘汰不代表可删除分钟事实；订阅历史另按业务保留 |
| 输入证据文件 | 固定公式、起点、复权口径、输入指纹及可重放内容 | 不能仅留哈希就删除唯一可重放输入；不每天无条件重复保存全部长窗口 |

252是首期在线历史服务范围建议，不是所有公式共同需要252根。按6,000只计算，热结果约151.2万行/有效版本；27个DOUBLE数值本体约327MB，按上一版工程预算含必要键/索引约0.76–1.51GB，待隔离库实测。归档后总数据并未凭空消失，只是减少热库规模。引用保护、保留版本和多个价格口径会额外增加行数。

若后续希望热表控制在百万行以内，120日约72万行，但年度历史查询必须从归档读取；这属于服务范围与访问成本选择，不改公式窗口。本轮采用252日候选规则，没有执行任何清理。

### 递归如何兼顾长期准确和速度

首期先提供可重算的完整历史实现作为基准。P2百股试跑分别量取完整历史读数和CPU成本；达到预算后再接全市场。若完整历史初始化太慢，将相同公式的EMA快/慢/信号值、RSI平均涨跌、ATR、前收、截止时间、公式修订和来源绑定保存到现有运行资产的检查点，后续只续算新增bar；有限窗口部分另保留最近60根即可。

这些是递归计算必需的业务中间量，不是新增生命周期状态。**检查点落地前不能启用递归输入截断清理。** 补数/价格复权修正若早于检查点，须从受影响位置前的有效检查点或固定起点重算；不能只拿最新一天补算。检查点准确接续、缺值预热与旧源修正测试属于后续P2，不把尚未完成的优化称为已上线。

固定起点由系统数据源适配器确定并写入批次证据，不能按用户问“30天还是60天”改变。源历史向前扩展或口径变更构成新的计算输入/发布修订；旧报告继续引用原证据。发生缺值时，本地v1从缺值之后重新积累该递归函数完整种子，不伪装跨缺口连续计算。

## 3. 已实现的27项公式

代码：`src/services/technical_indicator_calculator.py`。原`price_volume_v1`的11项函数保持兼容；新包`technical_daily_v1`有27列，数据库草案列名同步。

| 输出 | v1口径 |
|---|---|
| MA、端点收益、前期均量、量比、BIAS | 沿用第一包完整窗口口径 |
| `prior_close_high20/60`、`prior_close_low20`、`distance_prior_high20` | 历史最高/低均排除当前；距离为当前收盘/此前20期高点−1 |
| `macd_dif/dea/hist` | 快12、慢26分别以各自第一段SMA为种子，再α=2/(N+1)递推；DIF从第26根开始；DEA取前9个DIF均值为种子；柱=DIF−DEA，不乘2 |
| `rsi14` | 首14个涨跌的平均值为种子，随后α=1/14；100×平均涨/(平均涨+平均跌)；全平为50、纯涨为100、纯跌为0 |
| `atr14/atr_ratio14` | TR=max(高−低,abs(高−前收),abs(低−前收))，第一根没有TR；14个TR均值种子后α=1/14；相对ATR=ATR/收盘 |
| BOLL中/上/下轨、宽度、%B | 20期MA，标准差ddof=0，上下2σ；宽度=(上−下)/中；%B=(收盘−下)/(上−下)，零带宽时%B为空 |
| `volatility20` | 20个简单收益的样本标准差ddof=1×√252；需要21根价格 |

同口径高低收必须满足高≥收≥低。未知/未预热/零分母输出NaN（落库应转NULL），不填0；零成交量是有效值。每个输出最小首次可用bar数为`TECHNICAL_MIN_BARS`，系统用于可执行窗口规划，不重复建第二套业务用途目录。

已提供的调用：

- `required_technical_input_bars(indicators, output_bars=...)`：有限窗口返回精确根数；含递归项返回None，要求固定起点。
- `calculate_standard_technical_features(bars)`：计算完整已限定as-of的输入序列。
- `calculate_standard_technical_window(bars, as_of=..., output_bars=..., indicators=...)`：先截as-of，有限项缩小输入，递归项保持传入起点，最后裁展示结果。函数不替调用者补取历史或判断市场停牌。
- `technical_result_archive_dates(...)`：按去重后的已发布交易日期和引用保护生成候选日期；无DB连接、无删除动作。调用方必须提供完整引用集合，不能把“没读取引用”当“没有引用”。

仅调用已经通过测试的业务计算函数，不更改模型Output Schema、金融目录operation或旧MA工具。目录/数据库作业贯通仍属于P2。

## 4. 本轮验证与下一步

自动化验证覆盖每项首值位置、手算Wilder及独立权重展开的EMA参考、BOLL/波动、预热/空值/零分母、价格缩放、输入不变、未来数据不影响过去、同as-of不同展示长度一致、有限窗口截取与完整历史一致、引用保护和非交易日间隔。

两测试文件合计**41 passed**。CPU样本为串行100次单股调用、每次输出完整27列：300根/次共1.64秒（单次p95约17.7ms），3000根/次共3.82秒（单次p95约45.3ms）。使用同一合成样本重复，未含数据库读取、写入、输入文件或并发用户；只能衡量本实现的计算开销，不是全市场生产SLA。证据绑定当前代码哈希及环境：[technical_window_validation.json](../evidence/data_capability_inventory_20260928/technical_window_validation.json)。DDL列与27个输出逐项核对一致；尚未在MySQL执行DDL。

本轮完成：27项纯计算、取数窗口函数、归档候选函数及DDL草案扩列。下一包P2完成固定起点的源适配、100–200股试跑、发布读写、旧MA位置/消费者核验、隔离MySQL月年容量与归档读回，再进入生产迁移。当前没有数据库清理任务、历史归档写入、增量检查点或公开目录注册，不能把候选逻辑称为已运行的保留系统。
