# 分钟与实时指标：计算方式及第二批实施

2026-09-28。采用 **原始行情按既有计划更新入库，衍生指标按需计算并缓存**。本轮实现属于业务公式与数据适配；周期完成状态、时点、计算起点和时效参数属于必要的查询事实；用途与解释仍在现有数据目录。没有新增分钟指标历史表或全市场分钟指标定时任务。

后续关于用户观察任务每30分钟执行的调研见[17 半小时区间检查](17_half_hour_scan_research.md)：建议保留按需查询，并为定时任务补充完整区间检查；这是待实施建议，不能仅对本页最新值接口降低调用频率就承诺不遗漏区间事件。

## 为什么这样执行

| 数据/计算 | 运行方式 | 保存方式 |
|---|---|---|
| 日线27项指标 | 保持盘后全市场统一计算 | 公共批次与结果宽表，用户共享 |
| 原始1分钟K | 保持stock_agent既有约10分钟分批采集 | 既有分钟事实库 |
| 分钟30项指标 | 请求指定股票和周期时，从当日1分钟事实计算；最多20只/次 | 每进程最多128份输入内容缓存，不存分钟指标历史 |
| 实时快照8项指标 | 按需读取现有stockHq批量行情，再计算 | 最新原始快照使用5秒文件缓存，Fin Agent同机进程共享；不保存指标历史 |
| 用户的定时分析/监控 | 由既有用户任务调用相同入口 | 沿用任务运行结果与报告证据；本轮没有新建个人监控任务 |

与日线不同，分钟查询通常只涉及几只股票，计算本身很便宜。每分钟将6,000只股票写一行，单一周期即约144万行/交易日、3,024万行/21个交易日；当前使用量没有支持这项存储成本的实际需求。需要留存的报告或监控结论由现有任务结果保存，原始行情继续留在事实库。

同一份输入可以服务多个用户。分钟缓存键包含实际时间序列内容，补数、修订、新分钟都会产生新输入；数据时效每次重新计算，缓存命中不会把旧时点改成“现在”。不同交易日或周期不会混用结果。跨进程重复计算少量分钟指标的成本很小，目前不再引入分布式计算缓存。

## 分钟查询完成的逻辑

入口 `stock.technical_minute.query`，版本 `technical_minute_session_v2`。底层读取当日完整1分钟K，在内存聚合1/3/5/10/15/30/60分钟周期，不另抓一份各周期行情。

在原有20项固定窗口指标基础上新增10项：

- `session_macd_dif/dea/hist`：当日趋势动量，首次DIF需26根，DEA与柱需34根。
- `session_rsi14`：当日方向强度，首次15根。
- `session_atr14/atr_ratio14`：当日绝对/相对波动，首次15根。
- `session_vwap`：已采集区间成交额/成交股数；用于观察价格相对成交均价的位置。
- `session_volume_shares/session_amount`：当日已采集区间累计量额，缺区间则为空。
- `session_return_from_open`：当前周期收盘价相对当日首个区间开盘价的收益率。

**session_ 递归指标每天从09:30起算，遇缺口重新预热，不是跨日标准MACD/RSI/ATR。** 当前5分钟日内最多48根，MA60为空；60分钟周期每天4根，当日递归指标自然无法完成预热。跨日递归应在分钟历史读取及复权衔接完成后单独提供，不能用随热表滚动的历史起点冒充同一公式。

默认只计算完整周期。`include_partial=True` 可用当前周期已经到达的连续1分钟前缀试算：例如10:38:30查询5分钟，实际输入截止10:38，周期计划结束于10:40，`is_finalized=False`。未来分钟排除，周期内部缺口不拼接，上一周期缺失也不前向填充。分钟成交量从手转换为股。

返回实际数据时点、应有时点、延迟、计划周期结束时刻、是否完成、起点和缺口数。可选 `max_lag_seconds`：超过要求时保留时间证据，将指标置空并说明原因；省略时允许读取延迟参考值。

```text
r1 = stock.technical_minute.query(codes=["600519.SH"], period=5, include_partial=True, max_lag_seconds=120) -> code, data_as_of, lag_seconds, is_finalized, ma20, session_rsi14, session_vwap, unavailable_reason
```

## 实时快照查询完成的逻辑

入口 `stock.technical_realtime.query`，版本 `technical_snapshot_v1`。复用现有 `realtime_quote_provider.load_realtime_rows` 和stockHq数据源，没有引入开源免费接口。

8项指标：相对昨收收益、开盘后收益、开盘跳空、日内振幅、距日内最高的回撤、距最低的反弹、日内高低区间位置、相对供应商均价的偏离。单位均为比例；成交额、成交量不被用来伪造最新1分钟K线。

每次最多20只，缓存缺失的股票合成一批请求。共享文件锁合并同机进程的重复读取，最新快照缓存5秒；新增指标入口每个共享缓存目录最多30批请求/滚动分钟，失败请求也计数。缓存坏损时不会重置预算继续请求，接口失败不替换成旧分钟价。此预算只约束本次新增入口，**不声称已有stock_agent或其他旧行情入口也受同一个预算控制**。

`max_lag_seconds` 默认60秒。来源时点过旧、交易日不符、位于请求完成时刻之后或价格明显不成立时，返回空指标及原因。午休按11:30比较，盘后/休市日按最近交易日收盘时点评估。盘前竞价不在该入口的计算范围内。

```text
r1 = stock.technical_realtime.query(codes=["600519.SH","000001.SZ"]) -> code, data_as_of, lag_seconds, return_from_open, drawdown_from_high, range_position, unavailable_reason
```

## “实时算”与“实时数据”的边界

计算在请求到来时立即执行，但分钟输入仍受既有分批采集时效约束。新增实时快照入口能够直接取最新行情，**不能据此声称分钟MACD等已经拥有最新分钟历史**。如果用户要求最新分钟指标，查询需指定可接受延迟；超过时效会明确不可用。将分钟补取纳入stock_agent统一预算仍是采集端的后续工作，不能在Fin Agent另开无限制单股K线请求来绕过压力控制。

快照指标、完整分钟指标和未完成周期试算各有独立语义；用途、公式口径和例子均已加入现有数据目录。判断哪一种适合用户的问题由现有Skill与模型完成，系统不增加关键词路由。

## 验证与部署

已部署服务器上的计算模块和命令行，未修改stock_agent采集频率、数据库结构或日更调度。部署前版本保存于服务器 `data/stock_indicator_artifacts/ops/before-intraday-v2-20260928.tar.gz`。线上常驻聊天/API的新目录入口仍待成组发布，计算模块与CLI已经可用。

```bash
.venv/bin/python scripts/stock_indicator_daily.py minute --codes 600519.SH,000001.SZ --period 5 --include-partial --max-lag-seconds 120
.venv/bin/python scripts/stock_indicator_daily.py realtime --codes 600519.SH,000001.SZ --max-lag-seconds 60
```

验证结果：

- 服务器业务计算回归 **68项通过**；本地扩展回归 **153项通过、1项既有失败**。失败为 `test_realtime_quote_provider.py::test_query_alias_is_not_registered_and_navigation_shows_real_entry`，其研报目录旧断言在HEAD原始目录下同样失败，未改动该测试。
- 3股×3周期×20旧指标，共 **180个数值与上一版一致**；新增VWAP均处于对应日内高低价区间内。
- 真实库历史10:38:30试算正确截止10:38，未使用其后分钟；覆盖当日预热、缺口、无成交分母、修订失效、过期/未来行情、午休和盘后等测试。
- 测试包括两个独立Python进程共享缓存只发出一次源请求，以及失败占预算、超额拒绝新增请求。
- 服务端3股分钟查询约 **0.08–0.23秒**；实时快照首取约 **0.15秒**，随后相同请求约 **0.024秒**，第二次外部请求数为0。
- 这些是盘后联调和固定历史时刻验证，不代表交易高峰压力、长期稳定性或实时SLA已经验收。

证据：[服务器运行与源码哈希](../evidence/data_capability_inventory_20260928/intraday_v2_server.json)、[本地实际数据查询](../evidence/data_capability_inventory_20260928/intraday_v2_live_local.json)。证据仅记录数量、时点、耗时及校验结果，不保存股票数值明细。
