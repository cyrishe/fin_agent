# 基础输入核验：现有数据能支持哪些计算

2026-09-28；核验时间约北京时间14:41。范围为当前工作区配置指向的 `kingdomai` 数据库、现有 Provider 和两个固定版本上游仓库。采用有超时的只读查询；未采集新数据、调用上游免费行情接口、写入数据库或修改业务代码。运行记录只保存字段定义、时间、计数和缺失统计，不保存行情/财报原始值、连接地址或凭据。

后续补充：用户指出采集任务在stock_agent，本轮已核对其10分钟分批更新、同轮统一截止实现。下面分钟样本的时点差可以由分批提交解释，不能单凭差异判断上游异常。来源保障与刷新节奏应分开评估；详见[09 分钟刷新与事件来源](09_minute_refresh_and_event_sources.md)。

**结论：首批27个日线数值与3条规则所需的基础字段已有，且本轮取得实际数据证据，可以基于现有数据继续做公式实现与验收，不需要引入两个仓库的数据抓取器。整个上游功能集合的输入尚不齐全，盘中数据的来源保障、特殊供应商字段和全市场历史质量也不能据此判定已就绪。**

用户确定的来源约束：免费公共行情接口和网页抓取不作为本次融合的生产依赖或补数后备。可吸收开源计算代码、分析方法、展示方式；数据统一由现有受控数据入口提供。缺口优先核对已有供应商，仍缺则缩小功能范围，确有需求再另行接入有明确服务保障的数据源。

### 已确认的单位和复权口径

数据库字段注释给出的定义为：

- `volume`：股；`amount`：元；`turn_ratio`：百分数（%）。
- `adjopen/adjhigh/adjlow/adjclose/adjpreclose`：**后复权**开高低收及昨收。
- 普通 `open/high/low/close/preclose`：未标复权的价格列。

因此，不能直接搬上游前复权行情默认参数，也不能把成交量当成“手”或将换手百分数直接当0–1比例使用。指标计算使用一致价格序列；面向用户展示的实际价位需要明确价格口径。字段注释证明供应库的声明，历史除权日的数值正确性仍需后续固定样本验收。

源码：[quote_provider.py](../../../src/experiments/staged_data_protocol/phase2/quote_provider.py:38)。该Provider直接读现有表，没有因接入这些公式而新增AkShare等数据依赖。

## 3. 扩大到两个仓库全部能力时，哪些仍缺或有条件

| 能力 | 基础输入/现有情况 | 本次融合处理 |
|---|---|---|
| 更多日线技术指标、61种K线形态 | 主要仍是OHLCV；现有日线输入可复用 | 按需求选公式并验证，不必为每个指标找新数据源 |
| 筹码分布估计CYQ | OHLC及换手序列已有；本轮13字段包含turn_ratio | 无需抓取东方财富筹码接口；可做本地估计，但先统一换手单位、价格区间、复权/股本变化。输出是模型估计，不能当真实持仓成本 |
| 成长/质量/估值分析 | 三表、财务指标、估值表已有，核心样本可用 | 优先复用；行业不适用与数据缺失要区别。历史研究仍需披露/修订时点验证 |
| 分红/股东/解禁/质押/预告 | 现有corporate Provider和相应表覆盖多类事实 | 分领域做样本验收，不将“表存在”写成“全部公司事件齐全” |
| 主力资金与大单结构 | 现有moneyflow主力买卖/净额已抽样 | 保留原供应商划分定义；不能凭主力净额复刻DDX、DDY等专有字段 |
| 分钟趋势、盘中突破 | 有已存分钟OHLCV，但上游来源及更新一致性须确认 | 放在后续范围；显示真实数据时点，先证明可满足所需刷新频率 |
| 盘中同时间成交活跃度 | 需要足够多历史交易日同分钟/同累计区间的量，不只是最新240条 | 本轮未证明20日等完整历史覆盖；暂不承诺该指标就绪 |
| 龙虎榜席位、大宗成交、专门竞价明细、逐笔/Level-2 | 当前Provider未发现对应可调用入口；当前数据库相关表名/注释检索也未发现候选 | 记为“尚无已确认输入”，不补免费抓取器；相关规则先不启用。不能仅凭名称搜索断言其他系统绝对没有这些数据 |
| 东方财富平台人气、DDX/DDY/DDZ、专有热度/选股标签 | 上游是供应商返回值；OHLCV无法恢复专有观察范围/算法 | 不按同名自造数值。可明确另命名一个自有可解释指标，但不能宣称等价 |
| 新闻/公告/研报和事件归因 | `stock.news`走SearchGateway，默认实现为内部ES；另有public web/站点模式和独立新浪入口 | 本轮未验证全文、研报预测及事件覆盖。沿用已核实入口；不搬DSA搜索源作为自动后备 |
| 历史选股/因子评价 | 不仅要价格，还需要历史可交易股票池、退市/停牌、当时已披露数据、修订历史、交易成本等 | 本轮不确认point-in-time回测输入完整；不能用“日线已齐”推出回测可信 |
| 港美股、ETF、指数、板块 | 有些已有独立来源，但字段有差别，例如部分source显式NULL | 本次实测限于上述A股样本与stock表；不外推其他市场和资产 |

检索元数据：[source_gap_metadata_results.json](../evidence/data_capability_inventory_20260928/source_gap_metadata_results.json)。检索范围为当前库 `kcrp_`/`aiia_` 表名与注释中的相关关键词，未读这些未知表的业务内容；零匹配的证据强度仅限该检索。

### “目录有名字”不等于能直接取到数值

现有映射中可见真实例子：

- `financial.revenue_growth` 映射为 `NULL`。可基于已有财报或专门同比计算能力获取增长，不能读这个占位字段就当零增长。
- `pricevalue.dividend_yield` 映射为 `NULL`。若要自算，须确认现金分红窗口、实施状态、价格和单位，而不是仅因存在dividend表便判为已交付。
- `moneyflow.total_net` 等字段映射为 `NULL`；抽样成功的是主力资金相关字段，不代表整张目录所有列都通过。

源码：[financial_provider.py](../../../src/experiments/staged_data_protocol/phase2/financial_provider.py:111)、[pricevalue_provider.py](../../../src/experiments/staged_data_protocol/phase2/pricevalue_provider.py:58)、[moneyflow_provider.py](../../../src/experiments/staged_data_protocol/phase2/moneyflow_provider.py:65)。这些是当前能力边界，本轮未擅自修改其契约。

## 4. 已有实时依赖需要单独说明

当前代码实际路由：

- `stock.quote(mode=0)`：现有日线数据库。
- `stock.quote(mode=1)`：`aiia_stock_realtime_minute_snapshot`；本轮1分钟来源标记为 `upchina_kline_1m`，5分钟为 `derived_upchina_1m`。
- `stock.quote(mode=2)`：直接请求外部 `stockHq`；代码端点为 `http://jzyzwup.upoem1.com/json/hq_basichq/stockHq`。价格来自接口，数据库主要提供证券范围。

源码：[api_runner.py](../../../src/experiments/staged_data_protocol/phase2/api_runner.py:159)、[realtime_quote_provider.py](../../../src/experiments/staged_data_protocol/phase2/realtime_quote_provider.py:25)、[intraday_quote_provider.py](../../../src/experiments/staged_data_protocol/phase2/intraday_quote_provider.py:619)。

这是已有依赖，不是本次引入。代码和表中source标签不能证明其免费、收费、是否采购过、是否有服务保障；本轮也没有调用它补数据。日线库的底层采购/更新保障同样需要数据维护方的现有约定作为依据，不能从“内部数据库”推导出上游SLA。

依用户要求，本次方案只承诺复用经确认的数据；盘中扩展须先厘清已有供应关系、可用频率与稳定性证据。若现有保障不足，保留日线能力，并评估受控供应商；不增加多路免费抓取和静默兜底。

## 5. 对实施计划的实际调整

1. **首批可推进**：基于现有日线输入实现27项及3规则；公式、用途说明和Skill方法来自开源参考，计算与证据进入已有数据体系。
2. **不需要新增数据接口**：首批以及后续多数日线形态/技术指标。开放源代码计算库与不稳定公共取数接口分别对待。
3. **有条件扩展**：筹码估计、分钟指标、事件/财务细分字段；分别补单位/算法验证、上游与历史覆盖验证、领域样本核验。
4. **暂不接入**：无已确认来源的专有热度、DDX、龙虎榜/竞价等依赖；保留上游清单作参考，不登记为已可执行金融能力。
5. **仍需验收**：目标股票池历史覆盖与异常行情、除权样本、输入修订、盘后更新、全量取数计算落库耗时。此前CPU基准继续有效，但运行容量仍为 `NOT_READY`，本次数据样本审计不改变该结论。

自然语言仍可驱动已具备输入的能力。遇到缺口，Skill说明实际可回答范围和缺少的证据；系统沿用既有结果状态、来源和时点，不为这些目录说明新增一套协议状态或业务validator。
