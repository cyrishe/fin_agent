# Fin Agent 指标体系：分类、计算与使用

日期：2026-09-28。本篇是[全盘清单](README.md)的使用入口，按现有实现核对日线、分钟与快照指标。它描述如何整理目录和调用能力，不引入新数据库表、新协议状态或另一套因子注册中心。仓库中出现过的字段不自动算作已接入指标。

## 先区分六种对象

| 对象 | 例子 | 在系统中的位置 | 用户能问什么 |
|---|---|---|---|
| 基础事实 | 日/分钟OHLCV、财报原文数值、公告、龙虎榜披露及席位 | 原有行情、财务、公告表；已建龙虎榜表的采集仍待落地 | “发生了什么，数据到几点？” |
| 供应商派生值 | 源接口给出的估值、资金流、热度或标签 | 保留供应商口径、来源与时点；不能默认视作本地公式 | “供应商的这个值是多少？” |
| 本地可复算指标 | MA20、量能比、ATR/价格、财务同比 | 唯一公式实现；数值按使用规模决定盘后入库或按需算 | “数值及变化如何，公式是什么？” |
| 规则事件 | MA20上穿、连续三根站稳、披露触发条件 | 规则版本和参数；真正发生/发现的事件另存证据 | “哪根K线触发，何时发现，后来是否失效？” |
| 分析方法与结论 | 成长质量、事件传导、技术结构、估值比较 | 现有Skill选择证据并解释；结论及反证在任务/报告资产 | “这些证据一起意味着什么？” |
| 后验评价 | 信号后5日收益、预测误差、策略成本 | 评测与复盘数据，必须以当时可得输入回放 | “这种方法历史上是否有效？” |

这是**对象层级**，不能用“技术因子”一个名称装下六层。例如龙虎榜席位是披露事实，净买入额是派生数值，“机构主导”则是需要口径的判断。新闻热度即使是数值，也要先确认供应商样本和计算口径。

## 再按业务领域找指标族

| 领域 | 指标族与典型用途 | 当前接入判断 |
|---|---|---|
| 行情与量价 | 价格、收益、成交量额、换手、VWAP；回答价格与交易活跃度 | 日/分钟事实和相应标准指标已有实现 |
| 趋势与动量 | MA、BIAS、前高低、MACD、RSI；观察方向、突破及变化 | 日线和当日分钟计算已有实现；分钟不代表跨日标准MACD |
| 波动与风险尺度 | ATR/价格、布林带宽、历史波动率、回撤；比较波动和风险幅度 | 日线已算；分钟只计算适合当前口径的部分 |
| 市场参与与结构 | 资金流、两融、板块广度、龙虎榜席位；观察参与者和市场范围 | 部分已有查询；龙虎榜表已建，采集与核验尚未完成 |
| 公司经营与质量 | 收入、利润、现金流、ROE、负债和增长；判断经营变化 | 沿用财务三表及现有派生方法，注意披露时点 |
| 估值与预期 | PE/PB/PS、历史分位、预测盈利、研报修正；比较价格与预期 | 现有估值、研报和预测指标目录；供应商预测不当成实际值 |
| 股权、分红与公司事件 | 股东、股本、分红、质押、解禁、业绩预告、公告；解释事件和权利变化 | 各自沿用已有视图；口径与披露时间逐项核对 |
| 新闻、主题与关注 | 新闻、热度、主题关联；解释关注点及验证主题证据 | 现有搜索和主题能力；平台热度不当成全市场情绪 |
| 组合与方法评价 | 权重、成本、暴露、回撤、信号后验；用户风险和方法复盘 | 私有用户范围与评测资产，不并入公共股票指标宽表 |

一个指标可服务多种问题；业务领域是发现入口，不要求每个领域一张表、一个Skill或一个模型分类器。技术指标是整个体系的一部分，并不覆盖财务、预期、事件或组合研究。[来源与领域的完整盘点](README.md#2-全盘分类技术只是其中一部分)保留在原清单。

## 同一指标还需标注计算方式

这与业务领域是**另一条轴**，不应把“实时”误当成某种因子类别。

| 更新形态 | 典型对象 | 计算/保存方式 | 关键边界 |
|---|---|---|---|
| 盘后公共批次 | 27项标准日线技术指标 | 同一批次、每股一行写`aiia_stock_indicator_daily_batch`和`aiia_stock_indicator_daily`；用户共享 | 保留公式修订、输入指纹、价格口径与已发布批次；当前日更已运行 |
| 分钟事实持续采集 | 已完成1分钟K | stock_agent按10分钟节奏分批更新原始分钟表 | 抓取批次不等于每股同一时刻可见；保留实际K线时间 |
| 分钟指标按需计算 | 当前值/区间的30项分钟字段 | 只读已有分钟K；短缓存；不建全市场分钟指标长表 | 当日锚定、周期预热与缺口决定哪些值可用 |
| 最新快照按需计算 | 8项开盘、振幅、位置等比例指标 | 复用已有实时报价入口与短缓存 | 当前报价不是完整分钟K，不能拼出历史MACD |
| 已启用范围的规则检查 | 6条分钟事件规则 | 由现有定时任务或用户提问逐根检查；任务事件保存发现与修订证据 | 只有需要及时发现的任务才自动执行；发现不等于通知送达 |
| 披露更新 | 财报、公告、龙虎榜 | 依据披露/修订时间采集和入库，派生计算按需或在披露后共享 | 龙虎榜采集未完成；收费竞价数据继续暂停 |
| 用户特定研究 | 自定义阈值、股票池、组合条件和说明 | 按用户任务计算，结果进原有任务/报告资产 | 未经验证的用户参数不批量灌入公共宽表 |

现有 **27项日线、30项分钟、8项快照**是三个输出集合，不是65个互不重复的独立公式；MA等在日线和分钟复用概念，但价格口径、历史锚点及时间粒度不同。另有6条分钟**规则**，不能计入数值指标总数。详细公式和预热根数见[窗口口径](14_window_retention.md)，分钟规则见[实施说明](19_minute_signal_implementation.md)。

## 每个可用指标在目录里应能回答的问题

在现有`subject/dataview/field`目录上保留这些内容即可，不另建元数据表：

1. **它是什么、能做什么**：名称/别名、所属指标族、1—3个典型用途和不宜推出的结论。用途是自然语言说明，不做繁琐的机器枚举。
2. **数值如何解释**：单位、比例约定、价格复权口径、时间粒度、公式/供应商定义、参数及最小预热。例：`volume_ratio5`是当前K量/前5根平均量，不是供应商“量比”。
3. **值从何而来**：对应来源视图或公式修订、输入日期/指纹、数据截止时间、缺口与修订。使用时返回证据，不要求模型重复生成系统已经持有的事实。
4. **如何取得**：目录的`query/window/aggregate/compute`操作与示例；公共盘后读表，分钟读已采集K按需算，事件按规则检查。

数值字段沿用原数据视图的稳定路径。例如`stock.technical.query -> ma20`表示日线标准结果，`stock.technical_minute_series.query -> ma20`表示当日选定分钟周期的逐根值。二者名字相同但不能在图表或筛选里不带口径混用。规则走`stock_minute_signals`；分析方法走现有Skill。机器稳定承载证券、时点、来源、单位/口径、公式版本和输入引用；用途说明与选择理由保留在目录、Skill及结果解释中。

## 自然语言怎样用起来

2026-09-29补充：用户编写Skill时，只需描述技术面、因子分析等业务目标和约束，不必指定指标。Skill编写方法保留这个开放目标；执行时由专业方法结合当前走势，渐进选择证据。字段精确定义继续由数据目录维护，取证选择与解释由`technical-structure-analysis`和`factor-analysis`维护。

先复用已有的走势与量价背景，选取能区分主要解释的少量指标族，再判断是否存在值得继续查的变化。价值来自“对当前问题有什么影响”，不来自“数值最大”或“看起来最特别”。自身历史、可比对象、持续性和与其他证据的冲突可以使某项变化值得重点解释；正常值也能排除一种解释。没有新信息时允许停止，不全量扫描直到找到异常，不设全局统一的异常分或因子评分表。

现有日线query可取历史指标序列，kd可提供有效值均值/中位数/极值，agg可描述同一日股票集合；这些能力足以支持基础比较，但还没有技术指标历史分位或统计显著性的专用方法。不得仅凭当前值或min/max冒充历史分位。指标“少见”、对当前结构“有解释价值”、对未来“有预测能力”分别需要相应证据；最后一项需进一步回放与样本外检验。

K线协作边界（2026-09-29再次核对）：`kline-analysis`、`kline-basic-reading`、`relative-strength-analysis`已加入业务Skill目录；此前“尚未注册”的描述已过时。注册方法不等于所有形态扫描与视觉能力已经接通，执行以当前实际授权工具为准。确定性形态识别由Tool承接，方法选择和解读由Skill承接；共用证券、周期、复权、截止时点和已有结果引用。形态不成立或无法确认时停止该形态解读，同源形态和指标不重复算作独立确认。当前不修改或接管该会话的实验实现。

指标不归某一个Skill独占：用户可直接查询，也可通过自定义Skill或专业分析方法使用同一套数据。编写时保留目标，执行时根据行情选证据，完整职责与流程见[指标、专业方法与用户Skill的使用流程](21_skill_indicator_usage_flow.md)。

新增[合成场景评测](../../../tests/evals/technical_evidence_adaptive_v1.json)覆盖相同问题的正常/异常对照、无历史参照、形态未成立、盘中延迟及跨股价格尺度。现有`scripts/eval_finance_skill_methods.py`预加载方法并传入冻结证据，可验证解释和后续取证意图；不能用这类结果宣称已验证真实查询选路或自动指标发现。

两轮真实模型测试已保留[逐项人工复核](../evidence/technical_evidence_adaptive_20260929_r2/review.md)：可观察到解释重点随证据改变，但仍有资金意图、未提供走势和指标含义的错误，尚未通过整体业务验收。最终方法文字的冲突清理晚于第二轮快照，未重新运行模型；不得将接口回归或方法文件已更新等同于自主分析效果已验证。

用户说“找出经营改善、估值还不高，而且最近成交量活跃的股票”时，Agent先确定股票范围和时间，再分别取财务增长/质量、估值与量能指标。日线量能可以读公共批次，财务数据按实际披露日取，估值使用同一可比时点；筛选结果带关键数值和证据，再由研究Skill解释条件为何成立及可能反证。无需造一个“综合好股票”单列因子。

用户说“今天14:00到14:30这只股票5分钟线上穿又跌回了吗”，读逐根区间指标或信号工具，返回两次事件对应的K线时刻、数据时点和当前条件。只问“现在在MA20上方吗”则读当前值，避免调度一整天的监控。

用户说“持续观察这20只股票，出现连续三根站上MA20时告诉我”，先把股票、周期、阈值和时效落实到已有任务协议，再按新数据检查完整区间并记录真实发现。是否向用户发消息、何时发以及是否收费属于单独的订阅/交付配置，不能从一次条件命中自动推断。

现有[15个业务Skill的归属](README.md#8-skill-数量与吸收方式)已经够做首批方法承接。指标目录负责找数和解释口径，Skill负责选证据、组合分析与表达，任务系统负责持续运行和用户归属。下一步的维护重点是核对所有已接入字段的用途、口径与状态，并把尚未接入的候选与可调用指标明确区分；无需先为每个因子建立独立服务。
