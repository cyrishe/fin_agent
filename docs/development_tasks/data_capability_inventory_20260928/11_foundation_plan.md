# 数据底座设计与分批开发计划

2026-09-28。用户已授权按基础依赖逐步开发和测试；收费竞价暂停。设计依据为本目录01–10的源码、只读数据核验和用户最新的简化主备要求。本篇是后续实施入口；旧篇记录研究过程，涉及运行方式的差异以本篇为准。

## 1. 结论与成熟度

需要必要的数据库设计，但无需重建行情库、财务库、任务系统或金融数据目录。当前足以确定数据粒度、来源边界、计算复用方式和渐进迁移路线，支持先做日线与龙虎榜；不能把分钟接口容量、归档查询性能、历史时点可得性或生产运行验收称为已完成。

本篇以下保留设计基线；实际实施状态以[15 实施回执](15_implementation_receipt.md)为准。现已完成四表创建、日线公共计算和定时作业、分钟固定窗口按需计算；目录接入代码与生产运行激活分开记录。后续各包完成测试后分别接入，不一次性搬两个仓库。窗口与保留规则以[14](14_window_retention.md)为准。

**MA与容量补查修订**：见[13 MA复用与容量](13_ma_reuse_and_capacity.md)。旧MA源码采用`aiia_indicator_series`长表，但当前连接库未发现该表，实际部署/迁移状态尚未核实。标准宽表包含MA并逐步承接同口径的旧查询，避免长期保留两套重复计算；不能将前述基础核验理解为已核验旧MA生产运行。

## 3. 必须先定下来的基础口径

| 事项 | 首期决定 | 为何需要现在明确 |
|---|---|---|
| 证券身份 | 完整证券代码，例`000001.SZ`；适配现有分钟六位码，不能丢交易所 | 六位码不能作为跨资产全局身份 |
| 数据粒度 | 事实、衍生数值、规则、研究正文分别保存；日线按证券/日期/计算修订定位 | 避免把供应商标签或模型结论当事实 |
| 价格口径 | 日线标准技术结果优先采用现有后复权OHLC，明确标记`hfq`；真实价位展示读取不复权行情 | 均线绝对价格与展示价格必须匹配，不能将后复权均线直接画在原始K线价格轴 |
| 分钟价格 | 先用同一来源不复权分钟窗口；跨除权日的分钟收益/均线须有权息衔接再启用 | 日线后复权和分钟原价不能机械拼接 |
| 单位 | 输入价格元、成交量股、金额元；本地比率字段用小数，0.1代表10% | 外部万元/手/%在适配层转换；已有对外字段不静默改单位 |
| 时间 | 交易日期/交易bar用Asia/Shanghai语义；作业、抓取、发布时间用UTC | 数据发生时间不等于系统看到它的时间 |
| 窗口 | 指标以有效bar计数，不自行填停牌日；核实漏数与停牌约定；预热不足为NULL | 避免把缺数、零成交和无信号混在一起 |
| 完成/临时值 | 日线盘后完成值可预计算；当前分钟/日线临时值按输入时点返回 | 不能把十分钟批次数据称为此刻状态 |
| 修订 | 公式修订和输入指纹参与结果定位；已发布标准批次不可原地改值 | 旧报告和正在读取的截面不能被重算静默改变 |
| 历史可得性 | 财报使用披露时间；后验收益只进评估；未保存历史修订不能宣称PIT回测 | 最新源表回填历史不等于当时已知事实 |
| 空值 | 未知、未成熟、无有效分母保持NULL；0是有效数值 | 既有部分工具把空值转0，新的计算入口不能沿用该转换 |

实际接口与指标用途说明由目录和Skill承载。系统只保存必需的证券、时点、修订、输入引用与权限事实，不要求模型重抄这些字段，不大改Output Schema。

### 公式不静默替换

现有`StockQuoteTool._compute_tech_indicators`使用不足窗口的均值、简单滚动RSI、首价EMA和未乘2的MACD柱。新标准函数使用完整窗口；因此先发布独立修订，旧图表继续原口径，后续显式迁移。不能仅因名称相同就认为与TA-Lib或上游逐值一致。

第一包`price_volume_v1`已经实现：MA5/10/20/60，1/5/20期端点收益，此前5/20期均量、当前量/此前5期均量、MA20乖离率，共11项。均量排除当前bar；收益为`close[t]/close[t-n]-1`；均线包含当前bar且需完整窗口。输入缺值不前向填充；端点收益只需要两个端点，不虚构期间路径。

第二包已加入前20/60期最高收盘、前20期最低收盘、相对前20期高点幅度，共4项。前高低排除当前bar。

第三包12项已实现：MACD三项、RSI14、ATR14及相对ATR、BOLL五项、20期年化波动。`technical_daily_v1`锁定独立SMA种子的EMA、Wilder种子的RSI/ATR、`DIF-DEA`柱值、总体标准差的2倍BOLL，以及简单收益样本标准差×√252；详见[14的公式与测试](14_window_retention.md)。相同as-of的离线/在线计算必须取相同初始化历史，禁止根据显示条数改变EMA结果。尚未实现持久化递归检查点，首期保留固定历史起点。

三条首期规则的业务默认值：放量上涨为`return1 > 0`且`volume_ratio5 >= 1.5`；均线排列为`ma5 > ma10 > ma20 > ma60`；严格前高突破为当前同口径收盘价大于此前20期最高收盘价，相等不算突破。1.5是可修改的业务参数，保存时绑定规则修订；依赖值为NULL时保留无法判断，不当作已验证的未命中。规则放在业务计算/方法层，不进入系统通用validator。

## 4. 数据库草案与读写行为

完整草案：[12_foundation_schema_draft.sql](12_foundation_schema_draft.sql)。它是显式迁移草案，没有执行，也没有通过真实MySQL DDL测试。

### 4.1 标准技术结果：批次表 + 日线宽表

这是既有MA能力的演进，不是长期再建一套并行MA系统。旧表源码、当前库缺表事实、兼容切换和容量核算详见[13](13_ma_reuse_and_capacity.md)。当前27项不按MA/RSI/MACD分别建表。

- `aiia_stock_technical_batch`保存股票范围标识`universe_key`、交易日、公式修订、价格口径、源名称、输入清单引用、请求/写入数量、开始和发布时间。全市场公共范围与百股试跑使用不同标识；完整成员清单在输入证据中保存，不让最近一次百股批次覆盖全市场查询。用户临时自选分析走按需计算，不发布到全市场范围。
- `aiia_stock_technical_daily`每个批次、每只股票一行。草案已补齐27个可空数值列，原11项函数仍兼容。主键`(batch_id, stk_code)`；历史查询有`(stk_code, batch_id)`索引，交易日期由批次表唯一持有。
- 不为每个因子建表，也不将要参与SQL筛选/排序的标准数值全塞JSON；不同自定义参数的长尾结果留在已有运行资产，避免一开始做无限参数仓库。

写入流程：固定日期和股票范围→分块读取并计算→写未发布批次→记录范围、缺口及处理完成情况→最后一次提交`published_at`。分块取数使用有界的一致性只读事务或已固定的输入文件，取完即释放源库事务；不能仅凭一个最大update_time就假定各块来自同一快照。查询只选择一个已发布批次，不将今天半批与昨天半批混成全市场截面。股票预热不足可写NULL；缺失/无效输入在清单里说明，`written_count`不冒充全市场覆盖。全部没有有效输入时不发布空批次。

`published_at`是唯一新增的发布事实，不引入“待抓取/计算中/待审核/可见”等状态枚举；作业状态仍归已有run。读取须匹配范围、日期、公式修订和价格口径，不能仅找最后发布的一条记录。失败重试复用同一未发布批次ID，主键写入幂等；已发布批次只读。重算使用新批次，旧批次保留给已有结果引用。回滚通过读取旧批次和停用新入口完成，不需要删表或覆盖原数据。

全市场当前截面只约6000行，先不为27个因子分别加索引；按实际查询计划验证必要索引。6000只×21交易日，日线宽表每月约12.6万行，批次表约21行；同样27项放旧式长表则每月340.2万行。日频27个float64、6000只、252日的数值本体约0.327GB/年，不含键、版本、证据与索引；长期每分钟保存同样数据约78.4GB/年，因此分钟结果默认短缓存。

相同范围、日期、公式及输入复用既有结果，用户读取不新建公共批次；真正修正才保留新版本。输入证据、日志/备份另计；若每天复制全市场300根窗口，输入文件可能比指标表更大，P2必须分别计量。暂不按月拆物理表，也不假定当前有外键且日期只在批次表的DDL能直接日期分区。先在隔离MySQL验证月/年数据量、查询计划及并发读写。

热结果暂按252个已发布交易日期规划（6,000只约151.2万行/版本），更早结果先归档核验读回，引用日期额外保护；保留不是直接删除。有限公式按N+D−1取数，首批最大单点61根；递归项依赖固定起点/有效检查点，不套用统一300日删除规则。候选函数已实现，归档读写及生产清理尚未接入；原始行情与被引用证据保持独立生命周期。

### 4.2 龙虎榜：披露与席位分别保存

- `aiia_stock_lhb_event`一条披露对应证券、日期、原因和统计区间；`period_start`没有可靠来源时可空，不猜单日。`reason_key`由供应商原因标识/原文等稳定输入生成摘要，避免长文字作为索引；保留原始原因，不建立复杂跨源原因本体。
- `aiia_stock_lhb_seat`主键为`(event_id, side, rank_no)`。同名机构可以有多行；供应商席位编号作为来源字段，不作为跨源全局身份。买/卖金额用DECIMAL且统一元，未知列保留NULL。
- **取数与替换单位是“证券+披露日期”的完整包，包含所有原因和买卖榜。东财正常用东财，失效才用新浪。** 备用源完整包检查通过后，在同一事务替换该证券当天的披露和席位，避免旧原因残留或拼出两源混合榜；事务失败保持旧包。实现时先收集全包，再删除其旧席位/披露、插入新包；不要边抓边删。
- 基本检查仅覆盖日期/证券/原因、必要字段、金额单位、方向和明显重复。完全重复明细不重复计数，不能用名称合并“机构专用”；异常数据不据此生成完整榜单净额。不新增双源日常比对、评分或仲裁。

这里保存的是当前有效披露，报告证据用既有结果快照/来源响应引用留存；不能用可被替换的event_id冒充不可变历史证据。若将来要求龙虎榜严格PIT研究，再基于已保留的原始响应补版本读取，不假设当前表天然提供所有历史修订。

### 4.3 输入指纹、可复算与证据保存

指纹包含实际参与计算的有序字段、时点、价格口径；同一末端时间但历史bar被修正时必须产生新指纹。批次输入清单同时记录股票范围、来源、公式修订、窗口和各分块引用。

**哈希只能辨别输入变化，不能还原输入。** 要保证某次报告/计算精确重放，必须保存其实际输入窗口或可取回的供应商快照；源表`update_time`不是历史版本仓。实现盘后作业时保存分块输入证据及清单，利用已有文件/运行资产机制；不把整个市场多年行情复制进报告，也不扩大现有FileArtifact的2万行/50MB上限。分块大小按字节和行数控制，清单引用多个块。输入保留期和物理存储容量在首次百股试跑中计量，所引用证据不能被临时缓存清理规则删除。

DB字段/运行引用是系统持有事实，模型只消费所需预览和用途说明。历史PIT能力按实际证据覆盖声明，而非因为加了`as_of`字段就默认成立。

## 5. 不同计算维度如何共用底层

| 维度 | 输入依赖 | 计算/保存 | 开发包 |
|---|---|---|---|
| 单股时间序列 | 日期有序的同口径日线/分钟窗口 | 同一确定性函数；日线标准批次，分钟按需缓存 | P1–P4 |
| 全市场横截面 | 同交易日、同修订、同价格口径的发布批次 | SQL筛选/排序；返回覆盖范围，禁止逐股不同最新日拼接 | P2 |
| 行业/板块统计 | 上述数值 + 当时成分与聚合口径 | 优先已有aggregate，初期按需；没有历史成分就只声明当前成员比较 | P6 |
| 同刻量能 | 分钟归档 + 日历 + 同一盘中截止时刻 | 历史基线盘后算，当前累计量按需更新 | P4后半 |
| 财务增长/质量 | 报告期、披露日、财务事实与修订 | 复用已有财务窗口方法，按披露更新；空占位字段不能当已支持 | P6 |
| 龙虎榜席位 | 完整披露包、统计期、买卖榜和来源 | 盘后公共入库，按需查询/聚合；多原因不能重复累计 | P3 |
| 条件信号 | 已定义指标 + 参数 | 3条规则按需/订阅运行，保存所用修订与证据 | P2/P5 |
| 筹码估计/61种形态 | 更长历史、换手率及各公式约定 | 后续逐族验算；较重计算对订阅并集去重 | P7 |
| 私有组合/研究 | 公共事实 + 用户持仓/偏好/材料 | 公共数值共享，私有结果留在owner任务 | P5/P6 |

实时路径：用户需求→现有Skill选数据→统一入口判断时点→库/缓存足够则复用，不足则受限额补取尾段→同一计算函数→已有结果与Renderer。股票持续监控才需要后台主动刷新；收费竞价不属于这一轮路径。

分钟按需补取的限流与落库由stock_agent现有采集职责承接；Fin Agent发起有界需求并读取统一结果。跨项目部署前确认两进程服务边界，不能在两个Python进程各放一个局部限流器就声称共享供应商总额度。优先一个采集端持有预算，用现有服务入口扩展有界补取；若没有可复用入口，再确定最小本地/HTTP适配方式，避免直接复制采集器。分钟包上线前必须完成此项接口决策和协议测试，日线包不依赖它。

## 7. 每个指标如何保留用途

实现中的字段名/修订与现有目录一一对应；目录desc、rules、examples记录用途、单位和特殊窗口口径，方法参考留在现有Skill，不再做一份可漂移的可用能力注册表。

| 第一包字段 | 用途 | 必须展示/说明的口径 |
|---|---|---|
| ma5/10/20/60 | 趋势层次、均线排列、回踩参考 | 价格口径和完整窗口 |
| return1/5/20 | 短中期动量、跨股比较 | 端点价格收益，不是完整投资总回报 |
| prior_volume_mean5/20 | 历史量能基线 | 排除当日；交易量股数，除权/股本事件可能影响可比性 |
| volume_ratio5 | 相对近期成交活跃程度 | 当前量/此前5期均量；盘中半日量不能称完整日量比 |
| bias20 | 偏离均线的程度 | 比率小数，无固定涨跌结论 |

五个最终验收场景：①自选股趋势与量能解释；②全市场波动收窄且放量筛选；③此刻是否突破的按需补取；④昨天机构席位参与情况；⑤收入/现金流改善与估值、事件的组合研究。每个场景都记录所用事实、计算结果、时点与来源，并检验追问改变窗口后是否重新选择正确输入。

## 8. 可调整与不可混淆的边界

可调整：增加可空指标列、参数包、刷新频率、缓存保留期、实测后加索引、Skill文案与展示。供应商可以在适配层替换。

必须保持：证券身份、事实粒度、单位/复权、发生与可得时间区分、匿名席位身份边界、已发布结果不可悄悄改写、公共与私有隔离。遵守这些边界能显著减少原则性返工，但不能承诺未来没有迁移。

尚未关闭的实施事项已经落到具体包：旧MA部署核验、固定起点源适配、递归检查点（性能需要时）、隔离MySQL迁移/发布事务和归档读回→P2；完整龙虎榜包解析→P3；分钟全局预算入口及归档索引→P4；历史PIT只按证据覆盖逐步开放。这些不需要现在扩建通用框架。
