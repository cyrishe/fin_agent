# 分钟区间与信号任务落地

日期：2026-09-28。本文更新18的实施状态。代码已在两个本地项目实现；候选代码在现有服务器隔离目录完成100股回放及MySQL临时表测试。**本轮没有替换生产文件、重启线上进程、创建真实用户监控或发送通知。** 服务器验证不是线上部署回执。

## 已实现的执行方式

| 需求 | 实际入口 | 执行与保存 |
|---|---|---|
| 当前趋势、量能、VWAP | `stock.technical_minute.query` | 按需读取已有分钟K；保持原接口兼容 |
| 查看一段时间的指标变化 | `stock.technical_minute_series.query` | 从开盘计算，再裁取since之后的逐根结果；最多20股×240根，不写指标历史表 |
| 查看期间曾发生什么 | `stock_minute_signals`普通调用 | 逐根检查启用规则，返回事件及当前条件；0新增供应商请求 |
| 持续信号观察 | 现有定时任务中的`stock_minute_signals`工具步骤 | 仅任务股票、周期和规则；持久化发现与修订证据，已有任务表保存运行结果 |
| 自然语言解释/报告 | 现有问答、Skill或任务后续步骤 | 按实际场景消费上述事实；公式计算和信号检查本身不调用模型 |

较及时的任务可按10分钟节奏检查，普通观察报告可每30分钟。任务扫描当日全部已到达的完整K线，公式以输入内容复用。这样迟到的旧K线、同一时间戳的修正和短暂条件变化都能被检查；首期不建立复杂的增量游标状态机。记录`processed_data_as_of`是实际已取得的末尾时点，不代表之前没有缺口，也不用于跳过旧数据。

相同输入的公式序列在进程内共享LRU缓存；同机进程之间通过5秒文件缓存和锁共享分钟原始数据读取，缓存上限512个股票日文件。缓存保留原始时间，不把命中时间当作行情时间。5秒是合并并发读取的短窗口，100股1分钟全规则任务首次耗时超过5秒时，第二次运行仍可能重新读库。

## 首批规则与用途

| 规则 | 用途 | 触发口径 |
|---|---|---|
| `ma20_cross_up` / `ma20_cross_down` | 价格与均线关系发生变化、往返穿越复盘 | 相邻完整K线收盘与MA20差值跨越0 |
| `ma20_hold_above` | 减少把单根短暂站上视为持续站稳 | 首次满足连续N根收盘高于MA20，默认3根 |
| `session_macd_cross_up` / `session_macd_cross_down` | 当日动量方向变化 | 当日起算DIF−DEA跨越0；不冒充跨日MACD |
| `volume_expansion` | 找出量能扩张区段 | 当前量/前5根均量大于阈值，默认1.5；每段首次观测记录一次 |

缺失K线不补值、不跨缺口判断相邻穿越，连续确认遇缺口重置。第一根可计算的MACD/MA值本身不构成穿越。量能扩张是“区段首次观测”，不是承诺精确知道真实起涨时刻。信号不等同于收益有效性或买卖建议。

**执行间隔不是指标周期。** 每30分钟执行仍可看1分钟或5分钟K。现阶段只计算当日：5分钟MA20首值在11:10、MACD信号线首值在13:50；更早时相应条件不可用。10分钟及更大周期一天不足34根，session MACD信号线不可用。标准跨日分钟指标需要另行明确跨日连续输入和递归起点。

## 自然语言使用示例

- “今天10:00到10:30，这只股票的1分钟收盘有没有上穿MA20，随后又跌回？”——用1分钟规则检查整个区间，分别给出事件时间和当前条件。
- “每半小时检查我的这20只股票，看看5分钟K是否连续三根站在MA20上方。”——确认股票范围后使用现有定时任务，定时步骤直接调用工具；按需求另接报告步骤。
- “现在量能是否比前五根明显放大？数据到几点？”——按需计算，展示量能阈值、实际数据截止时间和延迟；没有新数据时不会强拉供应商。

工具输入示例：

```json
{"codes":["600519.SH"],"period":5,"rules":["ma20_cross_up","ma20_cross_down","ma20_hold_above"],"confirm_bars":3}
```

定时任务使用相同输入，省略`as_of`和`since`；这些只用于临时历史回放。可选择交易时段检查并包含15:10或更晚的收盘补扫，以覆盖最后一轮分批落库。节假日任务不将前一交易日事件记为当日新事件。现有cron为单表达式时可用宽一点的工作日时间范围，午间重复检查由缓存及事件去重处理；无需扩张调度协议。

命令行临时验证：

```bash
.venv/bin/python scripts/stock_indicator_daily.py signals \
  --codes 600519.SH --period 5 --rules ma20_cross_up,ma20_hold_above
.venv/bin/python scripts/stock_indicator_daily.py minute-window \
  --codes 600519.SH --period 1 --as-of 2026-09-28T10:30:00+08:00 \
  --since 2026-09-28T10:00:00+08:00
```

## 保存与恢复边界

无需DDL。日线两张指标表维持原设计；分钟指标不按分钟落长表。

`data/stock_indicator_artifacts/minute_signals/<scope-hash>/<trade-date>.json`保存每个任务、步骤、股票集合、规则参数和公式版本的当日事件。scope包含系统提供的用户归属，不接受工具普通参数伪造。`event_id`由股票、周期、规则、事件时间、参数与版本确定；首次发现时间与事件K线时间分开。

再次发现已有事件不进入`new_events`；证据变化、撤销或恢复进入`corrections`，旧观测保留在修订记录中。缺口导致暂时无法判断时不直接撤销旧事件。同一任务重试最后一次run返回原结果；不同任务/用户各有自己的发现记录。`events`含已经记录但后来失效的事件，消费方须查看`invalidated_at`；不应把全量事件再次当作本轮新提醒。

文件锁与原子替换覆盖同机并发；未实现多主机共享事件存储。每天只检查当日，**停机跨日后不会自动补跑所有遗漏交易日**；可对仍保留输入的日期显式回放，但发现时间仍是实际回放时刻。发现记录不等于通知送达记录，也没有宣称通知exactly-once。事件资产暂沿用任务证据留存，不自动删除审计历史；原始数据缓存可自动淘汰。

## stock_agent采集减压

继续10分钟分批采集、每股20根重叠窗口、12个工作线程、每批1000股。新增`--requests-per-second`平滑各线程的请求启动，包括重试；等待超过本批截止时间不再开始请求。正值限速替代固定批间等待，避免两种等待叠加。命令行省略该参数保留旧行为；启动脚本与默认运行配置的候选值为25次/秒、批间等待0，脚本支持`MINUTE_REQUESTS_PER_SECOND`覆盖。25是依据既有耗时估算的候选值，**不是供应商确认的配额，也未做真实上游压测**。

源K与派生K继续使用原事务和聚合SQL，确保补数据、修正、缺失派生修复和结束状态正常更新。仅让未变市场事实的重复upsert成为no-op：`fetch_time`在市场字段改变时更新，不再仅因重复读到相同值而改写。因此它表示该行当前内容入库的抓取时间；采集是否持续运行看已有批次日志，行情新鲜度仍看实际K线时间。没有省略聚合查询，**不能把no-op写入优化宣称为已经减少相同比例的数据库计算或API总量**。现有Fin数据状态页按snapshot_time判断新鲜度，其arrival字段仍代表当前行内容的入库时间。

这次不改变供应商、采集覆盖范围或10分钟间隔，也不接通严格最新分钟K补取。后者仍需采集侧统一请求额度后再接。

## 验证与上线边界

服务器隔离候选代码使用Python3.10.12、现有kingdomai的当日100股数据（99股各有240根完整1分钟K），开启全部6条规则：

| 场景 | 首次检查 | 同输入再次检查 |
|---|---:|---:|
| 100股、1分钟K、当日全区间 | 9.8006秒 | 5.3751秒 |
| 100股、5分钟K、当日全区间 | 4.8122秒 | 1.3695秒 |

上游新增请求0。5分钟样本1301条条件事件，重复执行新增0；这个计数只用于覆盖和去重验证，不用于声称信号质量。源K不变、源K修正、派生K不变、迟到补齐与finalized更新的MySQL语义均用合成数据和会话临时表验证，没有写永久行情表。

证据：[minute_v3_server.json](../evidence/data_capability_inventory_20260928/minute_v3_server.json)、[probe_minute_v3.py](../evidence/data_capability_inventory_20260928/probe_minute_v3.py)。证据含候选源码哈希、环境和workload；它只证明有界盘后回放与上述SQL语义，不能替代盘中高并发、采集限额或生产长稳验证。

Fin本轮专项与相关回归149项通过、2项按既有条件跳过；stock_agent采集测试17项通过。详细结果见[minute_v3_local_tests.json](../evidence/data_capability_inventory_20260928/minute_v3_local_tests.json)。额外尝试旧快照模块测试时，当前本地环境缺`akshare`导致收集失败，未把它计为通过。仓库其他未完成变更未纳入本轮上线包。

上线时需同步本轮相关代码、工具定义及目录，按已有人工发布Gate切换API/任务worker和采集进程，再查看一个完整盘中周期的覆盖、超时、落库时点和实际请求速率。未指定用户/平台股票范围前，不默认新建全市场信号任务。
