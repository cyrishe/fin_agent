# 紫金矿业个股研究：DSH 调度 Skill 的单题实验

日期：2026-10-07。问题取自 `tests/evals/stock_research_wencai_pair_20261007.json` 的 `resource`：截至 2026-09-30，区分紫金矿业金铜产销量、价格、成本、资本开支对利润和现金流的影响，并判断最值得跟踪的变量。实验代码见 `scripts/eval_stock_research_dsh_skill_orchestration.py`；生产配置和数据库未改。

## 对照口径

此前同日、同 commit `4b4d7a13d16144a43f3e5a5fb991060bccaa1682` 的完整 Chat API 基线保存在 `outputs/stock_research_wencai_pair_20261007/resource/`，用现有 `stock-research` 加 `earnings-analysis` 方法、实时查询和公开搜索得出答案。其完成耗时 274.0 秒，API 层 `total_tokens` 约 144,111；金融 DSH 内部为 11 次模型调用、138,765 非缓存输入/输出 tokens，另有 248,064 cache-read tokens，26 次金融工具调用。答案把“经营现金流 554.72 亿 / 买矿支出 215.86 亿 ≈ 2.6 倍”倒写成买矿支出为经营现金流的 2.6 倍。

为了只检验执行组织方式，受控组从上述运行的**原始冻结结果**提取同一份 2,034 字符的证据摘要，金额由原表的元确定性换算为亿元；覆盖 2025H1/2026H1 财务三表、金铜锂业务分部、2026-09-30 估值、两份公开材料的短摘及资本开支缺口。单会话组同时读个股研究与业绩分析 Skill；DSH 管理组的主会话读个股研究 Skill，再用 `dsh-subagent-spawn-in-process` 的一次性 `finance_skill_task` 调度业绩分析 Skill，主会话汇总。两组均使用 `BL/deepseek-v4.1-flash`，无金融工具、无网络扩查；因此此处时间和 token **只代表证据已取得之后的分析阶段**，不能与完整 Chat API 的 274 秒或 144,111 tokens 直接相除。

## 事实与业务效果复核

- **确定性关系**：受控单会话和两次管理组均正确表述 554.72/215.86≈2.6 的方向，也都指出投资现金流净额不能直接当资本开支、缺少购建长期资产支付现金分项。旧完整基线错在最终成文关系绑定。由于受控单会话同样改对，不能把这一改善归功于子任务。
- **单会话的错误**：把金铜分部收入增量 295.88 亿除以合并毛利增量 334.64 亿，写作“占毛利增量 88.4%”，跨越了收入与毛利两个不同口径；还用剔除卡莫阿后的铜产量增速推算整个矿山产铜分部的价格变动。证据虽清晰，模型仍能生成口径不成立的比例。
- **未限额管理组的错误**：从“剔除卡莫阿后产量 +5%”推定 2025 年铜销量“51–53 万吨”，冻结证据不支持这个区间；把“金价跌破约 4000 美元/盎司”写成失效条件，证据中也没有该阈值。局部 Skill 分段没有阻止精确数字自生。
- **短预算管理组的错误更重**：写出冻结证据中不存在的 2025H1 锂收入 6.67 亿；把金铜收入增量和合并毛利增量混比；推出未经证据支持的成本/价格敏感性；将 `经营现金流－买矿支出` 称作自由现金流“上限”，而买矿支出与资本开支不是可替代项。结果看起来更精细，事实和会计口径却更弱。
- **表达效果**：三个受控答案都能组织量价、现金流、估值和验证点，且都说明 W1/W2 是二手材料。管理组没有明显增加有依据的业务判断，也没有缩短正文。旧完整基线覆盖更广，因为它额外检索了很多资料；覆盖广度与受控组不可直接比较。

另做过一次**真实 Chat API 探针**：在现有金融 DSH profile 追加通用子任务插件和简短调度说明后运行同题。运行到金融问答阶段约 321.7 秒时仍未收束，金融 MCP 已执行 44 次调用，其中公开搜索 26 次；为避免无效消耗主动中断。该次没有完整答案或完整 token 统计，故不列入上表，也不能仅凭 MCP 轨迹判定搜索由主会话还是子会话发起。它至少证明“挂载工具＋一句调度说明”不是可靠的生产接入方式。

## 结论与下一次实验的边界

DSH 的一次性子任务能力在当前模型和本地 runtime 上可用，子会话确实被启动、与主会话分开计量；但**本次具体拆法不优于现有单会话**，在时间、token 和事实准确性上均没有净收益。尤其不能以“旧完整基线的 2.6 倍错误被修正”来宣称 DSH 子任务有效，因为同证据单会话也修正了它。当前应保留生产路径，不启用通用 `finance_skill_task`。

若继续试，应先解决三个具体主线问题：一是从同一结果存储按权限向子任务投影少量原始证据，主会话只看证据索引和简短判断，避免双方反复读全量方法与材料；二是给子任务的工具范围和任务目标设边界，使“现金流质量”局部判断不重新做整题公开搜索；三是对会改变结论的比例、量价拆分和自由现金流定义使用现有确定性计算/原始字段口径，而不是让主会话或子任务在文字里即兴推算。下一次仍用本题做完整 Chat API A/B，固定同一来源快照，同时记录父子所有模型用量、工具调用、最终事实核对和读者可用性；在这些前提落地前，不应扩大到其他 Skill。
