# AutoML 复核：股票日事件样本与高精确率选择

日期：2026-10-03（Asia/Shanghai）。基线：`788a42b`。

本记录是实际数据覆盖核查、现有代码审查和修订后的业务设计，**不是新版引擎已实现或新模型有效的声明**。本次没有重新训练、调节历史测试集阈值、写入数据库或部署。查询仅返回聚合与元数据；不保存行情明细或凭据到本目录。

## 目标重新对齐

用户需要从大量股票日机会中选出少量更可信的上涨事件，允许漏掉上涨、允许整天甚至某些时期不出手，尤其重视减少把下跌选为上涨。局部行业、市场情景乃至单只股票的有效模型也有价值，其适用范围应如实限定。

主指标应是选中样本的 precision（精确率），而非全体样本 accuracy（准确率），也不以召回率最大化为目标：

`precision = 选中且达到上涨目标的样本数 / 全部选中样本数`

必须同时报告：实际下跌比例、平均亏损和尾部亏损、目标命中相对同池同日基率的提升、信号数、出手日期数、覆盖率与净收益。高 precision 不自动等于正期望收益；少数大亏可能抵消许多小幅上涨。零信号时 precision 无定义，不能写成 100%。

## 实际样本规模

对两个已配置连接可读的 `kingdomai.kcrp_stock_price` 分别做只读聚合，得到相同的 2024—2025 年统计。这里的两年统计相同不证明其他字段或全表逐行一致。

| 范围 | 原始日K记录 | 证券代码 | 交易日期 | volume>0 且复权开/收盘价为正的记录 |
|---|---:|---:|---:|---:|
| 2024 | 1,297,019 | 5,435 | 242 | 1,293,651 |
| 2025 | 1,317,314 | 5,499 | 243 | 1,313,872 |
| 两年合计 | 2,614,333 | 5,551（去重） | 485 | 2,607,523 |

实际日期 2024-01-02 至 2025-12-31；这些记录的代码均匹配现有沪深北 A 股代码规则。全日K表日期端点为 2018-01-02 至 2026-09-30，不据此假定期间完整。

以上是数据池计数，尚未扣除特征历史不足、下一交易日标签缺失、上市/退市状态、停牌及其他质量限制，不能直接宣称为可训练样本数。

旧前端试跑主动限制到 16 家、485 个交易日，面板只有 7,760 行。再留出 3 家公司、最后一段时间及校准块，最终主模型拟合剩 3,536 行。这个小规模来自试跑配置，不来自数据库规模。

分钟数据：日线试跑连接看不到分钟快照表；另一个已配置连接可读取分钟表。`aiia_stock_realtime_minute_snapshot` 的日期端点为 2026-09-23 至 2026-09-30，`aiia_stock_realtime_minute_snapshot_full` 为 2026-08-24 至 2026-09-30。端点不代表所有证券每日窗口均完整，两个表也不能直接相加当作独立样本。

精确抽查 snapshot 在 2026-09-30 的 `14:30 <= bar_end_time <= 14:55`，有 132,548 条已完成 1m 记录、5,098 个证券、26 个 bar 时间。这最多对应 5,098 个股票日机会，而日K截至 09-30，尚无这些事件的下一交易日开盘标签。查询含两端，不能称为完整 25 分钟窗口；若时间戳表示 bar 结束，应在确认供应商语义后采用 `14:30 < bar_end_time <= 14:55`。

`_full` 最早日期 08-24 同窗口的已完成 1m 记录为 0。两次全期分钟按日聚合均触发 30 秒数据库查询超时，已停止。因此没有得出全期有效尾盘股票日数量，表级日期端点也不能当作连续 1m 覆盖。

因此现有分钟表不能直接提供 2024—2025 年的尾盘特征。较多证券的一月分钟数据仍只有一月市场环境；分钟记录数不是独立隔夜样本数。后续还需按证券、交易日、分钟类型、完成状态、窗口完整度和下个开盘可用性构造有效样本。

## 样本、特征和正负标签

一个样本是 `(证券, 决策日期, 决策时刻)` 对应的一次隔夜机会。默认先构造研究期间符合条件的广泛事件池，不先随机选十几家公司。股票代码用于身份、对齐及分组；没有必要直接当作通用模型输入。

历史上市范围按每个样本日期判断，纳入研究期间新上市且已有足够历史的证券，保留后来退市证券当时有效的历史。不能只取研究起点已上市的公司后宣称覆盖全市场。

输入可以包含截至决策时刻的全天已发生行情、尾盘窗口、过去多日走势、行业/市场相对表现、当时可得的市值和基本面。若决策时刻是 14:55，当天 14:55 之后的价格、全天最终成交量、收盘价及晚间新闻不能作为输入。过去完整交易日的全天数据可以使用。若决策是在收盘后，则可以使用完整当日日K，但不能再声称能按已经发生的收盘价买入。

保留两个不同业务问题，不能混用结果：

1. **次日高开预测**：`g = next_open / current_close - 1`，分类 `y = 1[g > target_return]`，回归目标为 g。当前收盘价可事后参与标签，14:55 决策时不能作为已知特征。价格需保持一致的除权口径，避免将除权跳空当作经济损益。
2. **尾盘进入至次日开盘的可交易收益**：标签使用决策之后可执行的入场价和退出价及成本，需要分钟级成交假设和可成交性。它与“是否高开”不是同一个事件。

正样本由真实事后结果达到目标定义；其他样本属于目标未命中。若目标为上涨超过 0.5%，上涨 0.2% 是目标未命中，但不应被报告为“实际下跌”。另外单列 `return < 0` 的被选中数量与亏损幅度。

初版优先保留全部有效正负事件及自然比例，尤其保留形态很像上涨机会但后来下跌的困难负样本。不能只保留大涨和大跌、扔掉平盘/小涨/小跌后把评估结果外推到全市场。算力不足时，在训练部分按日期和可得场景进行可复现的事件抽样；校准、验证和测试保持目标分布。若训练对标签分层抽样或改变权重，记录抽样概率/权重，并在自然分布校准数据上核查概率，不把平衡训练集中的分数直接解释为真实胜率。

## 按 precision 选择模型与出手条件

现有固定 60% 门槛不能取代研究。对开发期按时间产生的样本外预测，比较候选模型、适用范围和有限的阈值候选，形成 precision—覆盖率关系。通过支持样本数、出手日期数和下跌损失约束后，优先选 precision 的保守估计更好、在有信号的多个时段表现更稳定的方案。用户未指定精确率底线时，展示可实现的权衡，不擅自承诺 80% 或 90%。

Brier、AUC、RMSE、召回率继续作为诊断，而非要求每个高 precision 局部模型必须在全部样本上占优。阈值更高不保证样本外 precision 一定更高，需要实际验证。可以尝试更高的负样本权重、困难负样本训练、受支持的树叶规则或简单模型组合，但这些都是开发期的候选，不是保证改善的方法。大规模数据的第一轮优先适用线性模型、树和梯度提升；核 SVM 的预算单独控制。

Top K 是数量上限，不是每天必须买满 K 个。必须先达到冻结的入选条件，再在合格者中排序；无人合格就不出手。某折零信号不等于该折产生亏损，也不能产生胜率证据。全开发期信号太少、只集中在一天或一个行情片段，仍应报告支持不足。

股票日事件存在同日市场相关性与跨日相关性，不能把百万行当作百万次独立试验。用于高精确率证据的区间应按日期区块评估，并报告出手日期和分期结果。原有逐行 Wilson 区间只能作为描述，不足以充当概率保证。

## 训练、选择和测试

采用日期顺序的滚动训练和验证，同一交易日的证券一起落入同一个时间块；清除结果窗口跨过下一阶段边界的训练样本。特征处理仅在相应训练块拟合。

开发期需要区分主模型拟合、概率校准和样本外策略选择。校准或阈值学习不能复用其要宣称为独立效果的样本。候选和阈值可以用滚动验证结果选择，但该表现明确属于“选择证据”，最终未来测试才评估整个选择过程。将模型、特征、标签、局部范围及阈值一起冻结后再打开测试。

最终重训若改变模型和校准器，也必须保留其后独立的政策选择窗口或使用事先验证的完整滚动训练流程；不能假设换一个模型后旧分数阈值仍等价。所有决定不得读取最终测试标签。

泛化分开回答：

- 通用模型：未来日期是核心测试；额外保留部分公司，检查跨公司迁移能力。
- 行业／场景模型：范围由开发期决定，在该范围后续时期测试，并说明范围外没有证据。
- 单股模型：允许同一股票早期训练、后期测试，不强制留出陌生公司；只能主张这只股票对应场景的时间泛化。

不能在最终测试里扫描所有股票，挑出最漂亮的一只再称其有效。扫描范围、模型、阈值和场景都计入研究预算；新的发现要在新的未参与选择时段确认。已经多次使用的 2024—2025 历史窗口不能重新称作全新盲测。

## 现有实现差距与落点

本轮属于 AutoML 业务执行和 SOFT 研究策略的复核，不需要重造外层用户任务生命周期。

| 现状 | 修订落点 |
|---|---|
| `data.select_symbols` 先随机公司抽样 | 广泛历史有效股票日池；预算作用于训练事件；分批读取/聚合，不能仅放大 fetchall 上限 |
| `config` 500家公司、10万拟合行上限 | 分开表达数据覆盖与算法训练预算，报告各阶段准确计数；小样本试跑显式说明 |
| 固定未来开盘到开盘标签 | 增加实际消费的目标/决策与结果时点口径；报告、回测、推理共同消费，不能仅改自然语言说明 |
| 分钟适配只读单一连接、全天聚合 | 核对配置中数据源和字段映射，按真实覆盖构造窗口，不能以日线降级冒充尾盘训练 |
| `runner.assess_candidate` 按全体损失提升排名 | 使用开发期样本外 precision、误报损失、支持数和日期稳定性选择 |
| `constraint_checks` 每折强制信号及全体损失占优 | 允许阶段不出手；零信号不能成为高 precision 证据 |
| `prediction_metrics` 仅有扣成本信号胜率 | 分开目标 precision、实际下跌、净收益、覆盖率和出手日期 |
| 固定阈值分别从 spec 读取 | 在既有 selection 资产保存冻结选择；评估、回测、报告和推理重用同一政策 |
| 至少5家公司且强制公司留出 | 允许单股/局部时间研究，公司泛化作为相应范围的独立证据 |

只将程序需要稳定执行的目标、时间、预算和冻结政策纳入 HARD；研究假设、解释和场景表达留在 AutoML 规划/评审。无需新增任务状态，也不让外层任务系统理解金融公式。

验收至少包括：低召回高 precision 候选可被选中；零信号无虚构胜率；空折不机械否决；目标未命中与实际下跌分离；低支持样本不冒充高置信；未来特征不进入输入；修改测试标签不改变模型/范围/阈值；预测与回测使用同一冻结政策；单股时间验证可运行；全市场训练预算抽样不改变验证测试基率；数据缺失不能静默替换明确的分钟要求。
