## 1. 窗口约束放在哪里

采用现有 SOFT → HARD → SOFT，不再增加一套窗口状态机，也不让代码用关键词重新判断用户意图。

| 层次 | 责任 |
| --- | --- |
| 唯一目录的操作级说明（SOFT） | 模型区分“市场交易日”“每证券有效记录”“明确起止日期”，选择已有 API 和参数。已补充 stock.quote / stock.quote.kd 对应规则，没有另建提示词真源。 |
| 既有调用参数、交易日历与 SQL（HARD） | k 日统计用日历日期集合；count 按每证券记录取数；明确日期仍保留在 WHERE。不能因为停牌或结果不足跨出明确范围。 |
| 结果表达（SOFT） | 解释实际数据范围、记录数和缺失，不把缺数据说成模型查到了完整交易日。 |

提示词负责选对合同，代码负责执行合同。SQL 层不会凭用户原话“纠正”已经传入的 count / k。

边界：现有 k 日统计已在工具内使用日历；原始明细 API 尚没有统一的“交易日窗口”参数或独立日历工具。因此不能把本次目录说明当作所有 API 都已具备自动、硬性转换自然语言交易日窗口的证明。日历目前仅覆盖2026年，跨年长窗口仍需补齐可信历史日历。本轮没有扩充日历或新增公共 API 参数。

## 2. 静态 SQL 和三个月预查不是同一件事

静态 SQL 优化指修改 provider 的确定性 SQL 模板/访问方式，例如按代码索引倒序有界读取、先选键后取宽字段；不是再调用一次 LLM 改 SQL。

三个月预查是其中一种可选的物理读取策略：

1. 请求必须属于按时间最新取 N 条（或明确证券集合逐证券取 N 条），且没有明确日期范围/全量请求。
2. 在原过滤条件上额外限制最近三个**日历月**，不改原过滤、Top-N 与最终排序的先后顺序。
3. 全局最新 N 条必须取得 N 条；逐证券 N 条必须每个请求证券分别取得 N 条，总数够不算够。
4. 不够时丢弃预查结果，最多一次执行原范围完整查询。不逐月扩大，不合并两次结果，不让 LLM 重试。
5. SQL 出错/超时直接返回原有错误，不能当成“记录不足”或“历史耗尽”。

同一连接/游标完成两次读取；最终返回一次完整查询的结果，避免部分预查结果与补查拼接。原始数据不进入额外模型轮次。trace 使用已有 sql_shape 通道的 recent_scan（recent_months、sql_reads），正式字段列表不增加内部检查列。

明确日期、聚合/全历史统计、非时间优先排序不自动加三个月。逐证券查询若全局 limit 不足以容纳“证券数 × N”、证券集合无法确定或包含 OR，也不走逐证券预查。全市场逐证券查询不能因为总行数够就忽略长期停牌证券，因此仍用原有精确路径。

## 3. 实测后决定默认范围

| 现有执行形态 | 默认策略 | 原因 |
| --- | --- | --- |
| 指数/基金/债券/板块日 K 的逐证券历史窗口排序 | 满足上述条件时启用 | 仍走 ROW_NUMBER 历史排序；指数、基金实测显著减少耗时。债券/板块本轮只有模板级测试，没有真实数据性能结论。 |
| 企业多源视图的时间优先 Top-N | 满足条件时启用 | UNION 多源历史查询可缩小日期扫描，业务分部实测显著提升。其他企业视图未逐个做真实数据性能验收。 |
| 已有界索引读取的股票日 K、分钟 K | 默认不启用；保留安全 A/B 接入 | 实测没有明显收益，部分查询略慢。 |
| 研报明细/预测指标的时间优先 Top-N | 默认不启用；保留安全 A/B 接入 | 密集数据收益不明显；稀疏/空结果因补查明显变慢。 |
| 财务三表、两融、资金流、估值普通查询 | 未增加预查 | 默认本来就是最新报告期/最新日期截面，不是无界历史最新 N 条。 |
| 所有聚合、k 日统计、明确日期/全量查询 | 保留原逻辑 | 不能根据“近期凑够 N 条”证明完整统计结果。 |

FIN_AGENT_RECENT_SCAN_ENABLED 不设置时使用上述默认；0 全关；1 在安全条件满足时对保留接入的路径也强制启用，供诊断 A/B 使用，不建议生产一刀切设1。三个日历月是内部常量，不暴露给模型，也不要求模型选择扫描模式。

## 5. 业务分部不一致的根因及修复

原 SQL 只按报告期和公告日期排序，同一报告期有多个分部/来源，LIMIT 截断时没有确定的并列顺序。日期条件改变访问计划后，选出的前5条/顺序随之变化；不是模型入口变化。

修复在企业多源 SQL 模板：保留全部业务排序优先级，最后按请求返回的各列做二进制比较的确定性并列排序。只影响原来没有定义先后的并列行，不按公司名、问题词或字段业务含义写特例，不改变公共输出 schema。完全相同的投影行可互换。

这保证同一个请求、同一组输出列的结果稳定；不承诺不同投影字段下选中的底层物理行恒等。若后续要求跨投影稳定身份/分页，应单独利用源表唯一键解决，不在本次扩张协议。
