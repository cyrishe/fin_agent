用户指定阿里云盘 `全部文件/策略训练/收盘开盘_20261014`，作为收盘—开盘模型有价值训练的长期副本。本机镜像为 `outputs/stock_automl/aliyun_drive_local/策略训练/收盘开盘_20261014`，下有与云端相同的 `01_时间稳定性_七因子基线`、`02_联合目标与尾部风险`、`03_因子筛选_7至14`、`04_次日目标价_收盘均价次高最高`、`05_六切面序列_卷积网络` 五类目录。Git 保存代码、报告和适合版本管理的证据；本机镜像与云盘保存完整训练包。`/Volumes/阿里云盘` 是只读安装镜像，不能作为归档目标。本机镜像当前尚未与阿里云盘建立同步映射。

## 何时归档

在实验登记时判断本次训练是否形成可复现的基准、影响策略选择的对照证据，或准备供后续运行。符合其一就归档；单纯临时排错、没有独立结论的试跑无需复制一份。旧包不覆盖，新运行新建实验名或修订目录。

## 每个实验目录

目录名采用 `YYYYMMDD_实验代号_任务或因子_关键版本或数据口径`，例如 `20261013_X6_七因子_sklearn1.7.1_分钟补全后1440模拟`。实验 ID 在数据库中保持稳定，目录名和标题要让人直接看出训练方案与关键差别。至少包含：

- `README.md`：目标、数据区间、候选与标签口径、七因子或新因子的精确定义、训练窗口、模型与超参、依赖版本、代码 commit、数据来源、已知限制，以及是否复现 B1。
- `training.csv.gz`：实际用于拟合的**逐行训练样本**，含信号日、股票代码、因子、标签；若有权重或过滤规则，同时保存对应列或选择清单。文件哈希必须与运行清单相同。
- `model.joblib` 与 `model_manifest.json`：保存模型、因子顺序、训练日期、样本数、参数和内容哈希；不能用同名模型替换旧文件。
- `predictions.csv.gz` 和 `decision.json`：全候选概率、Top1／Top2 与轮空结果；没有次晨数据时，收益字段保持空白。
- `metrics/`：完成标签后按统一口径保存 Top1 达标／可接受／错误率，以及规则通过交易的逐日、逐月、总体 09:40 每笔收益率；同时列出是否应用轮空。
- `SHA256SUMS`：包内每个文件的 SHA-256，便于下载后核对；数据来源不能随包保存时，在 README 中记原表、日期范围与源快照哈希。

先在本地形成完整包并核对，再放入本机镜像、登记 `kingdomai.automl_training_archive`，最后通过阿里云盘同步并**从云端独立回读**文件数与哈希。该表记录实验 ID、日期、标题、分类、本机与云端相对路径、代码 commit、清单哈希、文件数及本机核验时间；`cloud_verified_at` 只有云端回读成功后才填写，空值表示待同步或待核验。上传未完成或回读失败时，不能写“已归档”。训练包是研究与复现资产，不因存入云盘而成为已验证的 B1 或生产模型。

## 每日开工与归档

1. 先读 [当前入口](ACTIVE.md)、最新 `HANDOFF_YYYYMMDD.md` 和[实验登记](EXPERIMENT_REGISTER.md)；运行 `.venv-automl/bin/python -m scripts.archive_automl_training audit --check-db`。核对本地文件、数据库哈希和云端待核验项；遇到缺失或不一致先追溯，不覆盖旧包。
2. 对有独立价值的新实验，先在[实验登记](EXPERIMENT_REGISTER.md)登记实验名、数据区间、训练口径、核心结果与证据。用 `scripts.archive_automl_training stage` 将含 `SHA256SUMS` 的完整包放入对应分类，并以 `--write-db` 写入数据库。相同实验 ID 不得改写成另一份包。
3. 阿里云盘同步映射建立后，将本机镜像对应到云端 `策略训练/收盘开盘_20261014`。每次同步后独立回读云端文件并核对哈希，再填写 `cloud_verified_at`；次日开工优先补齐待同步项。
