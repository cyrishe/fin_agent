# 涨停冷静：模型与策略版本的系统管理

## 身份和继承

| 对象 | 稳定身份／现有入口 | V1 与 V2 的关系 |
| --- | --- | --- |
| 策略家族 | 涨停冷静 | 面向人的总名称，不拿它代替版本 ID |
| 冻结策略定义 | `automl_strategy_definition (user_id, strategy_id)` | V1=`B2`，定义 SHA `157b9d77…`；V2=`B2_V2`，定义 SHA `54ebe015…`。公式或停摆规则变更应新建 ID，不能覆盖旧定义 |
| 可读展示身份 | `strategy_daily_run`／`strategy_execution` 的 `strategy_name, model_version, version_desc` | V1=`涨停冷静 / v1.0 / 四K形态后延后一根K模拟买入`；V2=`涨停冷静 / v2.0 / 月度停摆`。V2 完整名称为「涨停冷静 V2 - 月度停摆」 |
| D0 月模型与四 K 规则 | `months/YYYY-MM/manifest.json` 中 `model.joblib`、`rule.json` 的哈希 | V2 沿用同一 D0 月基础模型与规则，不复制或重新命名为“V2 模型”。月度重训只产生新月份资产，不自动升策略版本 |
| 训练包 | `automl_training_archive.experiment_id`、包内清单与源哈希 | 表示训练／实验资产；不代替策略定义、逐日执行或账户净值。现有 V1 包已登记，V2 对照使用其冻结资产及 R60 扩展资产 |
| 逐日决策与交易 | `strategy_daily_run`、`strategy_execution` | V1 原样记录影子候选和模拟交易；V2 以独立 `v2.0` 行记录当月放行或停摆，不覆盖 V1 行。逐日 `environment_json` 应写入策略 ID、定义哈希、D0 模型月、模型／规则哈希及月初门槛证据 |
| 账户回测 | R63 固定回执、逐日账本与输入 SHA | 历史研究结果；数据库目前没有账户级汇总表，不把账户收益塞进逐股交易列 |

现有可读表的 `model_version` 实际承载**策略逻辑版本**（`v1.0`／`v2.0`），不是按月拟合的模型文件版本。月模型靠模型月与资产 SHA 定位；实验序号 R57／R63 也不是产品版本。代码身份映射在 `scripts/readable_strategy_execution.py::IDENTITIES`，V2 定义在 `scripts/automl_b2_v2.py::definition()`，只读登记预览在 [R63 目录](20261020_b2_pause_best_r63/v2_registry_preview.json)。

## V2 每日可追溯记录

V2 每个月只作一次门槛计算：从**始终运行的 V1 影子账户**取上月最后 5／10 个交易日收盘净值、上月完整 D0 最终候选数，用 `scripts/automl_b2_v2.py::month_decision()` 得到整月决定。这里的“最终候选”对应 V1 `strategy_execution.actionable=1` 的 D0 归属笔数，**不是**每日 Top3 的 `selection_count` 或原始全市场 `candidate_count`。每个 D0 日执行时引用该决定和输入证据；暂停日仍写一条 V2 的零入选运行记录，V1 则照常保留候选、买卖和影子估值。跨月 D1／D2 沿 D0 所属版本继续完成，不能在新月重新判定旧信号。

所需门槛回执只包含已有主线事实：`prior_month`、完整 `prior_D0_candidates`、两个末窗收益、暂停决定、影子净值来源哈希、V1／V2 定义哈希、当月模型和四 K 规则哈希。放在 V2 的 `strategy_daily_run.environment_json` 中即可与 D0 运行同址回读；无需为展示建立额外状态机。`strategy_execution.details_json` 保存 D0 月和冻结规则身份，逐股模拟买卖继续使用现有表。

无需把整条**逐日净值序列持久化**为新表。可从可复放的交易／资金／头寸流水及三个窗口边界日收盘价，计算边界净值；也可逐日计算**影子账户收益率**，在窗口第一天前一交易日以 1 起算，乘足末 5／10 个交易日的 `1 + 日收益率`。[R65 逐月核对](20261021_b2_daily_compound_r65/README.md)与冻结净值算法 53／53 决定一致，数值差小于 `1e-15`。运行时只需可恢复的账户状态、最近 10 个日收益及月初门槛来源回执，不要求保存完整逐日净值。只把窗口内已卖交易的百分比收益相加则是不同的数学规则；[R64 对照](20261021_b2_trade_sum_gate_r64/README.md)显示 52 次历史月初决定有 7 次改变。既有 `B2_V2` 定义不变。

**当前缺口**：KingdomAI 只有逐股模拟记录，没有可直接回读的完整 V1 账户状态或逐日账户收益权威输入。R60 历史影子账可复算至 2026-09-30，生产可读库又缺 2025-05—10 的 110 个历史 D0 日；仅靠现有生产表无法从头重建所需日收益。因此 V2 运行前，必须把选定的历史影子账起点、现金／未平仓头寸与源哈希接到后续 V1 逐日交易及收盘估值，或按既有 B2 回填协议补齐完整历史再重放。账户状态、最近 10 个日收益和门槛来源可恢复后，再让 V2 写入运行表。这个缺口属于 V2 的真实主线输入，不以新增展示字段或想象中的通用模型注册框架解决。

- 已固定 `B2_V2` 的代码定义、基础 V1 哈希引用、`涨停冷静 / v2.0 / 月度停摆` 身份和月初决策函数；R63 已以同一函数复核 R60 已登记的 52 个完整前月门槛、强势段 18 个目标月的决定及账户回执。
- 已保存只读[数据库登记预览](20261020_b2_pause_best_r63/v2_registry_preview.json)和幂等登记命令 `python -m scripts.register_automl_b2_v2`。同一 ID 如遇不同定义哈希会拒绝覆盖。经用户按 `AGENTS.md` 人工 Gate 明确批准后，已执行 `--write-db`，只插入 `imac / B2_V2` 的不可变策略定义。
- 2026-10-20 独立[数据库回读](20261020_b2_pause_best_r63/v2_db_readback.json)确认 V1、V2 **定义字段内容重新哈希**分别与冻结值一致；生产逐日表仍仅有 `v1.0` 的 245 个运行日，无 `v2.0` 运行。2026-09 的 V1 最终候选恰为 16。回读命令：`.venv-automl/bin/python -m scripts.audit_b2_v2_registry`。
- 历史逐日回填、V1 影子净值连续衔接和 V2 实时运行接入尚未执行。定义登记不等于运行上线；这些后续生产写入仍按仓库人工 Gate 处理。本轮代码和文档尚未提交／推送，云端训练资产也未独立回读。
- 版本规则：月模型文件变化且训练／选规流程未变，更新该月资产清单；5／10 窗口、零候选、D0 归属、基础买卖或费用公式变化，使用新的策略 ID 与展示版本；仅重放已知历史或更换报告区间，使用新的实验回执，不冒充新策略版本。
