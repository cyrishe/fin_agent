# 连续选股列表与批量历史行情（2026-10-16）

按用户要求取消日期折叠，每条记录显著显示选股日期，相邻日期交替底色。初次20交易日，向下滚动或点击继续追加前20交易日；用最早交易日作排他游标，模型筛选保留。历史买卖事实与图表一次加载保留，当天记录、行情和分钟K每10秒更新，更新时只替换当天相关行。

`/api/strategies/page`在账户授权范围内读取一页执行记录，整批读取日线、分钟数据。历史分钟查询按主键顺序构造精确日期/结束时间/股票键，通过MySQL JSON_TABLE与PRIMARY连接，一次请求取整页。证券代码列使用原表utf8mb4_general_ci，避免临时表字符集冲突。保持既有fallback/finalized过滤，无索引/表结构变更。日线一批读取后按选股日期截取，历史分钟仅该日期；当天一分钟继续使用API。旧记录的前后两交易日翻阅仍按账户选股日期校验，不受首页20日限制。

初次批次实测98条选股、96个去重日/股票组合、23,040根分钟K，日K查询一次、分钟查询一次。服务器最终实测分钟查询2.337秒，全批4.268秒（本次日线1.610秒）；不同缓存和网络下耗时会变动，不宣称固定延迟。HTTP JSON约3.82MB，gzip约552KB。大OR方案放弃，改为按主键顺序点取；无每股票/每天HTTP请求扇出。

图表改Canvas，靠近视口才绘制，避免数万SVG节点；已有历史行DOM保持，实时轮询不重新查询或重绘历史图表。手动“立即刷新”才重新读取首页历史批次。原历史缓存按新增记录失效的逻辑由整页记录与行情同时加载替代。

验证：21项服务/路由测试、2项JS行为回归；包括账户隔离、无效/未来游标、整批数据按日隔离、今日分钟不查历史库、翻日边界、历史节点在实时轮询中不被替换。真实数据库相邻20日页分别10/16—9/11、9/10—8/14，无日期重叠；上线后验证滚动追加与分钟翻阅。

追加实测：8/14—9/10这批历史分钟首次读库29.744秒、整批32.045秒，说明冷月份的索引随机读取仍有明显成本，不能把首批4.268秒外推到所有月份。页面在接近末尾前约4,800px开始后台预取下一批；已经加载的列表保持可交互。服务进程按完整股票/日期集合缓存最多16份gzip压缩历史批次，新选股集合自动使用新键，手动“立即刷新”可清除缓存重新读库；10秒轮询不清缓存。缓存只保存数据库派生行情，不包含用户执行明细。完整测试更新为22项Python、2项JS。
