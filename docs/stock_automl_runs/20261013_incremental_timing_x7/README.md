# X7：七因子实时训练的单日增量耗时核查

2026-10-13，scikit-learn `1.7.1`。针对“每日是否必须重建 20 天、几个月回测为何更快”进行只读计时。先前多月回测读取已生成的本地候选母表，在内存中逐日独立拟合；当前实时 `prepare` 则从远程库逐日重建前 20 天的候选、因子与次晨标签，并在独立空缓存里对 20 天逐日生成全市场成交额，二者耗时不能直接类比。X6 的首个全量成交额缓存文件于 19:22:04 写出，最后一个于 19:25:16 写出，仅该阶段历时 3 分 12 秒。

## 实际增量计时

以 10/13 准备模型、10/12 为新增信号日，在同一环境重复 3 次。每次只从数据库构建 10/12 的七因子候选与 10/13 早盘标签、生成 10/12 一日成交额缓存，再读取已保存的 6,576 行训练文件并拟合模型，评分保存的 327 个 14:40 候选。该过程未修改数据库；计时含远程数据库读取，未包含昨日全市场分钟 K 缺口回填，也未包含 14:40 全市场行情接口采集。

| 步骤 | 三次耗时（秒） | 中位数（秒） |
|---|---|---:|
| 交易日历、日行情、流通市值及 ST 状态 | 12.29 / 13.48 / 11.30 | 12.29 |
| 昨日 14:40 分钟信号 | 4.28 / 6.47 / 4.58 | 4.58 |
| 昨日七因子及 ST 筛选 | 0.47 / 0.44 / 0.51 | 0.47 |
| 今日 09:31–09:40 成熟标签 | 0.77 / 0.77 / 0.76 | 0.77 |
| 昨日全市场成交额缓存 | 6.40 / 6.53 / 6.36 | 6.40 |
| 读缓存、核对、拟合 6,576 行及评分 327 只 | 0.47 / 0.43 / 0.39 | 约 0.43 |
| **合计** | **24.68 / 28.12 / 23.91** | **24.68** |

10/12 新增日的 **110** 条有标签候选，从数据库重新构建后与 X6 全量准备文件的股票键、买入价、七因子和次晨第二高价**逐项完全一致**；用 6,576 行拟合的模型对 327 个候选的全部四类概率与 X6 全量准备模型在 `1e−12` 内一致，Top1 同为 `603083`。逐次计时与数值核对见 [run1](evidence/incremental_benchmark_run1.json)、[run2](evidence/incremental_benchmark_run2.json)、[run3](evidence/incremental_benchmark_run3.json) 和 [计时脚本](../../../scripts/benchmark_automl_1440_incremental.py)。

整理进版本库后又用已归档训练行、模型和快照重跑一次，耗时 27.54 秒，数据与全量模型继续一致；见[归档后核对](evidence/post_archive_check.json)。

## 稳定性的前提

预测日 `T` 使用 `T−20…T−1` 训练，较前一个预测日复用的是 **19 天 `T−20…T−2`**；`T−1` 的完整标签还要等 `T` 日 09:40 后才能生成。历史日并非天然不变：X6 的 13:56 旧训练集比补数后少 **224 行**，其中 10/12 少 **38 行**，其他 19 日合计少 **186 行**。仅检查昨天不足以保证复用缓存正确。正常增量必须先有全窗口的已核验快照，并记录每个交易日的覆盖、数据源版本或内容哈希；任一旧日被补数或修订时，重新生成受影响的缓存与模型。

这三次证明**在当前数据已齐、数据库响应正常的条件下**，单日增量的实测量级是约 24–28 秒，模型拟合本身约 0.32–0.38 秒；还没有验证分钟接口故障、数据库高延迟、实际 09:41 标签到齐情况，亦没有把增量流程接入定时生产链。因此不能把 25 秒当作保证的最坏耗时。可安排 `T−1` 收盘后检查与补缺，`T` 日 09:40 后核对标签并准备模型；若输入未核验完成，14:40 不发布基准信号。
