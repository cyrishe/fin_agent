## 2. 已完成工作

### 2.1 Agent Surface Protocol v1

定义了七类稳定语义块：

- `narrative`
- `data`
- `workflow`
- `artifact`
- `assessment`
- `resource`
- `interaction`

协议明确区分 Provider/Harness 原始事件、业务语义协议和可信前端渲染器。模型不生成 HTML、组件树、可执行命令、稳定 ID 或审批凭据。

首期 Conversation Core Profile 收敛为五类主要展示块：Narrative、Artifact、Workflow、Assessment 和 Interaction。Data 与 Resource 继续保留，但不要求首期完成全部专用图表。

### 2.2 金融工具设计三层合同

确定三个不可混用的合同层：

1. Design Skill：输出需求理解、问题、完整设计快照和已有实现分析；
2. 业务工作流：维护需求收集、等待确认、实现、验证、提交等状态；
3. Agent Surface：将领域结果编译为可流式展示和交互的语义块。

固定状态映射：

| Design 结果 | Artifact | Interaction | 后台状态 |
|---|---|---|---|
| `clarification` | `draft` | `submission_mode=conversation` | `collect_requirement` |
| `review` | `reviewable` | `submission_mode=action` | `awaiting_design_confirmation` |
| 用户修改 | 新 revision | 旧确认失效 | 重新进入 Design |
| 用户确认 | `approved` | 后台受信 action | 进入 Coding |

### 2.3 Design Skill v3.1

新增的金融工具 Design 能力现已统一到 `src/skills/financial-tool-development/`：

- `SKILL.md` 负责业务含义、选择规则、金融口径和设计方法；
- `schema.json` 负责字段、类型、必填项和枚举；
- 只使用 `clarification` 和 `review` 两种模型状态；
- 每轮输出完整设计快照，不再自行生成 NDJSON；
- 用户确认由外层状态机处理，不由模型宣称 `confirmed`；
- 增加结构化问题、确定性规则、数据能力映射、异常和可测试验收场景；
- 提供 clarification/review 样例和金融检查参考。

Codex CLI 与 SDK Harness 均支持显式或同目录 `schema.json`，Structured Output 模式下不再向 Prompt 重复 JSON 传输规则。

### 2.4 后台状态机与确认安全

- Design 结果映射为 `collect_requirement` 或 `awaiting_design_confirmation`；
- Artifact 使用稳定 `design_artifact_id`、内容指纹和单调递增 revision；
- 结构化确认必须提交 `expected_revision`；
- 旧 revision 的确认会被拒绝；
- 模型 final 只作为业务结果收集，不能提前生成可执行确认；
- 受信后台负责绑定 `action_id` 并进入 Coding；
- 同一 thread 保存设计上下文和可恢复状态。

### 2.5 对话内增强渲染

在统一 Conversation Workbench 中接入：

- 工具设计 Artifact 摘要和分区详情；
- 输入输出、规则、数据需求和验收信息；
- 结构化澄清问题及可选答案；
- 确认与自然语言修改；
- Coding 产物和验证结果的 Artifact/Assessment 降级展示；
- 历史 Turn 中 Surface Block 的持久化恢复。

前端仍以对话流水为主。增强块渲染失败时，正文和统一输入框仍可使用。
