## 1. 数据库迁移：先停写，不是直接重启

你在服务器执行：

```bash
sudo systemctl stop fin-agent-web.service
sudo systemctl is-active fin-agent-web.service
```

看到 `inactive` 后告知执行迁移的 Codex。它会停止本项目的手工 API、本地 Web/API，以及核对其他写入端；复制源表并逐表校验行数和 SHA256；备份两端 `.env` 并将 `SYSTEM_DB_URL` 改为新库连接。

迁移执行命令（仅供停写确认后使用，不要自行在运行中执行）：

```bash
cd /home/che/cyris/fin_agent
.venv/bin/python scripts/migrate_system_database.py --apply --writers-stopped
```

旧库不删除，stock_agent 中现有 BI、热点和其他业务表不覆盖。失败时保留现场，禁止删除整个库重试。

## 2. 校验完成后再启动 Web

仅在收到迁移和环境切换完成的确认后执行：

```bash
sudo systemctl start fin-agent-web.service
sudo systemctl status fin-agent-web.service --no-pager
```

这次完整启动也会加载 `.env` 中的 Astra low。原 Gunicorn 主进程仍持有旧模型变量，HUP 不足以更新 EnvironmentFile。
金融 API 由迁移执行方按原手工方式恢复；不要再额外启动一个占用 22054 的 systemd API 服务。

候选配置与原配置备份位于 `/home/che/cyris/fin_agent_deploy/data-status-d614ee5/`。
已核对其差异只增加两个状态页 location。先确认线上配置未被其他人改动：

```bash
cmp /etc/nginx/conf.d/ngx.conf /home/che/cyris/fin_agent_deploy/data-status-d614ee5/ngx.conf.before
```

**只有 cmp 无输出且退出成功才继续**；有差异则暂停，请 Codex 重新合并，不能覆盖其他项目的新配置。

```bash
sudo nginx -t && sudo systemctl reload nginx
```

若 nginx 检查失败，先恢复备份文件，不要重启 nginx：

```bash

sudo nginx -t
```
