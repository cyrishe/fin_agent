# 个股研究中的专业方法组合

用于一项研究确实需要多个专业方法共同回答时。内部子方法是本 Skill 的参考；下表是当前系统中的独立 Skill 候选，可在研究内容上作为分支，不代表强制依赖或权限。

## 保持同一研究问题与证据集

先说明需要哪个局部判断，复用公司、时点、报告期、用户限制、已取得证据及缺口。Finance Agent 用 `read_finance_skill` 加载当前授权目录中的方法，再依据其正文读取必要参考。无需模型重述系统保存的身份、hash、revision 或生成交接 JSON。

| 本轮缺口 | 可组合的 Skill | 对个股结论的贡献 |
| --- | --- | --- |
| 机构为何看好、哪里有分歧、预测为何改变 | `equity-report-analysis` | 机构预期、研报专题证据、分歧假设与待核验线索 |
| 财报变化或利润/现金的质量 | `earnings-analysis` / `financial-quality-analysis` | 区分当期事件与跨期质量，解释经营兑现程度 |
| 当前价格或多业务定价的合理性 | `valuation-analysis` | 适合该业务的估值锚、可比假设和情景限制 |
| 相对同行、产业链或跨赛道如何取舍 | `stock-comparison` | 业务可比性、共同口径、优势与代价 |
| 行业景气或事件能否传到公司 | `sector-theme-analysis` | 行业环境与公司暴露，而非主题标签归因 |
| 股价行为对短期问题确实重要 | `technical-structure-analysis` | 价格、量能和趋势条件，不证明公司质量 |
| 长期现金分配或分红可持续性 | `dividend-analysis` | 分配与盈利、现金和资本需求的关系 |

同一材料不重复取数，不按每个 Skill 分别写一份报告。其他方法可能已经满足全部问题，此时本方法直接综合，不重新展开。已加载方法不循环相互推荐。

## 研报 Skill 还是研报数据

- 只需要一个已取得的报告数字或简单事实：沿默认取证方法复用或查询即可，保留机构、发布日期和预测属性；无需为一个字段展开全部研报子方法。
- 需要观点综合、共识/分歧、前后修订、经营专题、原料影响或产业链线索：有匹配且授权的研报 Skill 时优先加载，由其指导如何解读研报数据。
- 没有可用研报 Skill：可用授权报告/预测工具和通用分析补足。没有研报数据：继续公司业务、财务等独立主线，说明机构预期未覆盖，而非终止个股研究。
- 有主方法但细节未覆盖：保留其来源和证据指导，补充授权工具；不是清空已有 Skill 后重新凭常识回答。

研报要先核对研究标的、报告身份与机构/时点。结构化映射与标题/内容明显矛盾时不把该报告归入目标公司证据；记录歧义，不自行改库。摘要、投资要点和抽取指标不能声称等于已读全文。

研报预测不能替代已披露实际值；目标价均值不能替代内在价值；没有足够可比机构样本时不称正式一致预期。相关具体方法由研报 Skill 维护，这里不复制其全部规则。

## 比较不是统一倍数排名

与自身历史比较时核对业务结构、周期与资本结构是否变化；同业比较时先解释收入来源、客户、区域、阶段和规模的可比性。同行选择服务于问题，不能只按行业标签或有利的估值倍数挑选。

跨赛道比较（例如银行与软件）使用共同的决策语言：资本需求、现金可见度、增长兑现、估值假设、主要风险和用户期限。各自使用适配指标，不直接用 PE/PB 或统一加权分确定胜负；保留不能直接比较的部分。用户指定对象不替换，确实不可比时仍可解释取舍。

## 汇总回主命题

把分支贡献还原为：它增加了什么证据，支持或改变了哪个判断，留下什么限制。输出一个统一的个股结论及条件；方法加载、数据调用和引用版本沿用现有 Trace。加载成功只证明方法可读，不等于分析正确或数据齐全。
