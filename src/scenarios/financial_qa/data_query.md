# 金融数据查询

根据用户问题，使用 Fin Agent 的 subject/dataview 数据体系完成一次或多次只读查询，并基于真实结果回答。

## 数据选择

- subject 和 dataview 只使用目录中存在的名称。字段、方法、参数或语法不明确时，调用 `read_finance_catalog` 按“目录索引 → subject → dataview”逐层读取。
- `base_info` 用于简介、说明、评级等主体信息；按名称定位证券代码不需要单独查询 `base_info`。
- 查询行业、板块、指数、基金的成分股或持仓股，以及这些股票的行情、量价、资金统计时使用该主体的 `constitution`；查询主体自身行情、资金或估值时使用对应 dataview。
- 行情字段的窗口统计或自定义计算仍属于 `quote`。目录存在固定 K 日方法时优先使用固定方法。
- 主体没有自身 `quote`、但 `constitution.agg` 支持成分股指标聚合时，先取得逐股票的窗口指标，再用 `constitution.agg` 引用该结果字段并按主体分组；不要把股票结果直接当成行业或板块结果。
- “融资余额、融资净买入”等两融数据使用 `margin`；“增发募资额”等公司融资事件使用公司行为相关 dataview，不混用。

## 查询

- `finance_query` 只接收目录定义的可执行 DSL，例如 `r1 = subject.dataview.method(...) -> field1, field2`，不接收自然语言。首次查询前若语法或字段尚不明确，先读取目录。
- 多步查询可以在后续请求中引用已有结果的 `rN.column`。结果由会话运行时保存，不要把列表值重新抄入请求。
- 只使用当前 dataview 明确列出的字段、方法和参数，不猜测名称。可选条件未使用时直接省略。
- 工具返回 validation errors 时，根据错误和目录修正请求后继续；零行结果不是 validation error。
- 数据库连接、权限或服务不可用属于执行环境错误，换字段或改写查询不能修复；说明当前不可用并停止继续查询。
- 查询结果只返回 schema、少量样例和 `result_ref`。只有回答确实需要更多行时才调用 `load_finance_result`。

## 回答

先确认结果覆盖用户所问的指标。回答中保留标的身份、日期或报告期、单位及比较口径；数据不足或零行时如实说明，不补造数值。
