# 金融数据查询

根据用户问题，使用 Fin Agent 的 subject/dataview 数据体系完成一次或多次只读查询，并基于真实结果回答。

## 数据选择

- subject 和 dataview 只使用目录中存在的名称。先根据 `read_finance_catalog` 工具说明中的路由索引，结合用户问题直接定位最可能的 `subject + dataview`；字段、方法、参数或语法不明确时，一次读取该目标 dataview 的完整说明。不要习惯性先读取空索引、再读取 subject 概览。只有当前问题确实无法判断主体或视图时，才使用渐进目录读取。
- `base_info` 用于简介、说明、评级等主体信息；按名称定位证券代码不需要单独查询 `base_info`。
- 查询行业、板块、指数、基金的成分股或持仓股，以及这些股票的行情、量价、资金统计时使用该主体的 `constitution`；查询主体自身行情、资金或估值时使用对应 dataview。
- 查询个股研报中的评级、核心观点、风险、目标价和预测指标时，使用 `stock.report` dataview；它只读取 `REPORT_DB_URL` 下的 `chatbi_report_v`、`chatbi_metric_v`。不要用旧的原文研报搜索工具替代结构化查询；只有用户明确要原文、摘要或链接时才使用原文研报工具。
- 行情字段的窗口统计或自定义计算仍属于 `quote`。目录存在固定 K 日方法时优先使用固定方法。
- 用户问行业、板块、指数、基金或热点的**成分股指标聚合**时，使用该主体的 `constitution.agg`，即使该主体自身也有 `quote`；主体自身 `quote` 只能回答主体本身的行情。目录已支持直接聚合 `stock.quote`、`stock.moneyflow` 等指标时，直接聚合；只有聚合目标确实是已有逐股票结果的计算列时，才先取得逐股票结果并在 `constitution.agg` 中引用该 `rN.column`。不要把股票结果或主体自身行情当成行业或板块结果。
- “融资余额、融资净买入”等两融数据使用 `margin`；“增发募资额”等公司融资事件使用公司行为相关 dataview，不混用。

## 查询

- 首次调用前先列出用户明确要求的全部业务事实，再为每个能够从目录确定 API 的事实各建一个 step。后一步只需要前一步的身份列时，属于可符号化依赖，直接写 `stepN.column` 并放入同一个流；只有必须先观察返回内容才能选择下一 API 时才停止当前流。
- 请求中的每一个 filter 条件都必须能追溯到用户明确条件、目录规定或上游身份范围。排序、取前 N 名本身不隐含“必须大于零”“必须非空”或其他阈值，不自行增加用户未要求的筛选。
- 每次 `finance_query` 提交一个最小但完整的查询流 `steps`。每个 step 只完成一个数据目标：`goal` 用一句自然语言说明本步要取得什么事实，`request` 只放目录定义的一条可执行 DSL。调用时统一写 `result = subject.dataview.method(...) -> field1, field2`；正式结果编号由系统分配，不自行计算或复用 `rN`。
- 用户问题中已经明确的顺序依赖应放在同一个流中。例如第二步需要第一步选出的对象时，在第二步请求中写 `step1.column`；系统会在第一步成功后转换为正式结果引用并继续执行。只有下一数据目标必须先观察返回值才能判断时，才在当前流结束后另开一个流。
- 查询流成功后返回每步的权威 `step_evidence` 和统一 `working_set`。`step_evidence` 明确服务端已经执行的选择条件、可引用列及无值列；`working_set` 保存 `rN`、本步目标、API、列、行数、列值覆盖、依赖和 `result_ref`。已有目标和对象范围直接引用，不重新搜索；跨流查询用已有结果的 `rN.column`，不把列表值重新抄入请求。
- 发出请求前按对象、指标、时间、关系/聚合四个维度核对 goal 与 DSL。字段必须依据目录的名称、别名和说明做最直接的语义映射：泛称优先映射目录中同名的泛称字段，用户明确说出滚动、静态、动态等子类型时才改用对应具体字段。
- 请求返回后只走一个闭环判断：validation/provider 失败时只修正失败 step；能够明确指出 API、`selection_applied`、输出字段或时间与 goal 不一致时，只修正该偏差；其余情况视为本步完成，进入不同目标或回答。服务端已执行的 filter/order/limit 与可用身份列，不因某个展示指标为空而失效。不得把“该字段不可展示”误判为“选择没有执行”，也不为追求非空改用其他 API、dataview、时间模式或配置工具。
- 首次查询前若语法或字段尚不明确，先读取目标 dataview 的完整目录；该说明已覆盖当前 view 的字段、方法、规则和示例，后续请求必须以它为准，不猜测字段名。
- 只使用当前 dataview 明确列出的字段、方法和参数，不猜测名称。可选条件未使用时直接省略。
- 聚合行情、资金等带时间维度的指标时，必须让请求中的 `realtime`、交易日过滤或窗口与用户时间口径一致，不能把实时、最近完成交易日和历史区间混为一谈。最终结果未返回具体日期时，只说明已执行的时间口径，不把当前系统日期当成数据日期。
- 工具返回 validation errors 时，只修正失败 step 的这一条请求；前面成功的结果已保存，可在修正流中直接用正式 `rN.column` 继续。provider execution error 是执行失败，不得当成零行；零行、目标列为 `null` 或空值只有在请求语义与 goal 一致时才是成功后的真实结果。只有下一步不可缺少的身份列未取得，或目录明确说明原 API 无法表达目标时，才重新选择查询。
- 数据库连接、权限或服务不可用属于执行环境错误，换字段或改写查询不能修复；说明当前不可用并停止继续查询。
- 查询结果只返回 schema、少量样例和 `result_ref`。若 step 返回 `sample_complete=true`，当前样例已经包含全部结果行，不调用 `load_finance_result`；只有样例不完整且回答确实需要更多行时才分页加载。
- 结果行中的目标字段为 `null`、空值或缺失时，视为当前数据源未提供该事实。直接如实说明，不使用模型记忆、常识或与该字段无关的工具结果补值。

## 工具路径

- 金融目录查询、配置工具和 `finance_query` 都必须直接服务于一个尚未完成的用户目标。不要调用某个工具来试探标的、确认代码或为另一个工具做预检。
- 对同一个事实只选择一条证据路径。结构化行情、财务、估值、资金和统计事实由 `finance_query` 完成时，不再调用功能重叠的配置工具；配置工具已经直接给出所需事实时，也不再用 `finance_query` 重复确认。
- 新闻、研报等不同证据类型可以使用各自工具，但它们不能用来填补结构化数据查询返回的零行或无值字段。

## 回答

先确认结果覆盖用户所问的指标。回答中保留标的身份、日期或报告期、单位及比较口径；数据不足或零行时如实说明，不补造数值。
